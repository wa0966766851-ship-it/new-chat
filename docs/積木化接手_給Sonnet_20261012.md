## 2. 你的工作：P4 遷移（逐隻把定義轉成連鎖 Kit）

每批 **1 隻精靈、最多 6～8 份定義**。流程：

1. 從 `docs/audits/block-migration.json`（`npm run audit:block-migration` 產生）取同一隻精靈的條目；看 `unresolved` 的原因。
2. 讀原文 `elf_source_files/elf_files/<ID>_*.txt`（以 TXT 為準）。
3. 每句分類：
   - **A 現有動作／條件可表達**：寫解析規則（`src/blocks/parse.ts`，**錨定整句**，不得吞半句）或在 `distillEffect.ts` 轉換，讓 `distillEffect` 對整份定義回傳 `complete:true`。
   - **B 需要新的通用 op／條件／事件**：本批不做，記到 §4 的缺口表。
   - **C 原文有歧義**：記到待確認。
4. 只有整份定義都能表達，才能切換成 Kit；**不准部分轉換**。切換時在同一個 commit 刪除該定義的 handler 分支，並確認「同一定義只走一條路」。
5. 測試（新增 `tests/migrate_<ID>.semantic.test.ts` 或 integration）：P1 與 P2 各一次；條件成立／不成立；成功／失敗分支；附加效果失效時不執行；回合數到期；下場保留；傷害類型與數值。參考 `tests/effectSequence.integration.test.ts`、`tests/reviewedSequenceKits.integration.test.ts`。
6. 跑 lint、本批測試、`audit:block-migration`；每 5 批跑一次完整測試＋build＋audit:bundle。
7. 本機 `git commit`（訊息含精靈 ID），然後照 §0 寫回電腦。
8. 更新 §4 三張表與 §5 進度。

建議順序：先做 `conversionCandidates` 已為 true 但未驗收的定義（補測試即可驗收），再做未解分支少的精靈：5005 → 5004 → 5003 → 5002 → 5020 → 5030 → 5026 → 300 → …；最後才碰 5034／5035／5029／5033／5019／5023／5032。
