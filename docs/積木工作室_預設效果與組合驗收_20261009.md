# 積木工作室：預設效果、引用與組合驗收

日期：2026-10-09。延續本機工作樹，不重置、覆蓋其他既有修改；本階段未提交、推送、打包EXE或發布網站。

## 已接通的工作流程

一般精靈／自訂精靈 → 選魂印、特質或技能 → 原文與預設積木 → 效果庫引用或節點畫布 → 參數校驗 → 草稿 → 儲存 → 圖紙重載 → 正式戰鬥執行。

- 查看既存效果先使用原Kit；沒有Kit時嚴格煉成預設草稿，不能只因打開就修改卡牌或切換執行來源。
- 完整等價候選才能套用。遇到未解析、成功失敗關聯、特殊公式或未接通原子，保留原句與既有程式，禁止用部分Kit取代整份效果。
- 效果庫按精靈ID／名稱／原句搜尋；僅列同類時點，每頁12張。複製的是獨立Kit與描述，不複製原主能力、PP、身份、存活規則或印記。
- 名稱與PP保持使用者草稿；取消引用不寫入。完整引用後明確使用Kit，不再依同名handler執行另一套效果。
- 畫布修正能力、PP、比例、目標與條件的舊參數投影；只改目標不丟比例，改條件不殘留相反條件，容器子效果真正存回。
- 單一欄位不能代表的多維能力變化以保留機制呈現，完整參數可編輯；不預設成攻擊+1。沒有執行端的選項拒絕套用。
- 條件12.5%不四捨五入成13%；否定條件及超出畫布期限的機制保留原參數，不截成10回合。無視與額外行動的待接通標籤不再寫成轉真傷或連擊。
- 完整參數編輯與畫布同步使用同一Kit；未套用時阻止切換效果對象，提供取消參數與放棄畫布。
- PP補滿按正式技能上限，不用缺失的maxPp；0PP第五技能保持0。

## 前台與效能

效果工作室沿用首頁iOS卡片、分段導覽、圓角輸入、主題按鈕與焦點樣式。分為「原文核對／節點畫布／驗收清單」。預設積木以戰鬥節點、效果身分及完整參數分類呈現。

首頁詳情、唯讀精靈介紹的技能／魂印／特質預設可看積木，描述切換保留。被動機制不誤標成技能附加效果。收合的技能與逐句核對內容不提前執行；唯讀檢視不建立Blockly工作區。

效果庫首次索引按約8ms預算分批讓出主執行緒，分頁不掛載全庫畫布；首次開啟才載入，失敗可在重新開啟時重試。這是避免同步長工作的措施，不代表每個任務絕對小於8ms或低階手機流暢。

本階段採後台React/JSDOM互動測試與正式Vite戰鬥模組，不開前端視窗。這可驗證儲存、按需載入及互動資料流，不能算像素級畫面、手機觸控、真實SVG拖曳或FPS驗收。

### 複合效果的確切數值

測試配置是自訂驗收技能，不宣稱為某隻既存精靈的完整技能。自身低於半血才依序：恢復70、對手防禦-1、中毒3回合、固定傷害70、最大體力10%百分比傷害、真實傷害30、自身2回合非真實減傷50%、所有技能增加7PP。

對手最大體力20000，結算收據必須各有一次固定70、百分比2000、真實30，不允許換類型或重複。

自身起始8000／20000；對手每回合固定1000＋真實100，第二、三回合自身只等待：

| 回合 | 自身體力 | 保護狀態 |
|---|---:|---|
| 1 | 7470 | 恢復70；固定傷害500，真實100 |
| 2 | 6870 | 固定傷害500，真實100；保護到期 |
| 3 | 5770 | 固定傷害1000，真實100 |

條件失敗或附加失效時，整組不執行，不恢復PP、不降防、不附加異常或附加傷害、不建立減傷。P1與P2使用相同驗收數值。
