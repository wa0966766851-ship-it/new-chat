## Blockly 改造與實際大小

僅將官方核心轉成一個 ESM 的第一個實驗仍為772,336 bytes，沒有達標；沒有拿它當完成結果。正式方案由 `tools/buildBlocklyModules.ts` 建立依賴圖，將循環內的模組保持在同一群組，依拓樸順序產生可初始化的小模組，不是任意切壓縮程式碼。生成器另拒絕跨包循環、錯誤版本與髒來源；不使用 property mangling。

來源固定 `RaspberryPiFoundation/blockly` 的 `blockly-v13.2.1`，提交 `168fe103ac42294b845dcd88033e30698d0320b8`。提交可建置生成檔、SHA-256與Apache授權；一般建置不依賴忽略的原始碼快取。依賴版本固定為13.2.1。公開型別仍沿用同版 npm 型別。維護方式見 `src/vendor/blockly/README.md`。

## 效能採樣限制與結果

採樣採用正式版內建診斷（requestAnimationFrame間隔、PerformanceObserver長任務、可取得的JS heap），不是實際螢幕呈現FPS或整程序記憶體。桌面5分鐘首頁/控制中心：平均rAF間隔16.2ms、超過50ms共274次、最長1883ms，長任務29次/最長2590ms、heap20.4MB。戰鬥頁/控制中心5分鐘：平均29.6ms、超過50ms共157次、最長1017.7ms，長任務8次/最長269ms、heap24.7MB。

可確認有停頓，不能拿平均值說完全流暢；未定位每筆長任務來源，不憑這份採樣硬上Worker。下一步需固定操作序列、前後版本同機對照，以及實體低階手機測試。
