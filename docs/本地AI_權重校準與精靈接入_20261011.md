# 本地 AI：權重校準與精靈接入（2026-10-11）

## 用法與規則

首頁「本地 AI 策略」與控制中心「戰鬥」共用設定；敵方 AI 與我方託管可獨立選擇，或讓託管跟隨敵方設定。手動操作不受影響。不連外部模型、不消耗模型 token。

| 維度 | 選項 | 意義 |
| --- | --- | --- |
| 打法 | 均衡／強攻／穩守／干擾／續航 | 分別偏重整體、輸出、防護、封鎖、回復及資源 |
| 風險 | 保守／標準／激進 | 對相同候選的平均、最差、最佳取樣結果如何折算 |

穩守＋激進可以押高收益但可能失敗的防守；強攻＋保守可以選穩定進攻。思考強度（簡單／標準／深入）只決定比較數量，不使用「謹慎」混淆風險偏好。

## 校準證據

先指定行為要求，再透過正式引擎比較，不從最高分反過來生成期望答案。

調整前，六種戰局 × P1/P2 共 12 個案例只有 8 個達標：純特攻者把無用物攻強化（25.50）排在有效攻擊（8.92）前；已有滿體力等量護盾、對手無輸出時，仍把十倍盾（71.50）排在有效攻擊（17.86）前。

因此在 `src/battle/ai/evaluation.ts` 調整通用評價，不在引擎硬編碼單隻精靈：

1. 護盾權重 70 → 45；前 100% 最大體力的盾正常計價，後 100% 只給 15% 邊際價值，再多不灌分。護罩仍獨立計算。
2. 攻擊／特攻強化依可用招式類型估價，防禦／特防依對手攻擊類型估價；必中招式不靠命中強化灌分。
3. 打法作用於己方／對手各評分項目；死亡與勝敗不因偏好折價。

修正後 12 個全部達標，有效強化、低血回復、滿血不回復、有後備時優先確定擊敗對手仍保留。這不是全精靈最優權重證明；特殊能力值傷害、多回合鋪場不能單靠物特分類完全估價。

## 風險不是進攻係數

`src/battle/ai/styles.ts` 統一管理兩個維度，不改真實傷害規則：

- 保守：平均 × 0.15 ＋最差 × 0.85。
- 標準：平均 × 0.55 ＋最差 × 0.45。
- 激進：平均 × 0.60 ＋最佳 × 0.40。

風格測試使用同一戰局：均衡／強攻選攻擊，穩守選護盾與抵擋，干擾選控制，續航選恢復。兩側共 10 個案例。

風險測試用同一機率護盾招式、同一戰局與亂數樣本：保守選穩定攻擊（約 8.91 分），激進選機率護盾（約 37.72 分）。護盾成功與失敗均經正式引擎結算。兩側共 4 個案例，證明保守可進攻、激進可押防守。另以五風格 × 三風險 × 兩側，檢查不能因偏好放棄本回合確定勝利，30／30 通過。

先覆蓋不同種子，再擴充對手回應；一輪中所有候選共用種子與回應，未完成一輪不採用半份結果。簡單模式選保守／激進時也要求至少兩種子，但預算不足仍可能只算一組，報告會標註無法比較波動。未驗算的回應組合也會列出數量。

快速評估／回退沒有機率取樣，不能宣稱完成風險模型；UI 與報告均明示。最差／最佳僅指已取樣結果，不是完整機率分布保證。

## 我方託管接線

正式引擎用 `settingsForSide` 取得 P1、P2 各自設定，並帶入對手設定作回應排序。兩側共用 `planDecision`／Worker／`simulateAction`，不維護另一套簡化託管規則。

整合測試啟用真正 P1 託管、讓 P2 自動回應：我方穩守真的用盾、敵方強攻真的攻擊，兩側報告均有真引擎推演。等待結果時關閉託管，舊結果不會寫成手動指令。技能、藥劑與換人仍經原正式輸入驗證，AI 不直接寫體力／PP。

## 之後更新精靈的流程

1. 按專案規範拆分觸發、條件、目標、行為；完成正式資料及註冊表／積木的真實實裝。文字有寫不代表程式已有。
2. 為機制補 P1/P2 真引擎語意測試。AI 已使用相同引擎，不需再複製一份技能效果或加入精靈白名單。
3. 跑 `npm run test:local-ai`。其中行為測試動態掃描 `DEFAULT_ELVES`；新精靈自動加入合法槽位、候選不漏與有限評分契約。本輪為 42 隻／84 個側別。這份契約不是逐句效果正確率。
4. 補獨立行為情境，例如充能不足先鋪場、有效防護擋下致死傷害；只有實際觀察到錯誤傾向才調整通用權重。
5. `npm run build` → `npm run test:local-ai-worker` → `npm run audit:bundle`。Worker 在建置時包含精靈模組；只更新描述但未更新效果／Worker，不會取得新能力。使用新建戰局與目前資料驗收，避免舊戰局混入舊配置。
6. 長期戰術若超過一回合推演，可在 AI 策略模組增加有限提示，不可放進 battleEngine／BattleScreen。主頁執行時註冊的函式不會自動傳入 Worker，共用策略需在兩個環境載入並另外驗收。

新註冊技能另有接入測試：不用 AI 白名單，也能由同一引擎判定低血時選擇有效回復。

## 驗收與界限

- `test:local-ai`：19 個合法性／隔離／生命週期檢查、首頁與控制中心雙向同步 DOM 操作，再執行行為測試。
- `test:ai-behavior`：12 個校準、10 個風格、4 個風險、30 個確定勝利案例，以及 4 組整合檢查（含 42 隻／84 側別接入契約）。
- 真正首頁操作測試、`test:core-mechanics` 回歸、型別、建置與正式 Worker 跨執行緒驗收均另跑。
- 首頁設定獨立載入，保留原 950 kB 初始 JS 與所有區塊 500 kB 預算，不提高門檻。首頁 DOM 懶載入等待上限改為 10 秒，未移除原詳情／刻印斷言。
- 推演未處理例外會停止沙盒，故意拋錯測試確認只執行一次且原局不變。效果內部吞下的錯誤仍須另外稽核，AI 算完不是效果正確率證明。
- 未完成全精靈多回合勝率、完整機率枚舉、實體低階手機量測或本輪實際 Edge 外觀／CSP 驗收。
- 本輪不提交、推送或發布網站，保留工作樹原有其他修改。
