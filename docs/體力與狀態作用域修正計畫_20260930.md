# 體力與切換串位修正計畫／紀錄

## 範圍與紅線

針對缺失面板造成體力100、RegistryState／計時器／印記串給下一隻、板凳事件誤寫在場者、額外精靈複製戰鬥狀態。既有工作樹包含其他尚未提交的改動，本次不得回退、覆寫或整批提交。

「下場後保留」指同一個 battleId 的精靈保留；不代表下一隻繼承。「己方所有精靈／己方在場精靈」、明文指定下一隻的效果則保留陣營作用域。

## 計畫與實際修改

1. **正式能力資料邊界**：提取 `elfStats.ts`，依種族值、等級、個體、學習力、性格、刻印、公會及年費配置重算。装備前不再製造 `hp || 100` 或缺失能力值1。舊格式只有完整面板時仍可使用；完全損壞資料明確報錯，不偽造數值。自訂／預設覆寫讀取與保存也使用此邊界。
2. **個體／陣營分離**：新增 `stateScopes.ts` 個體銀行，正常與強制換人共用轉換。個體永久計數、原始體力快照各自保存；短期 `*Turns`／本回合／本行動旗標下場清除；計時器只把明確陣營資料保留在場，其餘屬於持有者。回合類預設離場清除，回合計數／次數類在持有者銀行保存。
3. **印記所有權**：Context 附加印記預設綁定持有者；未知印記預設不下場保留。場下個體印記保留在側清單供本人回場取回，精靈物件只存自己的與陣營印記；傷害與回血乘區使用持有者過濾。同名不同持有者不得互相覆蓋／清除。
4. **寫入目標與召喚邊界**：Context 與 reducer 指定身分找不到時不退回在場者；板凳 Registry 寫入自身銀行。強制換人讀取退場事件後的最新 incoming，避免舊快照覆蓋合法技能傳遞。額外精靈只繼承基礎配置，印記、能力等級、存活規則、護盾與PP特權需明確指定。
5. **驗證**：新增 `test:scopes` 語意回歸，接入正式 `npm test`。再執行型別檢查、完整測試、正式建置，結果據實更新下方。

## 對參考分析的更正

- 體力100的裝備兜底確實存在；不能据此斷言使用者每次復現都來自此處。缺少實際異常存檔，測試覆蓋的是已確認的製造鏈。
- 現有 Context 的 updateElf 已能按 contextual self 找板凳，並非所有裸寫都寫在場；仍需修復「找不到身分就回退」的缺口。
- 燦界聖芒現有描述是「己方在場精靈」，因此 `scarlett_holy_light`、`chanStacks` 保留陣營語意，不按參考分析一律綁個體。
- `fear_seed`、`fear_flower`、`demon_grudge` 保留陣營效果；狄盧枷鎖、凱爾德魂、詩章下場保留綁個體。詩章明文轉移機制不刪除。
- 體力上限缺失和效果串位是不同資料邊界的問題，不能僅靠清切換狀態一併解決。
