# 專屬機制包裝（legacyWrapped）拆成真積木：規則與避免事項（2026-10-17）

對象：接手的 AI。目標：把稽核中 `legacyWrapped` 的 61 份定義逐份改成可在編輯器調參數的真 Kit，最後 legacyWrapped＝0，並推送到 GitHub。

## 0. 先讀
- `AGENTS.md`（BattleScreen.tsx / src/engine/battleEngine.ts 不得有精靈專屬碼；立繪朝向規則）
- `docs/積木化續作與時點規則_20261012.md`（使用者已確認的時點語意，以它為準）
- `docs/audits/unconnected-73-plan.md`（Kit 新增方式、檔案位置）

- `src/blocks/ops/legacyHandler.ts`（包裝機制）、`src/data/migratedLegacyWrappedKits.ts`（61 份清單）
- 清單：`npm run audit:block-migration` 後 `docs/audits/block-migration.json` 中 `legacyWrapped:true` 的定義

## 1. 使用者已定的語意規則（不得自行改判）
1. 描述只寫「傷害」未指明類型＝攻擊傷害（不含固定／百分比／真實）。
2. 「N回合內」含使用當回合；「下N回合」從下回合開始。兩者不可混用。
3. 持續多回合、綁定使用技能的回合類效果：**首次命中**才取得效果（當回合算第 1 回合），之後期間內每次符合條件的技能使用都觸發，**後續不要求命中**；出手前被控制／打斷＝該回合不觸發但期限照走、效果不終止。原文明寫回合開始／回合結束／受擊時觸發者，依原文時點。保留「使用攻擊技能／屬性技能」等範圍限制。
4. 「技能使用後」＝技能使用成功後（無效／未命中不觸發）。
5. 「技能無效」系列本質是未命中：Miss／閃避／攻擊免疫分支都會觸發攻擊方的 on_invalid 條款。
6. 異常未註明回合數用共用預設 3 回合。
7. 「恢復量」「等量」以實際結算量為準（滿血／禁療時跟著變少）。
8. 吸取「使用後只吸取 1 次」：同一次使用不得因多個入口重複吸取。

## 2. 每份的流程
1. 讀原文（以 TXT／原廠描述逐字為準，Kit 的 description 必須與原文逐字相同，`applyReviewedSkillKits` 靠逐字比對）。
2. 讀舊 handler，列出它實際做的每件事（含副作用：寫哪些 registry 鍵、被哪些其他 handler 讀取）。
3. 逐句對應既有 op／條件／事件；缺的先做**通用** op（放 `src/blocks/ops/<主題>.ts`，runtime.ts／sequenceContract.ts 只加註冊行，合約欄位要驗證）。
4. 寫 Kit 到對應的 `src/data/migrated*Kits.ts`，從 `migratedLegacyWrappedKits.ts` 移除該份。
5. 讓舊 handler 不再執行該效果：刪除 handler 鍵（或依現有慣例以 effectMode 閘門），同步 `tests/fixtures/elfRegistryBeforeMove.json` 與 elfRegistryModules 的遷移表。
6. 寫 P1／P2 雙側語意測試（正常、失效／未命中、被打斷、期限邊界、下場重置、數值上限），加進 `test:migrate`。
7. `npm run data:kit-pack` 重產打包檔。

## 3. 避免事項
- **不得**用 legacy_handler、custom、空動作或近似替代當作完成。
- **不得**弱化、刪除測試斷言來過測試；舊測試直接斷言舊 handler 內部狀態（計時器 id 等）時，改寫成斷言同等行為，語意不可放寬，並在 commit 說明。
- **不得**部分拆：舊 handler 整份執行時，只拆一部分會重複執行；要嘛整份轉，要嘛整份保留包裝。
- 有跨精靈耦合的（例如 5010 魂印「海」的副作用被「克制」「浪打千擊」讀取；5018 奧佩婭魂印的登場紀錄）：先轉被依賴方，再轉依賴方，同一批完成。
- 不在 BattleScreen.tsx／battleEngine.ts 寫精靈名稱、魂印名稱或專屬常數；引擎只加通用讀取端。
- 不手動合併 `reviewedKits.*.json` 等產生檔，一律重產。
- 不調高 `audit:bundle` 首頁預算（950000）；包裝的首頁瘦身邏輯（指紋重建）轉成真 Kit 後要確認仍在預算內。
- 原文有歧義時不要自己決定：保留包裝，寫進 `docs/積木化續作與時點規則_20261012.md` 的待確認區，問使用者。
- 共享工作樹：開工前在協作文件登記要動的檔案；不要回退其他 AI 的未提交修改。

## 4. 建議順序
1. 先做缺通用 op 最少的（純數值／條件類）。
2. 再做有共同機制的群組，一次補一個通用 op 解鎖多份：
   - 疊層／層數狀態（符文、詩章、龍鱗、寂殺之魄）
   - 額外行動／連擊（賽博怨靈、終焉·六花斬、亂舞類）
   - 倒下前／本場一次事件（保留 1 體力、重生）
   - 能力等級視為（stage_view）、PP 上限與充能
   - 額外精靈／背包查詢（克塔亞特、場下精靈）
3. 最後做跨精靈耦合的魂印。
