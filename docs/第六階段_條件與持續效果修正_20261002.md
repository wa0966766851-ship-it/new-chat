# 第六階段：條件與持續傷害效果修正

本輪範圍：第五階段剩餘「複合 gate 的巢狀條件」與傷害執行入口。沒有提高明確積木執行登記數，沒有更改特殊模式經濟規則或宣稱逐隻效果驗收完成。

## 實際修正

| 問題 | 處理及證據 |
| --- | --- |
| 對手屬性只接受完整字串，電系條件不認神秘·電 | `effectConditions.ts`：單項、完整雙屬性及簡繁匹配；不使用模糊名稱包含 |
| 缺失精靈／體力上限快照時條件可能視為成功 | 缺失／非法快照判定失敗；負體力仍按實際比率判斷；等於門檻不算嚴格大小於 |
| 不知道出手順序時被當成後手 | 明確保留未知值；先手、後手及否定條件都不猜測；持續 gate 按持有者換算出手順序 |
| 層數讀到場下同名／已過期計時器 | 只接受同持有者或陣營計時器，保留合法陣營效果；層數條件缺少ID拒絕匯入 |
| 舊式內部效果的明確目標被預設覆蓋 | 保留 `innerTarget`，遞迴正規化百分比等參數；新式多子效果各自保留目標 |
| 持續增減傷忽略巢狀條件 | `damageGates.ts` 共用條件判斷，只讀取增減傷，不在傷害計算途中執行追加傷害／回血 |
| 雙方增減傷全部混在同一傷害上 | 增傷僅作用於造成者，減傷僅作用於受到者；明確子目標仍可指定對手 |
| 普通攻擊漏接持續增減傷 | `BattleScreen.tsx` 呼叫共用模組，不加入精靈名稱硬編碼；附加傷害API沿用同模組 |
| 自傷的造成者被推定為另一方 | `contextBuilders.ts` 使用呼叫來源side；實際API測試自己2倍＋自身20%減傷為160，不偷用對手9倍倍率 |
| 真傷持續增傷在安全倍率快照後才讀，失效 | 在安全倍率計算前讀閘門；保留現行「真傷不減傷」規則，增傷實際API測試100→200 |
| 普通攻擊讀易傷印記漏做持有者過濾 | 使用 `markAppliesToElf` 篩選，避免側清單場下印記污染在場者 |
| Windows舊工作樹Blockly校驗失敗 | 確認8檔僅CRLF差異；新增 `format:blockly` 先驗證所有正規化SHA再修換行，任何內容差異拒絕寫入 |

## 驗證邊界

新增14組語意測試：條件正反／缺失快照／負體力／雙屬性／出手順序／持有者／狀態別名／巢狀目標／增減傷方向／傷害範圍／舊參數／真正API接線。
真正固定／真實傷害API由Vite載入實際註冊表測試，沒有注入空註冊表。普通攻擊呼叫位置以接線斷言檢查；尚未用完整UI對戰逐隻覆核攻擊效果，不把接線斷言當作完整實戰。

初次真正API測試因Node不支援 `import.meta.glob` 失敗，改以Vite載入實際註冊表後通過。第一次完整測試因Windows換行SHA不符失敗，修復後重跑；最終結果另記於本文件收尾，不抹去失敗原因。
