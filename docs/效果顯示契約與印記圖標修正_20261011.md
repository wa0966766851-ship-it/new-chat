# 效果顯示契約與印記圖標修正

本輪範圍是顯示資料與讀取端；不是全精靈語意驗收，也不是接手其他 AI 的全部積木遷移。既有未提交修改保留，未提交、推送或發布網站。

## 已確認的混亂來源

- 註冊表 `timed()`、`uses()` 曾把技能名稱當效果名稱；Kit 計時器則顯示「持續效果」。
- 圖標靠名稱／說明的第一個關鍵字猜測，複合效果可能拿到完全不相關的圖。
- 簡介、頭像明細與效果檢視器各自拼資料；部分欄位與 Timer 重複顯示，負面極性未被讀取，攻擊技能封鎖被標成屬性技能封鎖。
- 印記既有 `iconTag` 沒有被所有讀取端採用；馬爾修斯的常駐機甲不應借用星執／魔王咒怨的名稱、圖標或虛構期限。

## 共用契約

`src/battle/effectPresentation.ts` 定義純顯示資料：

```ts
presentation: {
  semanticId: 'invalid:攻擊',
  label: '攻擊技能無效',
  description: '下一次攻擊技能無效。',
  sourceName: '來源技能名稱',
  iconTag: '技能無效',
  polarity: 'negative',
}
```

- `semanticId` 用來辨識顯示語意，不替代 Timer 的執行 ID。
- `label` 是實際效果，不是來源技能名稱。來源放 `sourceName`。
- `iconTag` 只採用明確登記的精確名稱；不能填整句描述，也不由正則猜測印記身分。
- `polarity` 是相對於持有者的正面／負面／中性，不是由「增傷」兩字決定。受到傷害提升是負面，受到傷害降低是正面。
- `remaining`、`kind`、`ownerBattleId`、`clearable`、`persistsOffField` 與 payload 仍是原本的結算資料；顯示不改期限、次數或所有者。
- 複合效果不能任選其中一項的圖標冒充整份；未確認素材使用 `public/status-icons/effect-placeholder.svg` 中性佔位。

### 新增或遷移效果時

1. 優先使用 `timed()`、`uses()`、`addBlockTimer()`；它們從已存在的結構化參數建立顯示資料。
2. 若參數未涵蓋，提供明確 `presentation`，或擴充共用映射及測試。不要在主引擎硬編精靈名稱。
3. 未映射的參數保持「待補說明的效果」／積木組合提示，不假裝已有完整說明。完整條件、成功與失敗分支仍查來源 Kit。
4. Timer 的 ID 不因改名而改動。測試執行身分應斷言 ID，而不是舊版通用標籤。
5. 圖標缺漏和效果未實裝是不同問題：中性佔位不代表效果失效，提供圖標也不代表效果驗收通過。

## UI 接法

`activeEffectViews()` 是簡介、頭像明細與效果檢視器的共用唯讀投影。

- 能力等級 → 異常 → 印記／計時／次數／常駐機制；護盾、護罩保持獨立容量顯示。
- 護盾／護罩為容量，不再虛構「1回合」；常駐機制不虛構剩餘次數。
- 同一效果的舊欄位鏡像只在語意和數值都相同時隱藏；兩個不同 ID 的真實 Timer 即使同名仍保留。
- 對手隱匿／幻化的說明來源使用可見投影，效果檢視器標題也不洩漏真名；己方負面效果的來源文字、提示與明細同樣套用既有迷霧詞彙遮蔽。
- 魘昧沿用目前 `statusRegistry.ts` 的定義：異常與能力提升顯示為 1 回合魘昧，能力下降照常；那個 1 是遮蔽顯示，不是實際期限。本輪未修改異常規則。
- 主標籤不再截成首字；HUD 長複合標籤限制寬度並可點擊看完整說明。尚未做實機手機逐像素驗收。
