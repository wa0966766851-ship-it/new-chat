# 建置與載入效能修正（2026-09-30）

## 實際結果與限制

本批改善啟動載入與編輯器初始化成本，沒有修改傷害、魂印、精靈朝向或立繪比例。大型區塊警告尚未全部消除，也未進行使用者實機的 FPS 或長任務測量；不能據此宣稱完全不卡頓。

下表採 Vite 輸出的十進位 kB，為壓縮程式碼但尚未 gzip 的大小。動態載入改變下載時機，不表示總資料量消失。

## 修改檔案與作用

- `src/components/StartScreen.tsx`、新增 `LazyBlockProgramView.tsx`：積木詳情與效果庫延後載入；保留原有 handler/blocks 來源判斷。
- `src/components/ElfEditor.tsx`：效果工具與積木頁獨立延後載入。
- 新增 `src/blocks/kitEntries.ts`、`ElfBlocklyPanel.tsx`：詞條分類不再為了匯入一個判斷函式而連帶載入完整 Kit 編輯器及資料庫；原匯出仍保留相容性。
- `KitEffectBuilder.tsx`：未使用的模式不搜尋整份資料；搜尋使用延後值，輸入先回應，結果隨後更新。積木換槽資料動態載入並有等待、失敗提示；非積木詞條照舊保留。
- `BlocklyBuilder.tsx`：改用 core 與原英文語系，省去本畫布未使用的通用程式積木庫；不移除自訂效果積木。
- `src/data/codexRegistry.ts`、新增 `codexEntry.ts`：字典索引保持同步可查，atoms 首次讀取才解析並快取；保留自訂註冊覆寫及 atoms 賦值能力。
- `vite.config.ts`：產生載入清單；未提高 500 kB 警告門檻。
- 新增 `scripts/audit_bundle.ts`、`tests/codexLoading.semantic.test.ts`，並在 `package.json` 增加 `audit:bundle`、`test:loading` 指令。
- 第二階段：`src/effects/abilityRegistry.ts` 改讀純資料；在 `src/data/elfProfiles/` 新增 17 檔，把 23 份描述物件原樣搬出對應的執行註冊檔。涉及 puni、lisa、monkey、dixin、opeia、odin、keld、keerhode、scarlett、mars、chaosBlake、wargods、wuxu、zhakesiFear、zhakesiAnnihilation、beliente、canglan 的 Registry。原檔保留同名 re-export，handler 內容不變。新增 `profileLoading.semantic.test.ts` 防止執行相依被加回描述資料，兩組載入測試已納入 `npm test`。

## 尚未解決／下一階段

1. 首頁仍 731.62 kB：描述資料已與執行 handler 解耦，但首頁本身、常駐控制中心、精靈資料仍混在一起。接著應拆非必要對話框，避免只分包卻仍全部在啟動下載。
2. 效果字典 1193.99 kB、積木資料 600.99 kB：已延後載入，但首次使用仍需解析完整 JSON。真正再降成本需要依分類載入資料及快取，不能破壞同步字典 API 或漏掉 fallback。
3. Blockly core 所屬區塊仍 715.42 kB：已僅留需要的核心及語系並延後載入；不應任意拆第三方壓縮核心，或提高警告門檻假裝改善。
4. 未量測戰鬥低階電腦／手機幀率、首次積木載入卡頓、長時間對戰記憶體。正式版驗收需測首頁、開戰、切換精靈、密集傷害、三個效果編輯模式及退出重進；記錄長任務與幀時間，再決定是否需要 Worker 或更低成本視覺模式。
