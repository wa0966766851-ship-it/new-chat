# 本地戰鬥 AI：模組拆分與驗收（2026-10-11）

## 範圍與結果

實作不連接外部模型、不需要 API 金鑰、不消耗模型 token 的本地 AI。以既有戰鬥引擎推演一個完整回合，再用局面評分選擇行動；不是以另一套簡化傷害公式取代戰鬥。

保留原有快速評估入口與精靈策略提示。背景引擎尚未載入、環境不支援 Worker、戰局含無法複製的閉包、推演失敗或逾時時，明確回退而不宣稱已完成推演。

此輪接上先前已抽離的 `src/engine/battleEngine.ts`，不是重新宣稱完成該檔案的抽離；也不搬動他人正在修改的精靈效果或積木定義。

## 模組責任

| 檔案（`src/battle/ai/`） | 責任 |
| --- | --- |
| `types.ts` | 行動、請求、設定與決策報告合約；技能以槽位傳輸 |
| `legalActions.ts` | PP／充能／選招／禁切／強制換人／藥劑庫存合法性 |
| `knowledge.ts` | 私人選招移除、隱匿／幻化可見資訊投影與戰局複製 |
| `evaluation.ts` | 集中局面權重；不修改戰鬥傷害、回復及機率 |
| `styles.ts` | 五種打法、三種獨立風險偏好 |
| `hooks.ts` | 既有精靈長期策略提示與可註冊策略掛鉤 |
| `legacyScoring.ts` | 保留既有快速評估實作與公開介面 |
| `heuristic.ts` | 快速候選排序，串接現行能力、傷害與公開技能投影 |
| `decision.ts` | 安全回退與一致的決策報告 |
| `search.ts` | 同種子、同回應、全候選完整比較；平均與最差回應風險 |
| `simulation.ts` | 正式引擎沙盒，完整回合／替補登場，隔離狀態與機率計數 |
| `worker.ts` | 背景執行緒入口、載入、進度與結果訊息 |
| `client.ts` | 預載、請求 ID、時間上限、取消、終止與回退 |
| `settings.ts` | 設定校驗／儲存、難度上限、最近兩側決策報告 |

`src/battle/ai.ts` 保留相容匯出；`src/utils/ai.ts` 保留原呼叫介面與實際行動還原。`BattleScreen.tsx` 只接服務與顯示，不添加單隻精靈專屬邏輯。引擎仍以既有註冊表／BattleContext 結算。

## 使用位置及流程

首頁 → 本地 AI 策略，或控制中心 → 戰鬥 → 本地對戰 AI：P1託管與P2敵方可獨立選五種打法與三種風險。控制中心另可選背景推演／快速評估、思考時間與決策說明。權重唯讀，不改遊戲規則。詳見 `本地AI_權重校準與精靈接入_20261011.md`。

1. 取當下戰局快照，移除對手未公開的選招及隱匿／原形私人資訊。
2. 列出合法技能槽、換人與實際可用藥劑，快速排序作為回退。
3. Worker 以相同回應與種子比較所有候選。只發布完整比較，不把未計算候選當成零分。
4. 正式引擎結算行動、魂印、狀態、死亡、換人與回合末；不重跑首發登場、不呼叫外部存檔或消耗真實庫存。
5. 依局面變化與風險排序，主引擎重新驗證行動是否合法後執行；過期結果不寫回。

預設 600 ms，校驗範圍 100～2000 ms；主執行緒另留 75 ms 傳輸餘裕，超時終止 Worker。簡單／標準／深入分別最多 48／96／144 個推演，對手回應 1／2／3 種、種子 1／2／2 個；保守／激進至少要求兩種子，未完成會明示。單個同步 handler 可能超時，故由外部 Worker 看門狗終止，不只靠引擎內計時。

初次冷啟動可先快速評估；PVE 進場預載背景引擎。控制中心明示本次是推演或回退，不把回退結果包裝為成功推演。

## 結算與資訊隔離

- 真實推演以現行引擎為準，包括護盾／護罩、能力、印記、回合效果、PP、充能及額外行動；因此既有引擎效果若未實裝或錯誤，AI 不會自動修好。
- 原局快照、全域 PRD／PRNG 計數與測試用隨機源皆須還原；瀏覽器推演只在 Worker，不在主執行緒改寫 `Math.random`。
- 零血／負血仍存活的規則不直接按死亡計分；零傷害不取得擊殺獎勵。
- 強制換人推演替補登場；不把它冒充下一個完整戰鬥回合。
- 隱匿敵人使用未知代理身分，避免由原 ID 偷觸發特殊機制；幻化敵人使用公開複製形態。這是未知資訊假設，不是完美資訊預測。
- 策略提示獨立於推演局面加分，避免登場效果／復活被重複灌分。提示不改戰局。

## 建置體積

Worker 原本把大量資料及戰鬥邏輯合在單塊，依既有資料、描述解析、精靈註冊模組與通用引擎邊界拆分；沒有提高警告門檻。

背景引擎主塊約 421.68 kB、精靈效果約 292.24 kB、百科資料約 451.82 kB。頁面及 Worker 的所有 JS 區塊均納入 `scripts/audit_bundle.ts` 的 500 kB 預算（原頁面 manifest 不包含 Worker，已補漏）。單塊降低不等於總下載量降低；背景引擎仍包含大量既有效果，按需載入與背景執行只避免首頁提前負擔及主執行緒推演。

## 驗收證據

- `npm run lint`：型別檢查。
- `npm run test:local-ai`：19 項後台語意情境＋設定介面的 DOM 操作；包含複合護盾／強化、P1/P2、死亡換人、同種子重現、資料隔離、超時、例外停止及不可複製回退，並驗證儲存容量不足時設定仍生效；另執行 `test:ai-behavior` 的風格／風險／動態接入檢查。
- `npm run build` 後 `npm run test:local-ai-worker`：載入正式打包的 Worker 模組，真正跨執行緒推演及傳輸；不是只測測試版替身。
- `npm run test:core-mechanics`：既有共同機制、蟲后、攻防、減傷、PP、正式節點、傷害管線、換人與積木語意回歸，並納入新的本地 AI 測試。
- `npm run audit:bundle`：首頁按需載入、原首頁大小預算與全部頁面／Worker JS 區塊預算。

## 不能據此宣稱的事項

- 尚未逐隻驗證全精靈 AI 戰術強度，既有專屬提示不是全精靈策略全覆蓋。引擎 handler 可吞下部分內部錯誤，成功完成一回合也不是效果正確率證明。
- 目前是有限的一回合多回應取樣，不是多回合最優解、不知道人類將選的技能，也不是完整機率分布枚舉。
- 部分動態閉包不能序列化，會保留原效果並回退，不移除效果以強行推演。
- 尚未在實體低階手機測 FPS／長時間記憶體，也未在實際 Edge 驗證本輪面板外觀與 CSP；DOM 及正式 Node Worker 驗收不等同那些結果。
- 沒有 commit／推送／網站發布；工作樹中原有其他人的大量修改仍保留。
