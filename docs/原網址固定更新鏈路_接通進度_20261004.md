## 安全審核要求的明確授權

首次設定遭安全審核攔下，理由是尚未明確授權這項敏感憑證外送。使用者後續回覆「是的」並要求確認不會公開網站；再次核對原站為 custom 分享、倉庫由使用者管理後，已經允許並完成設定。

已設定兩個變數：`SEER_SITE_SERVICE_TOKEN` 與 `SEER_SITE_PUBLISH_KEY`。使用者不曾在聊天中貼出憑證；本機設定透過隱藏 stdin，明文僅在記憶體中，GitHub 回應只顯示變數名稱與設定時間。

授權範圍：讓本倉庫的 Actions 對原網站存取並上傳已校驗的新版內容。具有 workflow 修改／執行權限的人可能使用這些憑證；因此需保護倉庫管理權、限制不可信 workflow，不得把變數寫入公開檔案或日誌。

## 公開範圍與加密界線

網站的 custom 分享名單未更改，保存憑證不等於公開網站。但遊戲 GitHub 倉庫本來為 public；已有原始碼／素材的可見性，不會因設定 Secrets 而變成私有。若要求連原始碼也不被外部查看，需要另外決定是否將倉庫改為 private，不能以網頁內藏解密金鑰代替。

GitHub 使用 sealed box 加密保存憑證，傳輸使用 HTTPS；網站發布由伺服器驗證獨立金鑰，玩家仍由平台分享規則控管。這些是不同層次，不是把可在瀏覽器取到的解密密碼當作登入機制。
