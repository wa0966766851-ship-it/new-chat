# 積木來源一致性：根因修復與全庫掃描（2026-10-22）

## 根因與修復

精靈存檔保存整份技能／魂印／特質定義，戰鬥再建立獨立的動態副本。戰鬥副本本身有必要；真正缺口是缺少來源版本：以前僅補回「沒有 kit」的舊定義，已有非空舊 kit 就永久停留在舊版。另外，編輯器、效果庫、能力詳情與執行端對 `Elf.kit`／`soulMark.kit` 的優先順序不同。

本輪採用共用修復，未在 BattleScreen 或 battleEngine 加精靈專屬判斷：

1. `src/data/builtinEffectBindings.ts` 記錄每份定義的上次內建指紋，三方比較「上次內建／存檔現值／最新內建」。未自行修改的效果隨內建更新；修改過的定義保留，其他未改定義仍能升級。指紋只作變更偵測，不是安全簽章。
2. 經既有 `applySavedSkillCorrections` 入口套用，保留配裝、體力、技能 PP 與實例身分。舊存檔缺乏版本且內容不同時列為 untracked，不猜測覆寫。
3. `src/effects/soulDefinitionSource.ts` 統一執行、效果庫、詳情、事件預篩選及 AI 幻化讀取：優先魂印 kit；只有欄位不存在才相容非技能的根 kit。明確空陣列不會從殘留根資料復活效果。
4. ElfEditor 將魂印積木存入 `soulMark.kit`，同時保留根 kit 相容舊入口；幻化詳情使用被取得精靈的根 kit，不能借用原持有者。
5. 圖紙匯出／匯入保留並驗證來源記錄，避免一次圖紙往返又失去版本資訊。自訂 ID、明確停用及已追蹤的手動刪除均受保護。

## 全庫與舊快照掃描

執行入口：`npm run audit:stored-effects`。讀取正式延後載入完成的 DEFAULT_ELVES，涵蓋魂印、一般特性、各類異能特質、出戰技能與替換池。無輸入時掃現行內建庫；也可傳存檔 JSON 或含 `store-*.json` 的快照資料夾。只在記憶體套用修復，不寫回輸入或使用者儲存空間。

## 驗證與範圍

- 來源綁定回歸：全庫、舊非空 kit 跨版本升級、自訂／空 kit 保護、技能重排、根 kit 相容、配裝／PP／實例保留。
- 聖靈譜尼正式 P1/P2 引擎 23 項：包含非空舊 kit 缺免控／免弱化入口的反例，升級後驗證真正免疫，並非只檢查節點存在。
- 編輯器實際儲存 → 圖紙往返 → 正式 P1/P2 引擎整合 10 項。
- 六種儲存路徑的升級、備份與冪等性，以及既有雷伊／舊技能修正回歸。
- 額外事件預篩選、AI 幻化來源與殘留根 kit 回歸。
- 型別檢查、正式建置。

本輪為後台測試與存檔掃描，未重新開前台手動實戰、未連線實戰，亦未更新使用者已開的戰局、EXE 或網站。全庫掃描只能證明本次來源／路由／合約檢查範圍，不能宣稱所有積木的戰鬥語意已逐條驗收，也不能宣稱戰鬥正確率 100%。
