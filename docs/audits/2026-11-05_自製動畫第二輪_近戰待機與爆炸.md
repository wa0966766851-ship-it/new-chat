出招已有可辨識的第二版：帝辛低身刺斬、六刃黑綠劍近身斬擊；原本遠程畫作留給特殊攻擊。墜星落砲有六階段爆炸圖、煙塵與碎片。蝕言額外行動有敵方咒頁聚集與裂隙收束。

**待機未完成，未通過品質驗收。** 現在四隻仍各用一張待機畫作，加局部胸口／衣襬小幅變形與能量細節；雖然資料不是完全不動，但正常對戰大小看起來仍接近靜圖。使用者要求至少接近官方動態圖的可讀性，這版沒有達標。格式測試、352 個小格或 96 個播放影格都不能代替觀感驗收。

近戰也仍只有少量關鍵姿勢，蓄力、出手與收劍可能看出切圖；不能稱原廠級逐格動作。

## 修到的接線問題

1. `preparePetFx` 會淺複製 clip，原本保存在 WeakMap 的砲口／劍尖定位資料因此遺失，實際戰鬥退回角色中心。`customPetClip.ts` 改以可隨淺複製保留的 Symbol 攜帶資料，並以真正的 preparePetFx 路徑測試。
2. 近戰接觸點不應按對手武器／披風外框最邊緣停止。共用呈現參數 `contactDepth` 允許此批姿勢向可見範圍內接近；其他原生精靈維持原行為。這不是全精靈骨架定位，仍須驗收不同體型。
3. 命中火花在命中後固定於接觸點，不隨收劍姿勢被拖回施法者。
4. 六刃原抱胸圖與新出招圖朝向不一致。只在製作匯入時正規化待機，遊戲仍共用一次鏡射；不得翻轉整個 HUD 或父容器。靜態 URL 與動畫分別登記。
5. 編譯器可拒絕與整段朝向不符的 pose.facing；準備腳本記錄每張正規化後方向。這是防止已知不一致，不能自動判斷圖片實際面向哪裡。

## 待機下一步：先做好一隻，再擴展

1. 六刃原稿作角色標準；先固定面具、單眼、六劍、裝甲與鞋。原圖朝右，匯入朝左，P1/P2 一次鏡射。
2. 先設計一輪可看懂的風向與呼吸：胸肩小幅起伏、衣襬有延遲波浪，六劍如需浮動應緩慢錯相，不能繞圈或讓剛性劍刃彎曲。頭與腳不能滑走。
3. 補畫呼吸上升、頂點、回落、回穩的相鄰關鍵畫作，先檢查輪廓連續；大改衣襬形狀不能硬套同一張網格或用淡入淡出遮掉雙影。
4. 可用修整後分層與局部變形補小幅中間動作；被遮住的布料必須真正補畫，不複製邊緣。大幅轉頭、手勢與武器透視另畫。
5. 正常遊戲尺寸連播兩輪、關閉光效，肉眼應看見合理動態；首尾不能跳、臉不能漂、衣服不能融化、手不能離開武器。達標才擴展帝辛、墜星與蝕言。
6. 暫不以影格數或 PNG 數量設通過門檻；與譜尼／雷伊同尺寸並排看片，再存畫面與問題清單。

## 大小與驗證

四張角色圖集下載各約 1.5–2.5 MiB；解碼後單張約 4.1–7.9 MiB。爆炸 PNG 1,365,538 bytes。manifest 約 52–63KB，局部待機以少量參數儲存，再於載入時展開；已避免每隻寫入約 9MB 重複頂點。這些不代表整場總記憶體量測。

本輪格式測試：customPetAnimation 36/36；customBattleFx、customCombatV2、poseAnimation 通過。battleSpriteFacing 15/15，包含新增六刃靜態／動作分開鏡射回歸。TypeScript 檢查與獨立驗收頁 Vite 建置通過。`customCombatV2.semantic.test.mjs` 須帶 `--import tsx`，直接用 node 會無法解析 TypeScript 無副檔名匯入；這個呼叫錯誤已修正後重跑。

本輪未修改戰鬥效果、魂印、PP 或傷害結算；動畫效果由共用呈現參數接線，沒有把精靈專屬判定塞入 BattleScreen 或 battleEngine。
