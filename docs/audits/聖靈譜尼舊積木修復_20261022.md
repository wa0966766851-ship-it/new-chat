# 聖靈譜尼舊背包魂印失效

## 已重現的原因

歷史背包的 soulMark 沒有可執行 kit，但 Elf.kit 留有 11 個原始描述詞條。舊修復函數把「存在非技能頂層積木」一律視為使用者自訂，因而跳過魂印恢復。這些描述詞條不等於真正的魂印行為，導致舊背包能被沉睡、攻擊與防禦下降；只用全新內建定義的測試無法涵蓋此情境。

## 修改邊界

- 從備份提交 0e340a43e48bd05ebbe144a2c4237b522c0c66e8 的 defaultElves.ts，以 AST 字面量提取歷史指紋（譜尼、聖靈譜尼兩份）。生成器不執行舊程式。
- 只有 id、精靈名、魂印名、頂層非技能積木完整相同，且原文符合現行或已知歷史原文，才補入當前魂印 kit。
- 原頂層資料、技能 PP、配裝、實例等保留；自訂積木、改寫文字、明確停用模式均不覆寫。
- 六條既有儲存路徑沿用先備份再修復；備份失敗不覆寫原存檔。沒有修改引擎或 BattleScreen 的精靈專屬邏輯。

## 驗證

- migrate_5000_puni_soul.semantic.test.ts：21 項通過。P1/P2 各以歷史頂層積木重現修復前沉睡與弱化，再驗證修復後免疫；另覆蓋清回合效果後的防護與其他原有魂印情境。
- savedBuiltinStorage.semantic.test.ts：六條路徑皆納入上述舊譜尼資料，驗證魂印恢復、原始備份、冪等與保護條件。
- test:saved-skill-corrections、legacyBuiltinSave.semantic.test.ts、型別檢查與正式建置通過。
- 未把此結果宣稱為所有精靈或所有專屬特性的正確率。尚未在使用者當前 EXE／既有戰局重現驗收；本次未打包 EXE、發布網站或推送。

## 套用時機

修復隨目前程式在讀取舊背包時執行。重新載入更新後程式並新開戰局；已啟動戰局不會中途替換魂印。舊 EXE 需要更新程式後才會具備本修復。
