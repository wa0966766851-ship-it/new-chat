# Gemini 決策輔助與 AI 藥劑開關：研究及接入設計

日期：2026-11-17。範圍：研究、現況核對與接入設計。未修改對戰程式、未安裝依賴、未使用金鑰呼叫模型。桌面 `api.txt` 已確認存在，只查檔案資訊，未讀取內容、未複製進專案。

## 結論

可以接入。建議採「本地引擎推演 → Gemini 協助評選 → 本地驗證與執行」，原有 AI 保留，模型輔助預設關閉。模型可幫助比較戰術與特殊道具價值，但不能假設一定提升勝率，更不能取代本地傷害、合法性與狀態結算。

藥劑限制可獨立實作，不必等模型；三個允許開關預設全開，適用敵方 AI 與己方託管，人工使用道具與技能不受影響。

## 官方介面核對

- 官方已提供 `gemini-decision-1`、`client.decisions.create`，目前限定 Developer API `v1beta`。使用者提供的 Python 初始化方式方向正確，但初始化成功不等於已驗證模型可用。
- 支援 yes/no、choice、score；回傳選項／評分、分布與 confidence，不生成解釋文字。官方將它和多步推理／文字生成區分；其選項機率不是本遊戲的勝率。
- 官方快速開始要求 SDK 3.2+。專案 `package.json` 宣告 `@google/genai: ^2.4.0`，本機實裝為 2.21.0，型別中未找到 Decisions 介面。
- 建議第一版在 Node 後端用內建 `fetch` 呼叫 `POST https://generativelanguage.googleapis.com/v1beta/decisions`，以 `x-goog-api-key` 標頭傳送金鑰。不新增 Python 服務，也不為此整批升級既有 SDK。
- 查核時官方價格：輸入每百萬 tokens US$0.10，輸出 0 tokens；有免費額度。共享輸入在同一請求計一次，各問題仍增加輸入用量。每回合仍會重新計入輸入，官方不支援此 API 的 context caching／Batch API。實際帳戶權限、額度及延遲未驗證。
- 金鑰留在本機不代表模型離線：啟用後，送出的戰況摘要仍會傳給 Google。官方對免費與付費服務的資料使用規則不同，首次啟用須顯示這項資訊。

## 決策流程

1. 在行動開始時取得版本化決策快照；包含戰鬥識別、side、回合、出場個體、狀態版本與設定版本。
2. `legalActions` 先判斷遊戲合法性；新的 `actionPolicy.ts` 再過濾 AI 不允許使用的藥劑。
3. 保留本地快速排序／Worker 推演。模型關閉、沒有金鑰、模擬戰分支或只有單一候選時直接採本地結果，不發請求。
4. 從本地候選建立小型清單，起始上限建議 6 個。除得分前列外，保留有明確用途的淨化、解除弱化、指定幻化等戰術替代；不能因目前特殊道具評分較低就全部排除。
5. 建立欄位白名單摘要：可見體力／PP／能力等級／狀態與剩餘回合、己方可知資源、技能及道具的結構化效果、各候選的推演結果與假設。
6. 一次 Decisions 呼叫評選合法候選；choice 中增加明確的「沿用本地選擇」選項。若另問戰術評分，問題須獨立定義，不能假設後一問題讀得到前一答案。
7. 第一階段先比較建議，不接管；通過實測後，再讓模型在本地結果接近、沒有明確劣勢的候選間協助選擇。差距、信心門檻需用本專案測試校準，不直接把 confidence 當勝率或任意加到本地分數。
8. 執行前重新驗證戰況版本、設定版本、候選 ID、庫存、選招與 AI 藥劑限制。模型回應不能創造技能、道具、目標或執行程式碼。
9. 網路失敗、401／403／429、無有效答案、低信心、超時、戰局過期，一律使用「當下仍合法且通過政策」的本地結果。

現有 100–2000ms Worker 預算不直接套用到網路。另設模型等待上限，起始建議 3 秒；介面顯示等待並可取消。關閉模型、換人、結束戰鬥或更改設定會中止／作廢在途結果。取消本機請求不能保證供應商不計入已開始的用量。

不傳整個背包存檔、戰報、圖片、磁碟路徑、API 金鑰、隱藏敵方資料、未公開選招、PRNG 種子／計數器或可執行效果程式。自訂精靈文字作為資料處理，不作系統指令。對戰資料版本或效果理解不足時保留本地結果，不宣稱模型已理解所有魂印。

成本控制採每個決策最多一次請求、單一金鑰並發上限、請求長度上限、每場請求上限及用量顯示；逾時不自動反覆重試。應用程式的上限不等於 Google 帳戶所有用途的帳單上限。

## 本機限定與金鑰保護

- 設定頁提供密碼輸入框、儲存、刪除、測試連線；讀取設定只回傳「已設定／未設定」，不回傳原金鑰。儲存後清空前端輸入值。
- 預設只在本次執行保留金鑰；使用者選擇記住時，Windows 使用 DPAPI CurrentUser 加密，保存在使用者資料目錄、以安裝／專案識別隔離的憑證檔，並限制檔案權限。不放在 Git、`.env`、`public`、`dist`、更新包、戰報、圖鑑匯出或瀏覽器 localStorage。
- 目前桌面捷徑是 PowerShell 啟動本機服務，不能只做 Electron safeStorage。憑證介面需供兩種啟動方式共用；Windows DPAPI helper 若需啟動子程序，以 stdin 傳遞內容，不把金鑰放在命令列或日誌。
- API 呼叫由本機後端執行，僅連固定官方 HTTPS 主機。第一版不提供任意上游網址，避免把金鑰傳給第三方。
- 新路由只在本機模式掛載；同時核對 loopback 來源、實際 Host／Origin、JSON Content-Type、每次執行的會話憑證／CSRF 防護與請求大小，拒絕跨站、LAN 及 DNS rebinding 請求。只綁 `127.0.0.1` 仍不足以取代這些檢查。
- 公開託管／靜態網頁模式不提供此本機憑證服務；其他使用者安裝後從空白配置開始，填入自己的金鑰，沒有共用開發者金鑰或暗中回退到原有生成服務金鑰的路徑。
- 狀態、錯誤與診斷只記錄代碼、時間、選項 ID、用量；禁止記錄金鑰、Authorization、上游完整錯誤／請求標頭與預設完整戰況。金鑰以標頭傳遞，不附在 URL。
- 若之後需要從桌面 `api.txt` 匯入，設明確的一次性操作；不在啟動時自動掃讀，不接受前端指定任意磁碟路徑。多筆／不明格式不能猜選。原始明文檔不因匯入而自動刪除。
- 這保護磁碟、發佈包及一般應用使用；無法保證抵抗同一帳號下可讀取程序記憶體的惡意軟體。

## 藥劑開關

目前核對 `BATTLE_ITEMS` 共 120 筆：攻擊干擾 22、附加異常 40、特殊分類 10、解除異常／弱化 2，其餘為恢復、強化及複合類。兩筆解除類的 `type` 仍為 `special`，只檢查介面分類會漏掉它們。

建議設定：

| 設定 | 預設 | 規則 |
| --- | --- | --- |
| 允許攻擊／干擾藥劑 | 開 | 攻擊分類及扣對手 PP、反噬、封藥、封換等效果。 |
| 允許控制／附加異常藥劑 | 開 | 依現有附加異常類及 `inflictStatuses` 判斷，包含控制與中毒等異常。這是本設計的分類定義。 |
| 允許直接藥劑傷害 | 開 | 檢查 `oppDamage`、`oppDamagePercent` 等真正直接藥劑傷害效果，不只檢查分類名稱。 |
| 特殊藥劑與解除用途 | 保留 | `type === special`／特殊分類及既有解除、指定幻化用途不受上述 AI 偏好開關剔除；仍須有庫存且合法。 |

多標籤、任一禁用即排除整瓶，不把複合藥劑拆成部分效果：

- `inflict_dmg` 腐蝕反噬藥劑屬附加異常，但有 100 直接藥劑傷害。關閉傷害時也必須排除。
- `atk_backlash_dmg` 反噬引爆藥劑同時含直接傷害與干擾，關閉其中任一相應選項即排除。
- 中毒後續的狀態傷害歸附加異常規則；不要混同為 `potion_damage` 直接傷害，也不改任何技能或傷害公式。
- 淨化藥劑、解弱化藥劑、幻化指令、山神護符與特殊藥草保留。特殊道具優先豁免 AI 類型偏好，因此特殊效果內若帶攻擊能力，也不會因這三個偏好被一刀切；遊戲本身禁藥、庫存等限制仍有效。

`actionPolicy.ts` 只處理 AI 候選，不改 `legalActions` 的遊戲規則。必須覆蓋 Worker、快速評估、模型輸入清單、模型返回、引擎接納及 `src/utils/ai.ts` 的 catch 回退。敵方回應推演使用對應側設定，不能沿用出手方限制。若排除後沒有選擇，依序採仍允許的其他合法行動／等待，不能偷偷重新打開禁用藥劑。

保留候選不代表保證懂得使用：目前 `illusionPlanning.ts` 已針對指定幻化作長期估值，清除異常／弱化也有評分。複雜特殊道具仍須用實際場景驗收，不能把開關正確當作戰術能力已提升。

## 設定介面及檔案分工（尚未實作）

- 「本地對戰 AI」保留現有難度、風格、風險及預算。
- 新增「模型輔助」區：預設關閉、Google 連線與金鑰狀態、連線測試、等待上限、比較建議／輔助選擇、最近用量與採用／回退原因。關閉時保證不發網路請求。
- 「AI 藥劑使用」三個允許開關全開，預設雙方跟隨共用設定；可按側覆寫。文字註明特殊與解除用途保留、人工使用不受影響。
- 金鑰設定與模型啟用分開：儲存金鑰不等於啟用呼叫；金鑰、連線狀態不寫進通用 AI 設定匯出。

建議新增的職責單一檔案：

```text
src/battle/ai/actionPolicy.ts           AI 藥劑與候選限制
src/battle/ai/decisionContext.ts        欄位白名單、候選 ID、版本快照
src/battle/ai/assistedClient.ts         本地推演與模型協調、取消、回退
src/components/BattleAIProviderPanel.tsx
server/battleAI/routes.ts              本機驗證、狀態／儲存／刪除／測試／決策

server/battleAI/secretStore.ts          記憶體／DPAPI 憑證儲存抽象
server/battleAI/localAccess.ts         Host、Origin、會話與本機防護
```

對戰主流程僅沿既有 `selectAi` 依賴注入及共用驗證接入，不放供應商 HTTP、金鑰處理或精靈名稱判斷。一般匯出／安裝包只包含空白設定與範例欄位。

## 實作與驗證順序

1. 先完成藥劑政策、設定預設／存檔遷移及所有回退路徑測試；確認人工合法操作和特殊藥劑不受影響。
2. 加入隔離憑證服務、存取防護與供應商回應 mock；驗證跨站／LAN 拒絕、匯出及產物不含金鑰、關閉零網路。
3. 接上比較建議模式，使用者主動測試連線才進行首次實際請求；核對帳戶可用性、用量、失敗回退和延遲。
4. 相同隊伍與成對種子、交換 P1／P2，比較本地基線與輔助模式。驗證解除控制、解弱化、指定幻化、封藥、禁用混合藥劑、強制換場、隱匿、超時與換人後舊回應作廢。
5. 記錄合法率、禁用道具違規率、勝負／平局、回合數、延遲、用量與回退率；報告統計不確定性，不用單場勝利或高 confidence 宣稱變強。保留未參與調參的測試場景。
6. 輔助採用通過驗證後，才納入正式桌面建置與更新；模型整體開關維持預設關閉，藥劑允許開關維持預設全開。

本輪交付只有這份研究設計及忽略目錄內的官方文件研究暫存。既有桌面啟用版本與目前戰鬥程式保持原樣；API 金鑰有效性、模型實際延遲及勝率收益均待實測。
