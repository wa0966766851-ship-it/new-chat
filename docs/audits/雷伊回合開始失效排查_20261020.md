# 雷伊回合開始複製強化失效 — 排查報告（DSH 2026-10-20 01:45）

## 已確認的根因（附證據）

### 問題 1：第 1 回合的 ROUND_START 完全沒有派發（已定位，未修）

`battleEngine.ts` 的 `resolveTurn()`（L2134）第一行是 `if (cur.phase !== "resolving") return;`，
而戰鬥開局（`start()`，L3822-3846）只派發 `BATTLE_START` + `ON_ENTRANCE`，**沒有派發 `ROUND_START`**。

實測（真實 Battle 掛載，雷伊 vs 帶 def:2/atk:1 的對手）：
- 第 1 回合：雷伊 statStages = {} （空）
- 第 2 回合：雷伊 statStages = {atk:1, def:2} （正確複製）

→ 雷伊「回合開始時複製強化」**晚了一整個回合**才生效。所有依賴第 1 回合 ROUND_START 的效果
（次元龍詩章累積、克塔亞特漸凍、各類回合開始被動）同樣受影響。

### 曾嘗試的修法與失敗原因

在 `start()` 末尾補派 ROUND_START → 雷伊第 1 回合即生效 ✅，但導致：
- `deathSwitchCatchUp`：「漸凍1」被提前 tick 成「冰封3」，違反使用者 2026-10-10 裁定
  「死切上場附加的異常不在回合開始補扣」
- `hamoShiyanIntegration`：狀態時序整體前移，多條斷言失效

→ 已完整回滾。**正確修法需要「只派發魂印的 ROUND_START、不觸發狀態 tick」**，
  需要先釐清 ROUND_START 與狀態持續回合扣減的耦合點，屬於架構級改動。

### 問題 2：額外精靈（克塔亞特）的專屬 Kit 沒有掛上（已定位，未修完）

`createExtraElf()`（src/utils/extraElf.ts）刻意不繼承召喚者 Kit（正確設計，避免詳情面板顯示召喚者全套）。
因此額外精靈 `kit` 為 undefined，其條款永不執行。

實測證據：
- 克塔亞特加入 P2 隊伍：`克塔亞特(extra=true)` ✅
- 但 `kit: undefined`、`soulMark.kit: undefined` ❌
- 結果：X 沒有獲得「漸凍1」

### 已完成的基礎設施（保留，有價值）

1. **新增 `ally_entered` 節點**（隊友登場）——原本積木層無法表達「己方精靈每次出戰時」，
   只有 `on_entered`（自己登場）與 `opponent_entered`（對手換人）。
2. `broadcastElfEntered()` 接入 `ally_entered` 節點派發（帶 try/catch，不影響既有流程）。
3. `registerExtraElfKit()` 註冊表機制（數據層註冊、op 按名查找）。
4. 克塔亞特三條款抽出為 `CTHYAAT_CLAUSES`（ally_entered / battle_phase_end / self_fatal）。

### 未解決的技術障礙

`summon_extra_elf` 執行時 `EXTRA_ELF_KITS.size === 0`——數據層的模組級 `registerExtraElfKit()`
在 op 執行前尚未完成（vite SSR 模組實例隔離）。需要改用「引擎開局統一掃描 Kit 資料」
或「在 createExtraElf 時從 DEFAULT_ELVES 反查」的方案。
