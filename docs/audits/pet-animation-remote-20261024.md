# 動畫遠端來源與空間盤點

日期：2026-10-24。只盤點動畫資源，不包含整個U端遊戲。

## 來源確認

- [上游播放器 README](https://github.com/Nattsu39/seer-pet-viewer)：說明官方Bundle來源、瀏覽器跨域限制、較大檔案鏡像方式。
- [上游代理程式](https://github.com/Nattsu39/seer-pet-viewer/blob/main/edge-functions/proxy/%5Bhash%5D.js)：提供官方來源路徑。本專案使用自己的同源後端連官方，沒有借用第三方代理服務。
- [公開動畫索引](https://pet-anim-viewer.seerapi.com/pet-anim-index.json)：本次取得version `20261022142543`、updatedAt `2026-10-23T03:58:53.041Z`。6231個動畫條目＋11個共用包，6242個唯一hash。
- 已對官方HTTPS來源實際GET兩個已支援檔案，回應200，與使用者本機U端素材的SHA-256完全相同。官方網址以白名單hash組合，詳見 `server/petAnimationCache.ts`。

索引包含不同格式與變體，不能把6231直接稱為不同精靈數。這是目前索引大小，未來新增資源會變化。計算沒有把依賴包對每隻精靈重複加總。

一般電腦容納目前0.56 MiB素材或512 MiB限額快取通常沒有空間壓力；全庫約11.3 GiB則應採使用者主動下載，不作預設。本次沒有下載全庫。

## 記憶體與流暢度

磁碟大小不等於播放記憶體。雷伊圖集為2048×1024，按RGBA8解碼的單份像素約8 MiB，還有CPU mesh、Worker與顯示卡材質。雙側播放器可能各持一份GPU材質，不能由582942 bytes宣稱總記憶體僅0.56 MiB。這些是尺寸推估，不是實測整個程式記憶體峰值。

目前同場解析同一素材只做一次、最後使用者離場會釋放clip；只載入實際使用的皮膚。仍以兩側顯示為上限驗收，不預先解析全索引。首次下載與解析期間使用既有外觀，不凍結戰鬥輸入；新播放器待機邊界才接入。

## 實測

1. 臨時建立完全沒有U端設定的專案根目錄，預設使用者下載快取起始0 bytes。
2. 同源API並行請求rey70與materials，從官方取得並驗證，合計582942 bytes；本次3209ms完成。
3. 重建服務並設定 `remote:false`，從磁碟快取讀回兩份檔案，200且SHA相同；本次13ms。這是本機觀察，不是網路速度保證。
4. 證據：`.seer-cache/remote-download-proof.json`。
5. 自動化測試涵蓋同素材去重、重啟離線、同大小損毀、截斷、超量、下載逾時、失敗冷卻、LRU上限、其他檔案保留及白名單路由。
6. 正式對戰瀏覽器驗收另用不存在的U端來源與空的獨立下載快取，確認起始rey70=false、bytes=0，再實際完成雙側三類動作、命中出傷、模式切換及三隻指定皮膚實戰；未使用本機U端備援。證據位於 `.seer-cache/remote-animation-shots/`。

目前只開放已驗證的普通雷伊素材與共用材質。找到其他動畫的遠端位址不等於已實裝，新增精靈仍須完成皮膚綁定、格式／依賴、尺寸、朝向、命中與收招驗收。
