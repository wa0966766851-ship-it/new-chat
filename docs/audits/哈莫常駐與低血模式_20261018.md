# 哈莫常駐與低血模式：積木修復及整合驗收

本輪修復魂印「鱗」的常駐條款，保留完整原文；沒有據此將全部397份定義或所有技能判為完成。

## 已補執行端

- 使用既有 `flag_set` 與 `player_state` 表達低血模式。每次登場回復正常模式，每回合開始檢查「自身當前HP同時低於對手、且低於自身半血」，本回合固定使用此次結果。回合中掉血／回血越線不偷換模式，下一回合再取樣。
- 正常模式經 `before_status_apply` 的 `status_guard` 免疫異常；低血模式改由 `before_damage` 的可編輯 `damage_cap_now` 限制技能傷害250。常駐上限不建立會被消回合類移除的技能計時器，也不擴張到固定、百分比或真實傷害。
- 新增通用 `missing_hp_scaled_boost`：當次造成指定分類傷害前，以當時失血每10%逐次乘1.1放大基礎150%增幅。原先在傷害節點新建1回合增傷計時器的延遲生效寫法已移除。
- 新增通用 `missing_hp_scaled_heal`：回合末以當時最大HP15%為基礎、每失血10%逐次乘1.1。每次獨立取樣，透過正式恢復入口接受禁療／恢復修正與HP封頂；不冒充重置體力。
- 新操作位於 `src/blocks/ops/missingHpScaling.ts`，嚴格合約限制入口、分類、步長、倍率與基礎值；不按精靈名稱分流。名稱、步長、倍率、基礎增幅、回血比例都可修改。

## 整份魂印交互缺陷

新增五回合整份魂印測試後，發現舊 `mark_lock_turns` 三種資源都使用同名計時器識別碼，互相覆蓋。現在識別碼包含來源類別、技能來源（若有）、持有者與資源ID；魂印刷新不再依當時選中技能建立不同鎖。技能與常駐鎖也不互相覆蓋清除屬性。此為通用修正，沒有放進精靈專屬引擎分支。

## 驗收

`tests/hamoPassiveMode.semantic.test.ts`／`test:hamo-passive-mode` 使用真實來源五個常駐入口，P1/P2驗證正常／低血、恰好半血、與對手等血、回合中越線、回血後下一回合恢復正常、首發當次增幅、10%臨界前後、正式公式攻擊與附加屬性傷害、固定／百分比／真傷隔離、回血封頂及禁療、改名改參數。

另使用完整來源魂印連續五回合測水火草染色、能力下降免疫、紅鱗免疫、PP清除、白鱗耗盡、三色同時受到保護，以及期限到後同回合真正消耗三色；驗證綠鱗消失副作用逐次降低敵方上限（100000→80000→64000）。舊 `hamoScales` 私有狀態沒有被重新寫入。全部來源Kit入口合約通過，整份魂印Blockly建立／儲存／讀回深比較通過。

最終定向測試exit0；型別檢查exit0；生產建置exit0（2547模組，48.66秒）；三份Kit封裝完整原文／參數深比較通過。未開前台或人工實戰；無推送發布EXE。
