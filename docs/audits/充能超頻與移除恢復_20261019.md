# 充能超頻、第五切換與哈莫移除恢復

## 馬爾修斯：恢復行為斷言

`marsCharge.semantic.test.ts` 原受方由施放者複製，連同已切 Kit 的魂印也一起帶入。這既讓受方自行恢復體力，也使依名稱掛入的傷害觀察器被正式魂印 Kit 路徑隔離。受方改為明確的無魂印對照後，原本的結算隊列能產生真傷扣血，並非已證明 queue flush 故障。

恢復的正式斷言要求 P1/P2 兩回合後：真傷回執 `hpLost=60`、受方體力 2000→1940、充能4→0、PP20不變。沒有用充能歸零或參數存在代替扣血。

另修正 `charge_consume_all_to_damage` 的三個實作缺陷：

- 依 `skillSlot` 精確消耗本次原槽；不再挑最高充能，也不會清掉所有同名槽。屬性技能不能消耗其他槽。
- `queueHpDrain` 已負責恢復，移除外層再次恢復，防止60傷害回120血。
- 原增傷呼叫讀取不存在的 `ctx.runAct`，已明確委派共用執行器，使用一回合的非技能回合計數增傷。

`mechChargeSettlement.semantic.test.ts` 已通過雙側正式扣血回執、單次回血、同名第二槽、PP隔離、150%主攻擊增傷及下回合到期。

## 第五技能與機甲切換

原前置條款節點 `before_skill` 搭配 `self_skill` 不相符，並且沒有第五條件；兩次循序切換也可能切回原組合。改為：

1. 正式選招事件記錄是否選第五，僅第五選擇時汲取。
2. 第五使用後採互斥分支切換一次。
3. 原文沒有要求第五必須命中或成功，失敗收尾亦切換一次；只有實際 `skill_invalid` 記錄第五無效。
4. 階段末只有未選第五或第五實際無效時準備超頻。

新增通用 `skill_fifth` 條件，透過技能欄位讀取，不判斷精靈或技能名稱。`mechModeTiming.semantic.test.ts` 已通過雙側選招汲取、使用前後模式、成功／無效收尾與階段末條件，以及 Blockly 保存重載。未把這些局部驗收當整份「械」魂印完整驗收。

## 哈莫：被清除內容的正式快照

三招用攜帶監控捕捉出手前後清除事件，所選技能的固有前置條件須持有對應色鱗才啟用。移除無讀取端的 `hamoRestoreRound` 寫入。`contextBuilders` 僅在既有通用事件增加移除前鏡像欄位值，不增加精靈判斷。
