### 後續使用

在專案根目錄執行：

```powershell
# 只看候選清單
node scripts/archive_retired_desktop.mjs
# 實際封存並清除已驗證的舊展開版本
node scripts/archive_retired_desktop.mjs --apply
# 還原到 build/restored-desktop/1793182625932，不覆寫目前版
node scripts/archive_retired_desktop.mjs --restore 1793182625932
```

腳本保留目前版、上一版與最近三版，避開近 48 小時有修改、仍被程序使用、有連結或被 Git 管理的版本；發現桌面更新鎖或目前版變動便停止。封存位於 `.local-archives/desktop-content`，**objects 與 manifests 必須一同保留**。還原命令只解開舊程式，不應拿來還原玩家存檔。

| 目錄 | 應負責的內容 |

目前不宜大搬 `src`：會同時影響匯入路徑、製作工具與其他進行中的工作。先固定上述責任，比為了整齊而搬檔可靠。

根目錄有許多未追蹤的 `_*.mjs`、`.tmp-*`、`arena-test` 實驗、近期動畫圖。它們不能只因未追蹤或名稱像暫存就刪除，部分仍是當前製作來源。下一步應先將「已採用工具／一次性實驗／原始素材／驗收證據」列冊，再把已結束實驗連同說明封存；目前不自動移動。

## 打包後看似覆蓋存檔的原因

### 已確認

1. 瀏覽器原有存檔依網址隔離。`localhost:3000`、`localhost:3011` 與 `127.0.0.1:3000` 是不同存檔空間。啟動器遇到埠被佔用會換埠，因此可能看起來回到初始狀態，舊檔其實仍在另一個網址下。
2. `launcher.ps1` 找到既有服務後有記錄 `foundPort`，但開視窗時沒有採用；已改為使用找到的服務網址。
3. Electron 與 Edge 桌面模式使用不同瀏覽器資料夾；它們原先沒有共同存檔來源。不能假設換入口會自動看見另一份資料。
4. 程式會升級內建精靈與背包資料。它與「整份玩家資料被安裝包刪除」是兩件事；既有修復測試通過，但本次未實際讀取玩家資料，不能宣稱歷來所有覆蓋問題都只有埠號一個原因。

### 本次新增保護

- `server/playerSaves.ts`：將 `seer_` 前綴的遊戲 localStorage 資料另存成獨立 JSON；不收其他前綴資料。
- `src/utils/playerSaveBridge.ts`：先讀回桌面存檔，再初始化畫面與既有資料升級，避免預設值先寫入。
- 瀏覽器桌面入口保存於 `%LOCALAPPDATA%\SeerBattleSim\player-saves\browser`。
- Electron 保存於 `app.getPath('userData')\player-saves`，沿用既有 Electron 使用者資料目錄；不放在 EXE、dist 或桌面版本目錄。
- 每次更新前保留前一份原始 JSON，再以暫存檔替換目前檔；舊版本號拒絕寫入，多程序由獨占鎖保護。
- 損壞、空間不足、兩份未建立關係的舊資料互相衝突時，停止同步並顯示提示，不靜默清空。

### 實際限制與維護

- 目前瀏覽器與 Electron 的磁碟存檔各自保留，**沒有自動混合兩個入口的隊伍與自製精靈**。要跨入口搬家仍應匯出／匯入，先決定哪份為主。
- 同步每 1.5 秒檢查一次，切到背景也嘗試寫入。突然斷電／強制結束仍可能來不及保存最後一次操作；原網址的瀏覽器資料仍是另一份副本。
- 程序在持有 `write.lock` 時異常死亡，鎖會保留並阻止後續寫入；應在確認沒有存檔程序執行、且先備份整個存檔資料夾後，才處理遺留鎖，不自動猜測並刪除。
- 歷史 JSON 目前不自動刪除；日後應增加按變更合併、每日保留點與容量提示，避免把存檔歷史變成另一個無限增長來源。
- 新保護只能從啟用後建立副本；不能憑空找回已被真正刪除、且沒有任何備份的資料。
- 將存檔加入資料夾排除規則，安裝、打包與清理工具均不得刪除使用者資料目錄。
