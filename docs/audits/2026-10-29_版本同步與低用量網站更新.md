## 低用量發布方案

專案已有 `.github/workflows/build-web-package.yml`（Build website package without AI），手動選擇正確工作分支並設定 publish=true。它負責安裝、檢查、測試、編譯、產物保存及發布；不用 AI 重新生成網站。發布後須比對線上 version.json 的 commit、version、buildId，不能只看流程成功或 Sites 外殼版本。

GitHub 路徑：Actions → Build website package without AI → Run workflow → 選擇工作分支 → publish=true。不要選擇仍然落後的 main。

一般 Chat 與 Work 不能視為同一能力：官方說明把 Sites 等多步驟工作歸於 Work。可在 Chat 討論／準備指令，但只有該模式實際提供啟動發布的工具才能代操作。可用最低必要的 Work 設定啟動現有流程，或使用者直接按 GitHub Run workflow。這能減少 AI 操作量，但沒有據此量測或保證帳戶配額／費用下降比例。

官方參考：
- https://learn.chatgpt.com/docs/web
- https://learn.chatgpt.com/docs/sites/creating-a-site
