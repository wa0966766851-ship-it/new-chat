## 1. 攻擊傷害（物理／特殊）— 主公式

### 1.1 入口
- 出手流程 3.5–3.6：BE:2838（`category !== "屬性" && power`），`calculateDamage` 呼叫於 BE:2882–2901。
- 連擊：hitCount＝`attackHitCountThisAction`＋`attackBonusHitCountThisAction`（BE:2839–2840），一次公式×次數（DC:180,185），單次動畫；每擊判定 `AFTER_ATTACK_HIT` 迴圈 BE:3177–3182（傷害只記在 hitIndex 0）。符合「連擊＝一次公式×次數」。

### 1.2 `calculateDamage`（DC:14–200）順序
1. 屬性技能或無威力 → 0（DC:33）。
2. 攻擊值：物理取 atk、特殊取 spatk（DC:39）；`blkAtkSpatkSum` 改為 atk+spatk（DC:41–42）；`calcAtkDefMult` 乘雙方攻／防（DC:49–50）；`opponentAtkPanelRatio` 以面板×比例**覆寫**攻擊（DC:51，並令 atkS=0，DC:114）。
3. 防禦值：物防／特防（DC:43）；核能機甲且受擊方 HP<1/3 → def×2（DC:53–55）。
4. 無視防禦%：取 max（特質 ignoreDefPercent、ignoreSpDefPercent（僅特殊）、ignoreSpDefPercentUntilSwitch（僅特殊）、ignoreDefPercent、套裝 ignoreDefSpdefPercent）（DC:57–73）→ `def=max(1,floor(def×(1−p)))`（DC:74–76）；套裝固定減防（DC:78–80）。
5. 能力等級：`skillStageView`（DC:82–83）→ 視為下降／詩章／oppBoostAsDrop／ignoreOppBuff／selfDropAsOppDrop（DC:92–112）。
6. **特殊公式替換**（DC:115–116，`specialDamageFormula`，specialDamageFormulaRegistry.ts:7–16）：無序·蝕言在對方隊伍存活時，特殊攻擊＝`floor(最終特攻×(1−擁有者最終特防/100))`，**不吃本系、克制、浮動、暴擊、套裝／稱號／刻印**，`isCrit` 恆 false，×hitCount 後直接 return。
7. `blkStageAsBoost`（DC:119）、`powerMultiplierThisAction`（DC:120）。
8. 弱點傷害 `weakPointDefenseTurns`：防＝min(本防, 另一防)×比例（預設0.6）（DC:125–132）。
9. 基礎：`base = (等級×0.4+2)×有效攻×威力×powerMult/max(1,有效防)/50 + 2`（DC:123,133，**不中途取整**；有效攻／防已在 `calculateEffectiveStat` 取整，statCalculator.ts:41–44）。
10. 克制 `skillTypeMultiplier`（skillTypeOverride.ts:4–14：typeMultiplierUntilSwitch → fixedTypeMultThisAction → blkTypeOverride 取最高 → 一般克制；noResistedThisAction 時 <1 視為 1）；`attackTypeOverride`/`targetTypeOverride`/`targetTypeThisAction`（DC:137–139）；`minimumTypeMultiplierThisAction` 下限（DC:140）。
11. 本系 1.5：grantStabThisAction／投石者+寶石技能／技能任一屬性含於自身系別（DC:143–145）。
12. 浮動 roll＝round(rv×255) 夾在 217–255（DC:147）。
13. 暴擊率＝critValue/16＋套裝＋稱號＋特性（會心+0.2／免爆−0.2，traitEffects.ts:61–66）＋積木 critChanceBonus，夾 0–1；PRD 判定（DC:162–163）。
14. 暴擊倍率＝`2×(1−致命抗性/100)`，套裝 critDamageMultiplier 再乘（DC:174–179）。
15. 取整鏈（DC:181–185）：
   `final = floor(base×STAB×type)` → `floor(final×roll/255)` → 暴擊 `floor(final×critMult)` → 依序 `floor(×套裝造成倍率)`、`floor(×稱號造成倍率)`、`floor(×對方套裝受傷倍率)`、`floor(×刻印強化1.2)`（僅 ≠1 時）→ `floor(×skillStoneDamageMultiplier) × hitCount`。
16. 暴擊時若對手防禦等級 >0，回傳 statResetApplied（DC:187–191；BE:2912–2918 歸零）。

### 1.3 引擎 5 段 damageComp（BE:2925–3060）

11. 武誅類印記：attackTakenMultAboveHalfHp／attackDealtMultBelowHalfHp（BE:3009–3022）。
12. `preventAttackDamage` → multiplier=0（BE:3025，**pure 也會被歸零**）。
13. `dmgDoubleTurns` ×2、受擊方 `damageTakenBoostTurns`/`DamageBoostTurns` ×2、`skillDamageBoost` ×k（一次性）（BE:3026–3036）。
14. `finalizeDamageReductions`：執行 `beforeFinalDamage` 鉤子＋門檻減傷 thresholdDamageReduction（DR:152–170）BE:3038。

最終運算（BE:3039–3060）：
```
stage1 = base × (1 + increasePercent) × max(0, 1 − decreasePercent)
stage2 = max(0, stage1 × multiplier − flatReduction)
limit  = min(comp.limit[除非 attackDefenseBypass.limit], 200[若 damageLimit200Turns], incomingSkillDmgCap[除非 bypass.limit])
        → 若 blkIgnoreLimit / ignoreDamageLimitThisAction：limit = ∞
stage3 = min(stage2, limit)
stage3_5 = stage3 + bonusFixed
final = floor(floor有值 ? max(stage3_5, floor) : max(0, stage3_5))
final = min(final, outgoingLimit)
mercyThisAction → final = min(final, 對手當前HP − 1)
```
減傷合成：`addDamageReduction` 以 1−(1−a)(1−b) 疊加（DR:118–134）；`multiplyDamageReduction` 把減傷寫進 multiplier（DR:136–140）；兩者都經 `effectiveReduction`：真實或 pure 時=0、`damageReductionOverridePercent` 覆寫、`reduceDmgEffectToZero`／千秋一淚衰減（DR:99–116）。

## 12. 不一致與疑似錯誤

### 確認
- **B1 致命抗性雙重套用**：DC:174–176 已把暴擊倍率改為 2×(1−抗性)，BE:421–423 落地時又對 `data.isCrit` 乘 (1−抗性)。實測 35% 抗性：應 378–444，實際 248–280（=×1.3×0.65）。只影響主攻擊（唯一帶 isCrit 的推送，BE:3097）。
- **B2 `ignoreDefPercent` 也削特防**：DC:65–67 只在物理時套用，DC:68–70 又無條件套用一次，所以特殊攻擊也會被削。實測：特殊攻擊帶 ignoreDefPercent 0.25 → 454（無：342）。來源包括 `ignoreDef25Turns`、藏品 `relicIgnoreDefPercent`（BE:2865–2869）。
- **B3 主攻擊的印記倍率在 limit／floor／mercy 之後**：主攻擊推送時沒有 `marksApplied`（BE:3097），所以 nonTrueDamageTaken/DealtMultiplier 會在落地段 BE:446–471 才套用。效果 API 則在 limit 之前套用（CB:146–176）。結果：倍率 >1 時可以超過 `incomingSkillDmgCap`／`limit`，也能打破手下留情（HP−1）；倍率 <1 時會壓低 floor 保底。
- **B4 死亡守護對技能傷害的範圍不一致**：在場分支只擋 `skill`／`skill_attack`／空字串（BE:409），`skill_attribute`（X系）和 `skill_extra_action` 擋不到。場下分支卻用 `startsWith('skill')` 全擋（BE:363），而且不看 attackDefenseBypass.block。
- **B5 場下目標分支缺很多步驟**（BE:357–391）：沒有暴擊抗性、印記、回神／頑強（`traitFatalResist`）、HP 上限快照、turnStats、TRACK_DAMAGE、OPPONENT_DAMAGE、TRUE_DAMAGE_TAKEN、攻方 AFTER_DAMAGE。另外 `FATAL_RESIST` 的 payload 是正規化後的 category，在場分支卻傳原始 `data.damageType`（BE:377 對 BE:530）。
- **B6 `OPPONENT_DAMAGE` 不檢查來源**（BE:785–787）：對面在場精靈收到所有傷害事件，包括目標自傷、DAMAGE_TICK、流失和無來源直推。`consumeSkillTypeOverride` 那段反而有檢查來源（BE:780）。
- **B7 DAMAGE_TICK 的來源是受害者自己**（BE:1279–1280）：`sourceElfName`＝受害者，所以 `TRACK_DAMAGE` 記在受害者名下（BE:802）。runDamageHooks 對同一隻精靈呼叫兩次 BEFORE_DAMAGE（isIncoming false 和 true，CB:94–110）。閘門的 damageIncreasePercent（owner===actorSide）也會加到受害者自己的 DoT 上（damageGates.ts:245–247）。
- **B8 黯痕對固定／百分比的減半只在兩個 API 有**：`applyFixedDamage`／`applyPercentDamage` 有 ×0.5（CB:369, 455），`applyPinkDamage` 的 fixed/percent 沒有（積木百分比 runtime.ts:174、hpDrain 吸取、多數魂印都走 pink）。另外這裡直接乘 0.5，不經 `multiplyDamageReduction`／reductionPolicy。darkScarRegistry.ts:36–69 的 `applyDarkScarSkillCap`／`darkScarDealtMultiplier`／`darkScarTakenMultiplier` 只有測試在用，引擎沒有引用；「受擊翻倍 takenDouble」在引擎找不到實作。
- **B9 `bonusFixed` 和 `floor` 在 multiplier 歸零後仍然生效**：BE:3025（preventAttackDamage）、traitEffects.ts:101（虛無／抵擋）把 multiplier 設 0，但 BE:3053–3054 之後還會加 bonusFixed（強攻 +80、takePhysSpecDmgBonusFixed），也會套 floor。bonusFixed 也不受 limit 約束。

### 疑似
- **S1 吸血以落地前的 finalDamage 計算**（BE:3173、CB:288），不是 receipt.settledAmount（抗性、印記後；BE:716）。依「以結算值」規則，可能應在落地後取 settledAmount。特性「吸血」11% 同樣取 finalDamage（traitEffects.ts:125）。`afterSkillHit` 整體在傷害落地前執行（BE:3098），瞬殺讀的是落地前 HP。
- **S2 真實傷害仍受 `limit`／`floor`／`outgoingLimit` 影響**（CB:317–318）：BEFORE_DAMAGE 鉤子若沒篩類別就設 limit，真傷也會被封頂。`safeMultiplier=max(1,…)` 會吃掉「增傷×減傷」混合後 <1 的結果（例如 1.5×0.5 → 1）。
- **S3 星光永恆「忽略雙攻 11%」**直接寫 `multiplier *= 0.89`，不分類別，也不經 reductionPolicy（suitEffectRegistry.ts:391–393），固定／百分比也會被減。核能機甲註解寫「等同於傷害值15%」，實作卻是對手 maxHp×15%（suitEffectRegistry.ts:78–83）。
- **S4 套裝目錄反射和稱號固傷是直推**（BE:3116, 3125）：不經 API，所以沒有 BEFORE_DAMAGE、異常倍率、閘門、fixedPercentAsTrue；反射以攻擊 finalDamage（護盾前）為基準。
- **S5 刻印「強化」（liuren_qianghua）**的說明是「所有屬性提升」（defaultElves.ts:1812），計算器卻額外給 ×1.2 傷害（DC:169–172）。它和異能特質「強化」+20%（traitEffects.ts:88）同名，可能是重複加成或誤植。
- **S6 effect API 的攻方「造成非真實傷害倍率」不排除自傷**（CB:146, 234, 352, 438）。落地段的 fallback 則固定把攻方當成受擊方對面（BE:460）。marks.ts:22 註解寫 nonTrueDamageDealt 含「真實」，與實作（排除真傷）不符。
- **S7 抗性比對 `data.damageType === 'fixed'/'percent'` 用原始字串**（BE:424, 427），沒用正規化值。目前推送端都會先正規化，但未來直推 `fixed_damage`／`百分比傷害` 會漏抗性。
- **S8 `TRUE_DAMAGE_TAKEN`** 用分支開頭的 `cur` 快照走訪隊伍，dmg=0 也會觸發（BE:789–798）。
- **S9 特殊公式（蝕言）**不吃克制、本系、暴擊、浮動、套裝（specialDamageFormulaRegistry.ts:8–15；DC:115–116），需確認是否符合原文。
- **S10 `applyPercentDamage` 以在場目標的 maxHp 為基準**（CB:333–334），走 fixedPercentAsTrue 轉真傷時 label 會遺失（CB:335）。

補充：
- `resolveHpAdjustment` 註解寫「不吃增減療、不受體力上限限制」（survivalRules.ts:107-110）。所以體力調整可以讓 currentHp > maxHp，reducer 也不夾（BattleManager.ts:136-170）。
- `damageChainFinalizers` 的 HP 變化一律標 `type: 'adjust_up'`，扣血也一樣（battleEngine.ts:1050-1055）。
- UI 標籤：BattleScreen.ui.tsx:378-379（adjust_up/down 都顯示「🔄體力調整」）。
- 增減傷分類 `non_true` 排除體力調整：damageChoices.ts:22-25；`adjust_hp` 本身不經任何增減傷，這點一致。
- 積木系統：沒有通用的「體力調整」op。只有 `consume_hp_all`（runtime.ts:554，走 adjustHp）和魂殤 metadata `hpAdjustmentMaxHpRatioPerStack`（runtime.ts:899-905，只對在場持有者）。`damageChoices` 會推斷 `hp_adjust`（:25），但 `dealDamage0` 不認得這個類型，未知類型一律當百分比傷害處理（runtime.ts:167-175）。
