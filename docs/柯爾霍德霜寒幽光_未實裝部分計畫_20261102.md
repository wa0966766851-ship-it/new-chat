### ① 的實作細節

```ts
damage_reduce_by_resource: (ctx, p, st) => {
  const comp = st.event?.data?.damageComp || st.event?.data;
  if (!comp?.isIncoming) return false;
  if (!['fixed', 'percent'].includes(String(comp.damageCategory))) return false;
  const marks = ctx.getMarks(ctx.targetSide) || [];
  const points = Math.max(0, Number(marks.find(m => m.id === p.id)?.count) || 0);
  const step = points * p.thresholdRatio;   // 霜寒幽光值 10%
  comp.beforeFinalDamage.push(() => {
    const base = ...;                        // 完整增減傷後的傷害
    if (base <= step) return;
    const times = Math.max(1, Math.floor(base / step));   // m 次
    comp.multiplier *= Math.pow(p.multiplier, times);
  });
}
```

**驗證方式**：柯爾霍德受固定傷害，對手身上霜寒幽光 = 500 → 門檻 50；
打 500 傷害 → m = 10 → 連續減半 10 次 → 最終 ≈ 0.49（幾乎免疫）。

## 二、待實作（②③④⑤）

### ② 持有者在場時吸取己方隨機1個不在場精靈所有技能1點PP值

**原文拆解**：
- 觸發：霜寒幽光的持有者（＝對手）在場時
- 目標：該持有者**己方**（即對手方）隨機 1 個**不在場**精靈
- 效果：該精靈所有技能 PP 各 −1
- 柯爾霍德在場時：這 1 點 PP 恢復到柯爾霍德身上（相同技能位）

**現有工具不足**：
- `applyKitPpOperation` 只能處理「在場精靈」（`current()` 取 `ctx.activeP1/activeP2`）
- `pp_op` 沒有 `scope` 參數

**實作方案**：

新增 op `bench_pp_drain_random`：

```ts
bench_pp_drain_random: (ctx, p) => {
  const side = sideOf(ctx, p.side);              // 'opp' = 對手方
  const team = ctx.getFullTeam(side) || [];
  const bench = team.filter(e =>
    !e.isVanished && !e.isExtra &&
    idOf(e) !== idOf(side === 'p1' ? ctx.activeP1 : ctx.activeP2) &&
    (e.skills || []).some(s => s.pp > 0));
  if (!bench.length) return false;
  const pick = bench[Math.floor((ctx.rng?.() ?? Math.random()) * bench.length)];
  // 各技能 -1
  const nextSkills = pick.skills.map(s => ({ ...s, pp: Math.max(0, s.pp - 1) }));
  ctx.updateAnyElf(side, idOf(pick), { skills: nextSkills });
  // 柯爾霍德在場時恢復相同位置
  if (p.restoreToHolder && selfIsOnField(ctx, '柯爾霍德')) {
    const self = ctx.self;
    ctx.updateAnyElf(ctx.actor, idOf(self), {
      skills: self.skills.map((s, i) => ({ ...s, pp: Math.min(getMaxPp(s, self), s.pp + 1) })),
    });
  }
  return true;
}
```

**參數合約**：`['side', 'restoreToHolder']`

**驗證**：對手有 3 隻背包精靈、各技能 PP 5/5 → 觸發後隨機一隻變 4/4。

### ④ 下場後將霜寒幽光減半附加給下隻出戰精靈

**原文**：霜寒幽光的持有者（對手）下場時，把當前霜寒幽光值的一半，附加給「下隻出戰精靈」（對手方的下一隻）。

**現有工具**：
- `defer_shield_to_next` 只能傳護盾，不能傳印記
- 有 `on_next_switch_in` 可以排「下一隻登場時執行」

**實作方案**：

在 Kit 加 `on_switch_out` 節點，用 `resource_mark_subtract` + `on_next_switch_in`：

```ts
entry('on_switch_out', 'switch_out', '霜寒幽光：持有者下場時減半附加給下隻出戰精靈', [
  { cond: [c('mark_count', { side: 'opp', id: 'frost_glow', op: '不小於', amount: 1 }, '對手持有霜寒幽光')], acts: [
    // 讀當前值、減半、清除
    a('resource_mark_transfer_next', { id: 'frost_glow', ratio: 0.5, side: 'opp' }),
  ] },
], 10),
```

**需要新 op** `resource_mark_transfer_next`：
- 讀 `side` 方在場精靈的 `id` 印記 `count`
- `Math.floor(count * ratio)` 寫入 `nextElfFrostGlow`（player state）
- 清掉原印記
- 下一隻登場時（`ON_ENTRANCE`）讀 `nextElfFrostGlow` 寫回

**驗證**：霜寒幽光 200 → 持有者下場 → 下一隻上場時 100。

### ⑤ 同時令該精靈在場前 n 回合無法主動切換精靈（n = 霜寒幽光值/50）

**原文**：接續 ④，「該精靈」＝接棒的那隻。前 n 回合不能主動切換，n = 霜寒幽光值/50（用**減半後**的值）。

**現有工具**：`no_switch` / `addBlockTimer` 有 `lockSwitch` 標記，`onSwitchElf` 已有 `activeConstraints(timers, ...).some(p => p.lockSwitch === true)` 檢查。

**實作方案**：

接在 ④ 的 `on_next_switch_in` 裡：

```ts
a('no_switch', { turns: 'computed', next: false }),
```

或新 op：

```ts
switch_lock_from_resource: (ctx, p) => {
  const points = Number(ctx.getPlayerState('nextElfFrostGlow') || 0);
  const turns = Math.floor(points / p.per);   // p.per = 50
  if (turns <= 0) return false;
  addBlockTimer(ctx, ctx.actor, '霜寒幽光鎖切換', turns, 'turns', { lockSwitch: true }, true, 'turn_effect');
  return true;
}
```

**驗證**：霜寒幽光 200 → 減半 100 → 100/50 = 2 回合不能切換。
