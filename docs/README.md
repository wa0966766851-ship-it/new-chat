## 維護方式

1. 先比對 `elf_source_files/elf_files` TXT 與遊戲資料；有疑義保留原文並列待確認。
2. 修專屬註冊表／通用機制，不在 BattleScreen 新增精靈名稱分支。
3. 加入條件、成功／失敗、P1／P2、傷害分類與下場作用域情境，累積後統一跑後台測試。
4. 實際通過後人工對應 `audits/semantic-evidence.json`；測試、依賴檔案與斷言錨點可追溯。不要只更新hash消除過期狀態。
5. 重新產生兩份清單，執行 `npm run test:audit`；完整驗證另跑 `npm test`、`npm run lint`、`npm run build`。

舊日期文件是歷史紀錄，不會為了讓它看起來「都完成」而改寫。現況以最新測試紀錄與目前程式為準。
