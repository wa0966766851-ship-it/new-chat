## 三、修理順序與可提交工單

### 工單1：持久 run 與戰後一次性結算（先修 E01/E02）

新增 run 資料與轉移模組（建議 src/modes/interstellar/runState.ts、runTransitions.ts）。快照包含 schemaVersion、runId、revision、設定、探索隊伍、地圖、資源、藥劑次數、裝備、銀行資料、待處理戰鬥與已結算標記。所有寫入經同一入口，避免 UI effect 用舊狀態覆寫已結算資料。

開戰前建立 battleId 與 pendingBattle，固定來源節點、隊伍實例、設定及獎勵／掉落抽樣依據，保存後才切畫面。結算以 runId＋battleId 對應，只接受待處理戰鬥；重送、重掛、返回與刷新不能再次發獎。掉落結果在首次結算時固定並保存，不因重送重新抽獎。localStorage 單一快照寫入不宣稱跨分頁交易保證；若支援多分頁，另加鎖或修訂檢查。

App 轉發的是可序列化戰鬥識別與結果，不保存依賴 Run 生命週期的結算函式。BattleScreen 已有 winner 回呼；先評估是否只需共用結果事件與藥劑消耗事件。若需要戰後 HP／PP，擴充通用結果快照，不能在主畫面寫星際獎勵規則。Hub 回探索讀取已結算 run，恢復設定與進度。

舊存檔缺欄位做版本遷移，保留已有資源／地圖；難度缺失用明確兼容預設，不能猜回原設定。壞存檔保留可恢復資料並提示處理，不能無條件清空。結束 run 的 meta 經驗也需避免重複計入。

驗收：普通勝利豆+80；elite勝利豆+200；boss勝利豆+400並正確開層；經驗依既有倍率；固定 RNG 的藏品與招募券只發一次；敗北依現行燃料-2且只扣一次；戰鬥中藥劑消耗能在返回／刷新後保持；難度與裝備保持；重送結果、同一 battle 重開、過期 run 結果不複製獎勵。退出／平手／未完成重開先定政策，不能當勝利。

### 工單2：命運五攔截表驅動與唯一入口（D01/D02/D05）

新增模式事件派送與攔截定義模組；從 ctx.self／ctx.target 及其 instanceId/battleId 讀 rank/effect/HP，不依名字識別同一實例。事件資料携帶 mode、owner、source、entranceId/deathId；登場／死亡次數與「首次」限定依各描述定義，不讓同一事件從多路入口重複執行。

| 效果 | 正確行為契約 | 核心驗收 |
| --- | --- | --- |
| 封技 | 下1回合禁止對手攻擊技，屬性技仍可用；模式限制，不用假異常名 | P1/P2、當回合與下回合期限、後手、切換是否解除、普通模式不觸發 |
| 時空枷鎖 | 對手各技能當前PP與有效上限各-2，最低0；修改實際技能／PP上限機制 | PP1/2/5、恢復PP不突破減後上限、多技能、再次登場不得錯誤重施首次效果 |
| 悲歌 | 下一隻精靈獲死亡者maxHp×0.8護罩，全異常免疫2回合，消費一次 | 護盾與護罩數值分開；非控制異常也免疫；下場持續政策、無下一隻、雙方同死 |
| 索魂 | 對真正擊殺者maxHp×0.35真傷，先制-2共3回合 | 真傷不受非真實倍率；不產NaN；擊殺歸屬、反傷／持續致死、鏈式死亡與去重 |
| 英靈 | 全隊存活者能力等級+1且恢復maxHp×0.3；死者不恢復 | 前場與場下、滿血、禁療／減療、能力上限、換上場不再重領 |

沿用前輪恢復規則、傷害分類、pendingActivation 與作用域能力，先檢查接口足不足，禁止另造平行計時／繞過禁療。護罩傳遞和全隊祝福放通用 primitive／註冊表，主畫面只接通用事件。先證實原生魂印實際handler與效果，再決定替換或同時適用，不能一概把所有 C 原生效果停掉。

### 工單3：面板快照與新局資源（E03/E04）

區分原始種族值／訓練設定、探索配置、戰鬥面板。收集藏品、難度、裝備加成後建立一次快照，明確固定加乘順序；App 與 BattleScreen 不再次套同一模式加成。模式之外的普通對戰 reset 保持既有契約。

驗收：同精靈無加成、單藏品、多藏品、HP×0.8、速度×0.85、敵人層級×1.2與狂暴首領；重複兩次戰鬥面板不累乘；HP／PP保留規則按確認政策；新局3／5鑽石、舊局存量0／7不能被初始值覆蓋。實作前列數值表，不能只斷言 calculatedStats 存在。

### 工單4：節點移動（E05）

新增 resolveMove(run,targetId)：先驗證當層、存在、連線、可移動狀態與燃料；成功才一次更新位置／fuel，再依該 target 開事件。去掉50ms延遲與舊 currentNode closure。已佔領狀態與目前位置應分欄，避免移動把佔領進度寫成未訪問。

驗收：戰鬥→商店、銀行→回復連續移動；非法／跨層／不存在節點不扣油；快速連點只做一筆合法轉移；佔領節點仍佔領；boss開層定位不污染上一層節點。各動作經run轉移入口保存。

### 工單5：抽卡穩定性（D03/D04/D06）

先確認保底與短池政策；不得自行新增替代精靈或允許重複卡以湊12。把 RNG 注入 pool／pull／shuffle，Fisher–Yates 取代 random sort，同一局的卡池、附加效果與實例身份固定。若未驗出雙建池UI問題，仍可將建池／抽取分開以利復現，不假稱已修某預覽bug。

驗收：池0/1/5/12與大池、缺S/A/C、同名不同ID、同ID多實例；不足時輸出明確不足結果或依已確認替補策略；同種子同結果；固定效果不因翻牌重抽；AI ban/pick與首發引用正確實例；6+6與單翻／全翻回歸。

### 工單6：經濟與評級決策後修（E06／D06）

先決定券取消退款、海盜追回本金／利息、模式評級是否統一、保底分布；再實作招募交易與銀行結算。保留基斯克本息、商人成功全額／失敗半本金、海盜無伏擊本息；新增有伏擊勝敗測試不能改坏正常路徑。
