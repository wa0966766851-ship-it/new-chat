## 製作與驗收順序

1. 保留原始靜態圖。以同一參考圖生成備戰、蓄力、出手、收招整張姿勢。書不能換手，武器不能穿頭，衣服、面具、冠與鞋應保持一致。
2. 目視檢查透明邊緣、頭腳、面部與武器，再登記來源。帝辛曾生成霧狀底色，透明提示無效後改用綠幕生成與去背；不能把霧邊直接上線。
3. 固定畫布、腳底與身高。禁止每張各自依外框塞滿，否則角色會忽大忽小。墜星保留四張同尺寸姿勢；其餘三隻按頭部與腳底錨點對齊。
4. 編譯到 build 草稿，檢查圖集、記憶體、命中與收招時間。24 fps 是播放時鐘，不等於有 24 張不同畫作。
5. 在與正式對戰共用的驗收頁測 P1、P2。關掉工具浮層及紀錄以免遮擋目標，使用工具中的技能按鈕安排雙方回合。直接點一般技能列只完成一方選擇，可能仍等待另一方。
6. 檢查抬手→發射→命中→收招、傷害位置、方向、完整頭腳，以及回到待機後是否停止特效。額外行動另測。第五技能必須在登記表明確指向 ultimate，不能只有素材而沒有接線。
7. 明確發布；腳本保留舊資料夾並同步素材登記。正式前後端與桌面發布仍走專案原本流程，本指南的預覽建置不會更新桌面版。

## 指令

從專案根目錄執行。先對照目視核對結果，才執行對齊：

```powershell
node scripts/prepare_zhuixing_poses.mjs
node scripts/prepare_cast_poses.mjs
npm run anim:pose:build -- --spec docs/custom-anim/drafts/20261105-upward-aim/poses.json
npm run anim:pose:build -- --spec docs/custom-anim/drafts/20261105-liuren/poses.json
npm run anim:pose:build -- --spec docs/custom-anim/drafts/20261105-shiyan/poses.json
npm run anim:pose:build -- --spec docs/custom-anim/drafts/20261105-dixin/poses.json
npm run anim:publish -- --id wuxu_zhuixing --source build/pose-animation --publish
npm run anim:publish -- --id wuxu_liuren --source build/pose-animation --publish
npm run anim:publish -- --id wuxu_shiyan --source build/pose-animation --publish
npm run anim:publish -- --id emperor_dixin --source build/pose-animation --publish
```

注意：prepare 腳本包含本次人工核對後的 accepted 欄位，重新執行會重算雜湊，**不能因此認定新換入的圖片自動獲准**。任何輸入圖片改動，都必須重新完成目視核對並更新紀錄。舊版 build_custom_animation 現在只寫 build/legacy-custom-animation，拒絕直接覆蓋 public。

```powershell

node --import tsx tests/customPetAnimation.semantic.test.ts

npm run lint
npx vite build --config tests/fixtures/petAnimation.vite.config.ts
```

預覽入口：`http://127.0.0.1:3016/tests/fixtures/petBattlePreview.html?elf=5026&opponent=5023`。保持同一 origin；素材與 manifest 使用相同版本查詢，版本不符會拒絕。替換後整頁重載，避免記憶體中仍留著舊片段。固定建置驗收優先於大量 HMR 更新中的畫面。

## 演出與負擔規則

- 待機不持續轉圈，也不循環播放出招光效。
- 墜星砲口先朝上，光束先升後從對手上方落下；光柱需漸淡收尖，避免變成硬邊矩形。
- 六刃的黑色刀身要在加亮光效之後畫，否則黑色會被亮光吞掉。目前輪廓仍偏幾何形，後續應補刀刃專用畫作。
- 蝕言優先完善額外行動，普通攻擊保持克制；帝辛使用金色斬擊。
- 動態與靜態方向分開核對。一次翻轉，P1 朝右、P2 朝左；不能憑檔名推測。
- 記憶體看解碼尺寸，不只下載大小。此批單隻圖集約 4.1–6.6 MiB RGBA，下載約 1.5–2.1 MiB。不得推廣成整個遊戲的記憶體用量。
- 測試通過只能證明格式與接線，流暢、自然、威力感必須看片。下一步應增加相鄰姿勢畫作，不能用平移或模糊混合掩飾缺幀。
