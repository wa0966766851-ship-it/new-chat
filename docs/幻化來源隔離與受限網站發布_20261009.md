# 幻化來源隔離與受限網站發布（2026-10-09）

## 這輪修正

先確認本機 main、origin/main 與工作樹，保留前幾輪未提交的修正。所有專屬處理仍走註冊表；不在 BattleScreen 新增特定精靈分支。

幻化：觸發是幻化存續期間的事件；來源是目標魂印／特質定義；持有者仍是自身戰鬥身分。目標體力、印記、存活規則與戰鬥 ID 不複製。自身及取得來源分開執行與展示；解除恢复自身能力層、PP上限及原形，不直接減到1。

本輪補上取得來源的即時持有者視圖。舊 handler 的 `self === activeP1` 判定與直接體力寫入，先前可能辨錯陣營或只修改隨即丟棄的暫存物件。現在 `self` 與本方 active 使用同一視圖，欄位寫入經過正式更新入口。帝皇之盾另改以 actor 判定側別。

取得來源寫入的 registry 私有值有前值與來源紀錄。解除只回收仍屬該來源的值；原有值、自身後續同值寫入、明文己方／下一隻傳遞不被抹除。常駐積木閃避加入取得來源查詢，依既有最大值規則，不自行相加；首次致命旗標區分取得世代，避免同名原魂印占用。

## 網站更新路徑與安全界線

原網站為受限Sites入口及版本供應器，不替換成公開靜態網站。原本custom分享設定、外部訪客名單及停用AI排程不變；Site worker源碼不改、不重設目前版本指標。

使用既有GitHub `build-web-package.yml`，推送後明確指定publish=true：安裝依賴 → 型別檢查 → 全部測試 → 建置／bundle核對 → 套件校驗 → 上傳不可變資源 → 啟用 → 核對線上版本。GitHub與Sites憑證只在既有私密變數／記憶體使用，不寫入repo或輸出。

本機套件只證明打包及發布契約。真正更新成功需GitHub工作流程完成，且发布結果的verified與commit匹配推送版本；不能把原生Sites閘道v11當成遊戲內容版本。

首次GitHub發布37811258108在test:data被阻擋，沒有上傳／啟用。原因是description gzip比對重新壓縮後的bytes，而非還原內容；不同Node／zlib版本可產生不同串流。新增`scripts/lib/packedDescriptions.ts`與`tests/packedDescriptions.semantic.test.ts`，嚴格檢查容器、版本、base64、解壓及完整資料值。不同gzip串流可還原同值；技能數值、吸取／汲取、陣列顺序改動或損壞仍拒絕。`scripts/pack_effect_data.ts`與test:data改用此契約，未改既有素材或描述內容；二進位網站資源仍逐bytes核對SHA-256。
