# 低成本積木代理工作規則

日期：2026-10-13（Asia/Taipei）。本輪授權僅準備規則；修理、模型連線及代理啟動由後續模型接手。

## 1. 工作範圍與 Git 保護

- 正式工作根目錄是本文件上一層的內層專案，不是外層同名舊副本。先確認 git rev-parse --show-toplevel。
- 已備份遠端分支 backup/20261012，記錄 commit 0e340a43e48bd05ebbe144a2c4237b522c0c66e8；此為先前驗證結果，不是本輪重驗。
- 不 commit、push、切換分支、reset、checkout、stash、部署網站、EXE 打包或重啟現有服務。備份已完成，後續只在本機工作。
- 開始前列出工作樹變更與相關檔案摘要；既有修改全部保留。禁止將所有未提交修改視為自己可覆寫的產物。
- 不讀取／輸出憑證、API key、cookies；不把憑證或整個 repo 傳給外部模型。

## 2. 節省成本：先分工，不重造模型轉接器

- 使用者偏好免費 DeepSeek／Muse Spark 1.3。候選識別碼：
  - our-free-model/deepseek-ai/deepseek-v4.1-flash
  - our-free-model/muse-spark-1.3-contributor-free
- 本輪只查到本機模型目錄含上述名稱；沒有重新呼叫模型、測工具能力或確認當下免費額度。目錄有名稱不等於目前可用。
- 選擇模型必須用當前 DSH 實際支援的設定／選單。若 subagent 介面沒有 model/provider 參數，就不能聲稱能指定某個模型。
- 不為此工作開發 Codex bridge、自製代理服務、tool-call 翻譯器或新 server；先使用 DSH 既有工具介面。
- 不默默切到付費模型。不支援指定或免費通道不可用時，交付任務包並停止連線調試，由使用者／後續模型選擇。
- 對同一通道最多一次簡短工具能力檢查、一次必要修正；第二次仍失敗就停止，不用長推理反覆探測。
- Agent Teams／持久 teammates 只有使用者明確要求才建立；一般子代理不等同 Agent Teams。
- 每個子任務限定一個共用機制或最多兩份完整技能；只讀必要檔案與原文片段，不把所有歷史對話或大型稽核 JSON 全塞進上下文。
- 建議每份任務最多 8 個工作步驟、同一測試失敗最多修正兩次。這是執行約定，不是已安裝的 token／費用硬限制；超限需回報實際缺口。

## 3. 真正的進度標準

既有稽核基線：[遷移資料](<audits/block-migration.json>)記錄 43 隻、397 份定義、172 份 Kit、225 份非 Kit、132 份自動轉換候選。本輪未重新執行稽核。

- 非 Kit 不等於功能沒實裝：可能仍由 handler、舊積木或混合路徑執行。
- parser 支援增加、候選增加、測試案例增加都不是新增整份遷移。
- 必須具名列出本次從非 Kit 變成 Kit 的完整定義，且完整原文有等價入口、舊路徑不再重播，才計入遷移成果。
- 機制已支持但未接到精靈：標「底座完成／尚未遷移」。只有部分子句完成：標「部分完成」，禁止把剩餘句改 noop。
- semanticallyAccepted 目前由[稽核腳本](<../scripts/audit_block_migration.ts>)固定輸出 0；不能把它解讀成所有測試無效，也不能擅自改成完成數。
- 所有指標附分母／範圍；全文逐句驗收、解析率、入口數三者分開，不計算臆造的戰鬥正確率。

## 4. 實裝規則

先遵守[專案規範](<../AGENTS.md>)；以下補充不得取代該規範。

1. 每句拆成 Trigger、Condition、Target、Action、數值／公式、固有／附加／攜帶、傷害類別、期限／下場規則。
2. 已確認且無歧義的語意直接實裝。真正原文不明才提出「原句＋兩種解讀＋行為差異」；缺 API／容器不叫文字爭議。
3. 先找通用查詢、事件、持有者印記與抵擋繞過介面，不只搜尋舊 state 鍵；禁止只看 blkIgnoreBlock 沒讀取就認定整個引擎無此能力。
4. [主引擎](<../src/engine/battleEngine.ts>)與[戰鬥畫面](<../src/components/BattleScreen.tsx>)禁止新增精靈名分支。專屬配置放註冊表／資料；必要引擎改動必須是通用介面。
5. Kit 必須可真正 Blockly 保存、重載、修改參數後執行。禁止 handler 包裝、native 引用、未知鍵、日誌-only、999 回合冒充常駐。
6. 完整匹配技能名稱、持有者與原文才套用，不覆蓋自訂描述、明確模式或既有自訂 Kit。
7. 每次只改一個机制，先專用測試與型別檢查，再接下一項。不為清帳面指標改原文、降低快照預期或清除未解析紀錄。
8. 吸取固定＝固定傷害，比例＝百分比傷害；汲取＝真實傷害。無類型「傷害」依已確認規則只指攻擊傷害。
9. N 回合內含當回合；下 N 回合不含當回合。成功使用、命中、行動結束與戰鬥階段結束不能互換。
10. 同一隻下場保留不等於下一隻繼承；個體銀行、來源／持有者、存活場下與額外精靈分開處理。

## 5. 第一批分工：互斥寫入範圍

下面是待交給後續模型的任務，不代表已啟動或已完成。寫入範圍是協作约定，不是 sandbox 的硬鎖。

### A：用既有底座完成一份技能遷移（優先 DeepSeek）

- 第一候選：5012「霜凍之錮」。先讀[技能來源](<../src/data/defaultElves.ts>)與持有者原始 TXT，再核對：必中、4 回合免疫／反彈、命中 80% 冰封／失敗吸取強化、每回合按低血條件選 1/3 或 1/2 吸取。
- 只在所有句子能用既有 op 完整表達且語意無歧義時建立 Kit；不能把 1/3→1/2 近似成翻倍。時點未確認就單獨列待確認，不自行猜。
- 寫入範圍：新資料模組 src/data/migratedExistingPrimitiveSkillKits.ts、新測試 tests/existingPrimitiveSkillKits.semantic.test.ts、單獨結果 docs/delegation-results/existing-primitives.md。
- 禁改共用 runtime、parse、主引擎、package、封裝彙總與原廠資料；需要修改時在結果寫明最小接線 diff，交整合者處理。
- 驗證：雙側正式引擎、成功／失敗、附加封印、期限、原文失配、低血邊界；至少真實 Blockly 往返一份。
- 不支持整份時交付具名阻擋，不用僅 parser 改善替代本任務成果。

### B：隨機異常通用積木合約（優先 Muse Spark 1.3）

- 目標 op：status_random；先查現有抽樣／狀態施加行為是否正確，再補嚴格參數合約、預覽與測試，不能只把 op 加白名單。
- 後續可遷移候選：5024「毀傷湧進」；必須完整原句匹配且所有分支有測試才切換。
- 寫入範圍：[通用 runtime](<../src/blocks/runtime.ts>)中 status_random 單一區段、[閉合合約](<../src/effects/sequenceClosureContract.ts>)、[連鎖合約](<../src/effects/sequenceContract.ts>)中分類／必要參數、[連鎖預覽](<../src/effects/sequencePresentation.ts>)、新測試 tests/randomStatusBlocks.semantic.test.ts、單獨結果 docs/delegation-results/random-status.md。
- 欄位驗證檔或 Blockly 元件確需追加：先記錄具體位置交整合者，不擴大自己的寫入範圍。
- 抽樣依原文定義；「兩種」不可抽成同一種。固定 RNG 不得無限迴圈；免疫失敗不得擅自補抽或改其他狀態。
- 各分類有明確候選；未知分類／非整數次數／數量超出候選等必須拒絕或明確按合約處理。異常施加仍走免疫、抵抗、反彈及來源管道。
- 先雙側單元／正式引擎、固定 RNG、分類、失敗分支、Blockly 改參數往返，再由整合者遷移整招。

### 整合者（後續接手模型）

- A/B 可獨立準備，但 B 會改共用執行器；A 的正式整合／最後驗收等待 B 結束。不得邊改底座邊把長測試當最後結果。
- 單獨負責 [Kit 彙總](<../src/data/migratedSequenceSkillKits.ts>)、[封裝](<../scripts/pack_reviewed_kits.ts>)、[註冊入口](<../src/effects/battleEventRegistry.ts>)、[測試指令](<../package.json>)與稽核輸出。
- 不一次移除所有舊 handler。完整遷移一份才停用那份舊入口；證明 Kit 只執行一次且非 Kit 自訂描述仍保留舊行為。

## 6. 驗收與証據治理

- 最小流程：新增專用測試 → npm run lint（本專案是 tsc --noEmit）→ 整合／data:kit-pack → test:data → test:connections → 必要 core-mechanics → build／audit:bundle。
- compile_applet／lint_applet 若不存在就說明採用實際 npm 指令；不能聲稱跑了不存在工具。
- 單元、真實引擎、Blockly 往返、完整 suite、建置各別記錄；一類通過不能代替另一類。
- 每條指令單獨記實際 exit code。PowerShell 管道／最後一條成功不能掩蓋前段 node 失敗；不能只用輸出關鍵字說全通過。
- 長測試使用 managed job，記錄 job id，完成後收集結果；中止／失去結果都不算通過。不反覆睡眠或忙輪詢。
- 測試超時先判別仍在進行或掛起；設定上限且保留日誌，不每改一行重跑整套。
- 舊証據是否 stale 以摘要比對判定；本輪改了依賴就承認影響。實際對應測試重跑通過且審查断言後，才更新該項摘要；只統一 CRLF/LF，不盲目刷新全部。
- 沒做的雙側／期限／場下／BOSS／失敗／來源邊界明確列未驗，不說「全部驗收」或「100% 相容」。

## 7. 子代理交付模板

每個代理最後只交：

1. 完整遷移：持有者 ID／名稱、技能／魂印、前後執行路徑；沒有則明寫 0。
2. 語意 Tokens：觸發、條件、目標、行為、期限、傷害分類；原文來源。
3. 修改檔案、共用檔案接線建議、沒有改哪些受保護範圍。
4. 測試指令、exit code、成功案例與未驗分支。
5. 原文爭議／缺 API／通道不可用分開列，不以複雜為由統稱不能做。
6. 下一個最小步驟。避免貼整份歷史稽核及長日誌回主對話。
