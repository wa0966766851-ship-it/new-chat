# 戰鬥引擎分離與官方節點順序（2026-10-10，已實作）

## 1. 結構

| 檔案 | 職責 |
|---|---|
| `src/engine/battleEngine.ts` | `createBattleEngine(options)`：回合結算、效果佇列、上下文、死亡判定、AI 驅動。不依賴 React。 |
| `src/engine/nodes.ts` | 官方節點表 1.1–6.6；`onNode` 回報用的 id。 |
| `src/components/BattleScreen.tsx` | 165 行：建立引擎、訂閱狀態（`onStateCommit`）、播放（`presentation`）、把玩家輸入交給引擎。 |
| `tests/battleEngine.headless.test.ts` | 不經 React／DOM 跑整場戰鬥，鎖定節點順序。 |

- 引擎介面：`getState`、`dispatch`、`pushEffect`、`presentation`、`onSkillSelect`、`onSwitchElf`、`onUseItem`、`start`、`mount`、`unmount`、`idle`。
- 原本依 React `useEffect` 觸發的驅動已改成「狀態整批提交後的反應」（`reactToCommit`），觸發條件不變：
  - 進入結算階段
  - 自動戰鬥
  - 強制換人收尾
  - PVE AI 換人
- 型別：原專案沒有安裝 React 型別，`useCallback`／`useRef` 的回傳是 any。抽出時維持相同的寬鬆型別（`stable`、`Ref<any>`），之後可以逐步收緊。
- 結算與播放分離（2026-10-11）：引擎從不等待動畫，整回合立即算完。演出排進 `BattlePresentation` 的時間軸：
  - 傷害數字：`record`
  - 出招動畫：`animate`
  - 換人校正：`align`
  - 回合數：`setTurn`
  - 狀態快照：`stage`
- 畫面顯示 `presentation.view`（播到哪就顯示到哪），日誌、異常、回合階段不會先於動畫出現；玩家要等畫面播完才能再選招。
- 自動戰鬥與 `onBattleEnd` 也會等播放結束。
- 原本寫在 BattleState 的彈字、震動、出招動畫（`ADD_DAMAGE_POPUP`、`SET_SHAKE`、`SET_SKILL_ANIM`）不再寫入戰鬥狀態。
- 精靈專屬程式已移出引擎（2026-10-11）：
  - 新增 `src/engine/battleRules.ts`（全局規則掛點：`roundStart`、`faint`、`entered`、`roundEnd`、`actionFlags`）。
  - 規則檔：`effects/elves/dimensional-dragon/battleRule.ts`（詩章）、`effects/elves/imperial-shield/battleRule.ts`（守護印記、PP 消耗遞減）、`effects/rules/nextElfPending.ts`（下一隻上場護罩／免疫／隱匿＋PP），於 `effects/battleRules.index.ts` 註冊。
  - 懼噬的擊敗恐懼、劫數的增傷與抵擋，原本引擎與咤克斯魂印各寫一份，現在只留魂印裡的那份。
  - 深淵凝視的 300 固傷原本被加兩次：BEFORE_DAMAGE 併入一次，引擎又加一次。已改成魂印在 ON_SKILL_HIT 附加一次獨立固定傷害。
  - 迪恩之刃改由 `relicIgnoreDefPercent` 提供。
  - 六刃回血上限改為通用個體鍵 `recoveryMaxHpCap`。
  - 晨曦之星改用通用鍵 `opponentSpeedPenalty`；恐懼之種改為 `fearSeedDrainPP`／`fearSeedDrainReason`。這兩處原本寫入巢狀物件，引擎讀不到，等於從未生效，現已修正。
  - 稱號與狀態的日誌改讀資料名稱。
  - 引擎內已無精靈名稱判斷，只剩註解。

## 2. 節點順序（實作後）

| 官方 | 引擎 |
|---|---|
| 1.1 戰鬥開始 | `start()`：首發登場 |
| 1.2 操作階段 | **新**：切換精靈、使用藥劑在回合開始前處理，順序依在場速度；這兩種行動不進入出手流程 |
| 1.3 登場 | 換人登場（ON_ENTRANCE 等） |
| 2.1 回合開始 | **移除**回合開始補扣異常 → BEFORE_TURN_RESOLVE → ROUND_START |
| 2.2 戰鬥階段開始 | 先制與速度判定 |
| 3.1 出手流程開始 | BEFORE_SKILL、BEFORE_ACTION、OPPONENT_ACTION |
| 3.2 使用技能時／命中前 | PP、技能轉化、無效、命中、閃避、攻擊免疫 |
| 3.3 技能命中時 | 命中確定 |
| 3.4 技能效果結算 | 技能 handler／積木 |
| 3.4.1 寶石詞條 | **新**：寶石效果從命中後移到這裡（造成傷害之前） |
| 3.5 造成傷害前 | 基礎公式＋BEFORE_DAMAGE 與各種增減傷。基礎公式在 3.4 之後計算，所以 3.4 的威力變化會套用 |
| 3.6 紅傷 | 造成攻擊傷害 |
| 3.7 使用技能後／命中後 | AFTER_ATTACK_HIT、ON_SKILL_HIT、after-hit、AFTER_ACTION |
| 3.8 出手流程結束時 | **改**：ACTION_END 緊接本次出手，不再拖到下一位出手者開始時 |
| 3.9 額外行動 | **改**：在死亡節點一之前執行；對手已倒下仍執行（鞭屍），只有自身倒下才停止 |
| 3.10 死亡節點一 | 每位出手者結束後都判定（含未命中、無效等提前結束的情況） |
| 4.1–4.9 後手 | 同 3.x（`detail.order = 1`） |
| 4.10 戰鬥階段結束 | **改**：BATTLE_PHASE_END 移到回合結束之前 |
| 4.11 死亡節點二 | **新**：戰鬥階段結束效果造成的陣亡在此結算 |
| 5 回合結束 | 計時器 → ROUND_END／ENFORCE → **異常扣減與轉化（改到回合結束效果之後）** → 免死、回合計數 → 特性 → 回合末額外行動（同樣可鞭屍）→ 持續傷害 |
| 5.4 死亡節點三 | 判定陣亡後換人 |
| 6.1 未被擊敗 | **新** `EffectTiming.NOT_DEFEATED`（死亡節點一，出手目標存活） |
| 6.2 被擊敗時 | `DEATH_NODE_1`（沿用舊名作為「被擊敗時」；`data.node` = 1／2／3） |
| 6.3 未擊敗對手 | **新** `NOT_KILLED` |
| 6.4 擊敗對手時 | `ON_KILL` |
| 6.5 被擊敗後 | **新** `AFTER_DEFEATED` |
| 6.6 擊敗對手後 | **新** `AFTER_KILL` |

同一次陣亡只結算一次：哪個死亡節點先看到，就由哪個節點派發。

## 3. 行為變化（請留意）

1. 漸凍等異常：陣亡換人上場時附加的異常，不再於下一回合開始補扣，而是照常在下一個回合結束時扣減與轉化。`tests/deathSwitchCatchUp` 已改為新規則。
2. 主動換人、藥劑提前到回合開始之前。換上場的精靈會吃到本回合的回合開始效果，以及對手本回合的攻擊。換人方不再觸發 ACTION_END。
3. 寶石詞條（狀態、能力、200 點附加傷害、PP 等）改在造成紅傷之前生效。
4. 額外行動排在死亡節點一之前，對手倒下仍執行。
5. 戰鬥階段結束效果改在回合結束效果之前；這類效果造成的陣亡在死亡節點二結算，不再等到回合結束。
6. `tests/deathSwitchCatchUp`、`tests/deathSwitchRoundEnd` 原本在失敗時仍以 exit 0 結束（`finally` 裡 `process.exit(0)`），已修正為失敗時回傳 1。
