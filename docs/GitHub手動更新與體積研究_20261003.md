## 現況（2026-10-03）

- 倉庫 `wa0966766851-ship-it/new-chat` 為公開；匿名查詢 `releases/latest` 回傳 404，尚無可取得的正式最新 Release。原始碼 push 不等於發布可下載的遊戲更新。
- `package.json` 版本 1.0.0，尚無 electron-updater 依賴；`electron/preload.cjs` 只提供 `isElectron`，沒有更新 IPC。
- `SiteUpdateNotice.tsx` 查的是本機 `/version.json`；桌面版的本機版本不會自行變成 GitHub 新版，因此這個網頁重新整理提示不能充當 EXE 更新器。
- 同時有 NSIS 安裝版與 portable 免安裝版。electron-updater 的 Windows 支援為 NSIS，不應把安裝器更新流程當成 portable 替換流程。
- Electron 使用 userData 個人目錄；自訂精靈、編隊、裝備與星蝕進度仍有 localStorage 儲存。現在 localhost 連接埠占用時會遞增；網頁存檔受來源（含連接埠）影響，更新時必須處理這個隔離，否則可能像是存檔消失。
- builder 的 portable 模板會提供 `PORTABLE_EXECUTABLE_FILE`／`PORTABLE_EXECUTABLE_DIR`。替換的必須是外層免安裝 EXE，不能拿解壓後的 `process.execPath` 當下載目錄中原始 EXE 的路徑。

## 建議交付選擇

先保留單檔免安裝模式，實作「使用者按檢查 → 按下載 → 確認退出更新」，不要在戰鬥中、離開程式時或背景自動覆寫。
最小第一版可以先下載新版本到旁邊、保留舊版並提示開啟新版；若要按一下即替換，才加入獨立更新 helper 與交易日誌。
安裝版可使用 electron-updater，但仍需另做存檔備份與回復機制；不能宣稱工具本身保證完整回滾。

## GitHub 發布規格

1. 用新 semver（如 v1.0.1）建立 Release；`package.json`、`version.ts`、發布 tag 與 manifest 版本必須一致。不得拿不同內容重發同版號。
2. 安裝版上傳 installer、`latest.yml` 與 `.blockmap`；portable 上傳相對應 EXE 與嚴格格式的 manifest（version、platform、architecture、fileName、size、sha256、releaseTag、saveSchemaVersion、最低更新器版本）。兩種檔案不可混用。
3. 先上傳完整檔案並核對，再發布正式 Release。草稿／預覽版預設不向一般玩家提供；保留前一個已驗證版本供回復。
4. 更新用的倉庫 owner/repo 寫死於可信設定，下載使用 HTTPS，驗證 tag、平台、檔名與官方 asset 來源；處理 GitHub 下載重新導向時限制已知 CDN，禁止任意 URL／路徑。
5. 客戶端不攜帶 GitHub 寫入 token。雜湊能發現下載損壞，不等於來源認證；更強的保護使用離線私鑰簽署 manifest，程式內只放公開驗證金鑰，並逐步加入 Windows 程式簽章。

## Portable 更新交易（尚未實裝）

`檢查 → 下載 .part → 完整驗證 → 備份 → 退出 → 替換 → 啟動新版 → 確認 → 保留回復點`

1. 檢查只讀 Release 資訊；提供目前／新版版本、變更內容、下載大小。無網路、404、格式錯誤都保留舊版可玩。加逾時、重複點擊鎖與 API 限流退避。
2. 串流下載至自有 staging 目錄的 `.part`；完整比對大小與 SHA-256／簽章後才改成已驗證檔。中斷不得觸碰現在 EXE。大檔不要整包載入記憶體。
3. 確認目標原始 EXE、寫入權限、磁碟可用量與路徑邊界。空間估算要包含新 EXE、舊版備份、玩家資料備份與 portable 解壓資源，不能只算下載的 210 MB。
4. 輸出有 schema 的玩家資料快照，涵蓋自訂精靈、覆蓋資料、編隊／背包、模式進度與設定；先處理連接埠來源差異。排除 API 金鑰及可再下載快取。若備份 Chromium 實體資料庫，必須在所有自有程式與子程序退出後複製，不能照抄使用中的 LevelDB／Cookies。
5. helper 重新核對新檔及目標身份；複製舊 EXE 到版本化備份，逐檔／串流雜湊比對，確認備份能讀且清單完整，才允許替換。不以「目錄存在」作備份成功證據。
6. helper 等待原程式與自身伺服器停止；僅處理記錄的 PID，不按程序名稱全殺。新版先落在目標同磁碟的 staging，再進行可復原的 rename／replace。交易日誌每步持久化，斷電後可判斷尚未切換、已切換或待回復，不假定多檔操作天然原子。
7. 啟動新版，等待新版版本號、正式資源、前端首次載入及存檔可讀的握手。僅 HTTP 200 不足以證明成功。逾時、崩潰、遷移失敗則關閉自己的新版程序，恢復舊 EXE；如存檔已遷移，須恢復匹配的資料快照，不能只回復程式。
8. 不在成功後立即刪除備份。至少保留上一個有效程式及資料快照，提供「回復上一版」。過期清理只允許刪除更新器擁有且有 manifest 的檔案，不得遞迴清理玩家選定資料夾或下載資料夾。

可設「僅下載／備份完成／等待退出／替換中／待新版確認／成功／已回復」狀態。取消應保留舊版；讀取唯讀位置則提供另存新版，不提升權限硬寫。

## 實作模組與驗收順序

- `electron/update/releaseClient.cjs`：來源固定、semver、manifest 與下載驗證。
- `electron/update/backup.cjs`：版本化備份、清單校驗與明確持有範圍。
- 獨立 helper：等待退出、journal、替換與回復；不讓前端任意傳入要執行的命令或覆寫路徑。
- preload 提供有限的 `check/download/prepare/confirm/status`；主程序驗證 IPC 呼叫者是自己的頁面，不暴露任意檔案／shell API。
- 控制中心只展示版本、檢查、下載進度、備份位置與確認按鈕。戰鬥未結束時不允許退出更新。
- 修正資料持有模型：固定／可遷移的桌面存檔來源、JSON schema、遷移前快照與回復；名稱、appId、userData 不任意改名。
- 離線／超時／404／假更新、舊版／同版／預覽版、錯誤 hash／簽章、路徑越界、磁碟不足／唯讀／鎖檔、取消與連點逐項測試。
- 兩份真正版本 EXE 做升級與回復；首次進入、存檔遷移、崩潰、各 journal 時點中斷後重啟均驗收。保留上一版只有在回復可啟動且資料相容時才算完成。

## 體積實測與瘦身優先順序

以先前已驗證 1.0.0 產物為準（十進位 MB）：

| 項目 | 解壓後原始體積 |
| --- | ---: |
| Electron 執行環境（含多語言等） | 384.83 MB |
| dist（含 Vite 複製的 public） | 44.92 MB |
| public | 36.88 MB |
| pet | 28.28 MB |
| images | 6.71 MB |
| 系 | 3.40 MB |
| 整包 | 505.25 MB |

免安裝 EXE 約 210.41 MB，再 ZIP 約 210.12 MB，只少約 0.29 MB（0.14%）。設定已是 `compression: maximum`，換壓縮檔格式不應承諾大幅減半。

1. **先驗證並去掉封裝重複來源。** Vite 將 public 複製到 dist，現在又額外附 public；檔案雜湊盤點得到 458 組重複，重複原始大小約 38.23 MB，包含雷伊、帝辛等圖片。先核對 server 靜態與圖片 fallback 路由，再在打包 staging 只留一份（不能直接刪源圖）。可減少解壓磁碟量；固實壓縮可能已利用重複，最終 EXE 降幅必須重測。
2. **優化衍生素材，不改原圖。** 依實際顯示尺寸產生頭像／立繪與縮圖，評估無損 PNG／WebP 或高品質有損 WebP。保留透明、邊緣／光效、圓形頭像、P1/P2 與右鍵複製功能，不能把 SVG/GIF 等盲目轉檔。
3. **保留必要語言。** 考慮 builder electronLanguages 保留 zh-TW、zh-CN、en-US，測試中文 UI、對話框、字型與 fallback；不刪 Chromium 核心、GPU／媒體 DLL，也不移除 LICENSES。
4. **可選完整包／輕量包。** 輕量版只預載實際名冊素材，其他初次使用下載並校驗快取，代價是首次取圖需網路。不能默默把現有離線素材移走。
5. **架構選項。** 若要求數十 MB 級單檔，可評估 WebView2／Tauri 原型（借用系統瀏覽器環境），但必須重做 Node/Express、preload、圖檔、本地解析、存檔與更新，且有系統執行環境前置需求，不屬於單純壓縮。

### 加密與完整性

加密不會減小檔案，通常新增 nonce/tag，且先加密會破壞後續壓縮效益。ASAR 是封裝，不是保密。含解密金鑰的離線客戶端不能保證程式／圖片不被提取。
更新檔更應優先「完整性校驗、發布簽章、原版備份」，不是把下載包加密。程式混淆可能增加體積與啟動負擔，不能當作防卡頓手段。
