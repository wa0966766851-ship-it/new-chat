# 馬爾修斯顯示修正與積木遷移第一批

## 已修範圍

- 舊顯示把極速機甲借用「星執」、毀滅機甲借用「魔王咒怨」，堅壁機甲偽裝成已解析麻痺，並附上一回合期限。改成獨立的堅壁／極速／毀滅機甲常駐視圖，不建立印記、不猜解析異常、不假設一回合失效。
- 馬爾修斯技能列、懸停詳情與唯讀精靈詳情同時顯示「PP 上限/上限・恆滿」與獨立「充能」。充能可為0或超過原PP上限；顯示層不回寫PP，也不重置充能。
- 0充能仍能選招；技能資源顯示不再混同PP與充能。取得馬爾修斯效果的資源視圖也沿用相同規則，但取得效果的全部交叉情境仍待驗。
- 狀態詳情能力等級補齊正式欄位 `spatk/spdef/speed` 的中文全名，兼容舊別名。

修改：`effects/elves/mars/presentation.ts`、`data/effectCatalog.ts`、`BattleScreen.ui.tsx`、`StatusInspector.tsx`、`SkillResources.tsx`、`ElfReadOnlyProfile.tsx`。本輪沒有將專屬效果放入BattleScreen主流程。

### 充能與結算修正（不是整隻驗收）

- 護盾／護罩和恢復由0.33改為精確1/3後捨去。堅壁回合末附加量取自身恢復請求量，不另取對手最大體力；滿血也不將請求量變成0。
- 汲取15倍消耗充能明確走真實傷害，吸取比例明確走百分比傷害；回復共用正式恢復入口，不裸改體力以繞過回復限制。
- 扣充能寫回出招原槽，保留同名槽資訊；不把出手順序當技能槽，也不將充能同步覆寫PP。後台兩回合實測曾抓到「已打出汲取，但真實技能槽充能沒扣」，此路徑已修正。
- 「PP視為滿」不再由充能是否等於上限判定；革新已至在0充能及超上限充能都按滿PP的1/2吸取。
- TXT的「有0充能時所有技能+5」只掛於第五技能的成功附加效果，移除回合末無条件自動補充。允許充能超上限，不改PP。

另修改：`effects/elves/mars/registry.ts`、`data/elfProfiles/marsRegistry.ts`；新增`tests/marsCharge.semantic.test.ts`，20情境通過，包含P1/P2真實兩回合、真傷穿盾罩、同名技能原槽、充能與PP分離。這些僅登記本報告的部分證據，不把整個魂印標成語意通過。

## 第一批真正遷移

譜尼300／聖靈譜尼5000各5種，共10份（含技能庫）：元素、斷空破、聖堂之門、千烈虛光閃、聖靈魔閃光。

- TXT逐句對照，明確目標、附加身分、使用節點與真實／百分比傷害參數。
- `data/reviewedSkillKits.ts` 是人工審核白名單，先套原始TXT，再精確匹配ID＋技能名＋完整描述。描述不同就停止套用；不覆蓋手動模式／自訂Kit。
- 以 `effectMode: kit` 掛接單一來源，不再同時執行同名手寫handler或通用文字fallback。預設卡牌原文、技能屬性／威力／PP保持不變。
- 每份Kit可以在現有積木工作區繼續編輯與存檔。原始文本保持可追溯，不拿生成描述覆蓋TXT。
- 真傷200／30；百分比取對手最大體力1/8；消強只清正等級、解除自身下降只清負等級。附加失效不誤傷主攻擊，使用／命中／無效節點不重複。

後台實測：`tests/marsPresentation.semantic.test.ts` 12情境，`tests/reviewedSkillKits.semantic.test.ts` 42情境通過。正式戰鬥含P1/P2、附加失效、盾／罩分流及精確追加量；使用沒有魂印的隔離持有者，不代表譜尼整體所有交互通過。10筆部分證據登記在 `audits/reviewed-skill-evidence.json`，保留實際依賴／測試指紋，過期不可自動算有效。

## 100%遷移的剩餘工作

全量42隻、369份定義。嚴格轉換候選27份、尚不能完整轉換342份；現行Kit 16份與27份候選重疊，不能相加成43份。342份是完整可編輯轉換的阻擋數，不等於342份未實裝。詳見 `audits/block-migration.json` 每條阻擋原因及 `全精靈效果實裝核對.json` 的原句與測試證據。

處理順序：

1. 其餘完整候選逐句核對TXT後驗證，再切換。技能石有額外固有／攜帶與特殊效果，不可只轉中毒等一行就刪掉其他效果。
2. 缺口按共同機制分組：成功／失敗與等量結果、即時／快照、分類免疫與次數、秒殺、額外行動、能力值與能力等級、場下作用域、定時／消除／保留、複製／幻化、技能轉化／充能。
3. 每一機制補完整查詢／執行入口與數值測試，再遷移依賴該機制的精靈。繼續保持註冊表與通用容器邊界，不將專屬名稱寫入BattleScreen。
4. 原文含歧義先保留原文並集中記錄；未驗不等於未實裝、解析成功也不等於驗收。仍有342份阻擋，不宣稱100%。
