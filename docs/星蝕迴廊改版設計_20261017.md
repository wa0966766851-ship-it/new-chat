### 1.2 資料流
`Hub（選裝束、契約）→ createRun → draft（6 選 3）→ map ⇄ 節點場景（戰鬥 prelude／事件／商店／星爐／祭壇／寶匣）→ reward → 下一章`。

### 1.3 隨機數來源（改版前後）
| 來源 | 改版前 | 改版後 |

### 1.4 背包與倉庫（舊）
出戰／待命上限 3 起、每章 +1、最多各 6；其餘在「倉庫」（無上限）。舊規則：倉庫只能在地圖節點存取（迎戰前不行、其他場景完全不能開帳冊），只有「上場／下場／存入／放入」按鈕，沒有拖拉、搜尋、屬性篩選、替換。使用者體感「放進倉庫像被封鎖」。

### 1.5 招募與星晶
`shards`（星晶）是唯一的招募貨幣：商店賣 2 隻精靈（低/中 1、高 2、頂 3 星晶）；戰鬥／事件的招募是「系統隨機給 3 隻選 1」。玩家無法自己挑。（2b 起：星晶仍是貨幣，但改成自選精靈招募與進階，見 §3。）

## 3. 需求 2：星晶招募／進階與招募令（第 2 階段 + 2b，已實作）

實作位置：純規則與數值 `v2/recruit.ts`（價格、來源、掉落率、令、重複招募、深度曲線）、引擎 `v2/engine.ts`（`recruitWithShards`／`recruitWithToken`／`advanceElf`／`advanceInfo`／`rollRepeatDrop`／`mintToken`）、介面 `eclipse/Recruit.tsx`（帳冊「招募」分頁、挑選視窗、`AdvanceChoice`）與 `eclipse/Bag.tsx`（背包卡「進階」鈕）。測試 `tests/eclipseRecruitTokens.semantic.test.ts`、`tests/eclipseBagSuitSeed.ui.test.tsx`。

### 3.1 規則總覽
| 動作 | 付費方式 | 說明 |
|---|---|---|
| 招募（星晶） | 星晶 | 從共用 `ElfPicker` 任選一隻「未持有、未禁用」的精靈；不受屬性與強度限制 |
| 招募（持令） | 免費 | 持有符合條件的招募令：免費招募一次符合條件者（令的屬性與強度上限仍是硬限制）；**不扣星晶，也不推高下次價格** |
| 進階（星晶） | 星晶 | 對已持有的同一隻精靈，二選一：強化（全能力 +40%／層，最多 3 層）或 PP×2（進戰鬥時技能 PP 與上限 ×2，只能一次，0PP 技能不變） |
| 進階（重複招募令） | 免費 | 持有重複招募令＝免費進階一次（兩種選擇皆可），令消耗 |

規則（自行定案）：**令＝免費招募一次符合條件者；無令時花星晶招募任意者。** 持有重複招募令時，進階一律先用令（`advanceElf` 預設，`useToken:false` 可強制付星晶）。星晶招募是任選一隻，介面不會自動替玩家用令：要用令請按令旁邊的「免費招募」。

### 3.2 資料結構
```ts
interface RecruitToken {
  id: string;                 // 實例 id（由局種子衍生，可重現）
  kind: "any" | "types";      // any＝任意；types＝限屬性
  types: string[];            // 例 ["火"]、["火","水"]（最多 2 個）
  match: "has" | "exact" | "either"; // has＝精靈屬性集合包含全部；exact＝恰為這幾個（雙屬性）；either＝任一
  tier?: "low" | "mid" | "high" | "apex"; // 可招募的強度上限
  repeat?: boolean;           // 重複招募令：免費進階一次
}
run.shards: number;           // 星晶（貨幣）
run.recruitCount?: number;    // 已用星晶招募的次數（持令招募不計）
run.tokens: RecruitToken[];   // 限定招募券
run.shardsV3?: true;          // 已套用 2b 存檔格式
```
- 「火系招募令」＝`types:["火"], match:"has"`：火系與火系複合屬性（如火.水）都可選。
- 「火/水雙屬性招募令」＝`match:"exact"`：只能選屬性恰為火＋水的雙屬性精靈。「火或水招募令」＝`match:"either"`。
- 令的強度上限隨章節：第 1 章至中階、第 2–3 章至高階、第 4 章起至頂階；套裝特權「強度上限 +1 階」再升一階。**星晶招募不受強度上限限制**，改以價格加成平衡。

### 3.5 重複招募令：隨機掉落（不限章節、不綁開關）
任何來源都有機率出現；擲骰走 `Dice(seed, nonce)`，同局種子可重現。N 等級每階把掉率相對降低 3%（線性，至少剩 40%），即 `repeatDropChance(source, N)`＝基礎掉率 × `max(0.4, 1 − 0.03·N)`。

| 來源 | N0 掉率 | N9 | N18 |
|---|---|---|---|
| 一般戰鬥 | 4% | 2.9% | 1.8% |
| 夢魘 | 12% | 8.8% | 5.5% |
| 首領 | 30% | 21.9% | 13.8% |
| 商店稀有欄（取代原本抽到的令） | 14% | 10.2% | 6.4% |
| 事件（任何選項結算後，非戰鬥類） | 6% | 4.4% | 2.8% |
| 祭壇 | 15% | 11.0% | 6.9% |
| 寶匣（挑完遺物後） | 8% | 5.8% | 3.7% |

取得後在獎勵／事件／祭壇／寶匣的結果文字都會列出；套裝特權「重複招募令 +1」照舊在開局給。

### 3.6 使用流程與介面
1. 帳冊「招募」分頁：頂部顯示「星晶 N」、「招募」鈕（標示最低價）、「進階」鈕；下方列出持有的令（同款合併），每張令有「免費招募」或「免費進階」鈕。
2. 「招募」：開 `ElfPicker`（`eclipse` 外觀），候選＝未持有、未禁用的全部精靈，每張卡右上標星晶價（買不起者停用並在 tooltip 說明）。令的視窗只列符合條件者，價籤一律顯示「免費」。
3. 「進階」：列出可進階的已持有精靈，點選後出現 `AdvanceChoice`（強化／PP×2 各標價；持有重複招募令時顯示「免費」）。背包卡上也有「進階」鈕（價格寫在 tooltip，持有重複招募令時顯示「進階・免費」），開同一個進階視窗。
4. 圖片：`ElfAvatar` → `petImageUrls` → 專案既有 `/seer/head/<id>.png`（本機 → 快取 → 遠端 SeerAPI 自動補圖）。
5. 確認後精靈加入（`addMember`：出戰 → 待命 → 倉庫）。挑選視窗掛在 `.ecl-root` 上（帳冊的 backdrop-filter 會讓 fixed 子層被裁切）。頂部資源列與帳冊分頁標籤顯示星晶數。

### 3.7 進階效果（沿用第 2 階段）
- 寫進該個體 `dup: { stat: number; pp: boolean }`；進階不吃背包格，不產生第二隻。
- **強化**：全能力 ×(1 + 0.4 × 層數)，層數上限 3，套裝「重複招募上限 +1 層」為 4（N12 起特權失效）。接進 `panelFor` 的「個體淬鍊」之後、難度詛咒之前。
- **PP×2**：進入戰鬥時每個技能 `pp`、`maxPp` ×2（原本 0 的技能不變；只能一次）。僅作用於戰鬥副本，戰鬥結束以 ⌈pp/2⌉ 折回存檔（不超過原上限）。
- 技能本身的護盾與回血不隨層數放大（維持現狀，先玩測）。
- 背包卡顯示「強化 n」「PP×2」徽記。

## 4. 需求 3：禁用位（已實作）
- 開局設定頁「禁用」：搜尋＋屬性篩選的挑選視窗，選到名額上限自動關閉；名額 `banCap(N) = 6 − ⌊N/3⌋`（N0＝6，N18＝0），降 N 以外的調整都會截斷多餘的禁用。
- `RunV2.bans`（精靈 id 陣列）；`byTier(pool, tiers, bans)` 是所有精靈池的唯一入口，已套用於：選秀、敵方生成（一般／夢魘／王座）、獎勵招募、事件招募、商店精靈。分級（低／中／高／頂）以完整池計算，禁用不會讓其他精靈換階。
- `createRun` 會過濾不存在或不可用的 id，並依 N 截斷名額，所以改局碼無法繞過名額。

## 7. 需求 6：遺物倍增與敵方深度曲線（第 2 階段，已實作）

### 7.1 己方倍增遺物
遺物欄位 `panelMul`，在 `applyRelicPanel` 的「先百分比、後定值」之後**乘算**。
| 遺物 | 稀有度 | 效果 | 備註 |
|---|---|---|---|

| 增殖晶簇（mul_cluster） | 稀有 | 全能力 ×1.5 | |
| 雙生之核（twin_core） | 傳說 | 全能力 ×2 | |
| 黑日之心（black_sun_heart） | 王座 | 攻擊、特攻 ×3，防禦、特防 ×0.5 | 高風險 |

### 7.2 敵方深度曲線（與 N 等級疊乘）
層數 `L = (章−1)×12 + min(欄,12)`（1…72）；`depthMul(L) = 100^((L−1)/71)`（最終王座 ≈ ×100）。（原草稿誤寫成 `L/71`，以此為準。）
`敵方能力倍率 = depthMul(L) × 類型加成（夢魘 ×1.15、王座 ×1.3） × 蝕度加成（≥25 ×1.1；首領 ≥75 再 ×1.15） × (1 + N 敵方能力)`；
`敵方體力倍率 = depthMul(L) × 類型體力係數（一般 2.5、夢魘 4、王座 7） × 蝕度（≥100 ×1.2） × (1 + N 敵方體力)`。由 `E.enemyScales(kind, depth, eclipse)` 輸出。
| 層 L | 1 | 12 | 24 | 36 | 48 | 60 | 72 |
|---|---|---|---|---|---|---|---|
| depthMul | 1.0 | 2.0 | 4.4 | 9.7 | 21.1 | 45.9 | 100 |
（L12／24／36／48／60／72 即第 1–6 章末首領；以 `depthMul()` 為準，測試鎖定 L1＝1、L72＝100、單調遞增。）

### 7.3 固定值縮放（已實作）
- 規則：回廊內固定值＝基準值 × `√depthMul(L)`（L72 時 ×10），**我方與敵方使用同一條曲線**，所以藥劑與護盾不會在深層失效。
- 機制：開戰時在雙方遺物清單尾端加入偽條目 `fixed_mul:<倍率>`，`fixedValueMul(relics)`（`relicEffectRegistry.ts`）讀取；不在 `BattleScreen.tsx`／`battleEngine.ts` 加任何精靈專屬碼。
- 已縮放：固定傷害（`applyPinkDamage` 的 `fixed` 與 `applyFixedDamage`）、戰鬥藥劑回復值、虛空護盾發生器（500×）、套裝特權「每章首戰護盾」（400×）。
- 不縮放（以最大體力百分比換算的量）：詞綴「吸取」與 `amountMode: max_hp_percent` 的效果。
- **已知邊界**：技能組內的一般護盾與回復量（非百分比換算者）無法與百分比換算量區分，目前**不縮放**；深層時它們相對偏弱，若玩測後需要，需在 effectRunner 為每種 `amountMode` 標註後再補。
- 顯示：面板、傷害、血量、預告與倍率一律走 `formatBigNumber`（萬進位到「極」）。

### 12.1 失敗判定：生命制（2d 改寫，取代「全隊陣亡＝失敗」）
**原 bug（2c 已修）**：出戰名單全滅但待命有人時卡死。現行生命制下仍保留 `ensureFighters` 補位。

**規則（現行）**：失敗條件只有一個：**生命歸 0**。每場戰鬥結束（勝負皆然）依「本場倒下的我方精靈數」扣生命，臨時生命優先。首領戰敗或放棄首領戰只扣生命、回到迎戰前可改隊重戰（蝕度 +6），除非生命歸 0 才失敗。非首領戰敗：蝕度 +6、回地圖。全隊（含待命、倉庫）倒下但生命未歸 0：以生命換回隊伍，全員 30% 體力復甦。勝利但生命歸 0 仍是失敗。

| 項目 | 數值 |
|---|---|
| 初始生命 | 5（`LIFE_BASE`），最低 2（`LIFE_MIN`） |
| N3／N6／N9 | 各 −1（N3＝4、N6＝3、N9 起＝2；N9 以上維持 2） |
| 永久生命 | 隨整局保留；來源：提燈者之心 +1、命蓮 +1、首領獎勵 +1（`BOSS_LIFE_REWARD`）、事件「縫命婆婆」、商店（240 豆，每買一次 +50%）、套裝特權（熔爐機甲 +1） |
| 臨時生命 | 只在當章有效，換章清空後重新給當章份；優先於永久扣除；來源：餘燼燈芯每章 +1、星光守護者特權每章 +1、事件「守夜人的燭台」、商店（80 豆） |
| 敗因 | 「生命耗盡」（`cause: "lives"`；`DEFEAT_TEXT.lives`），紀事寫入倒下的精靈 |

**舊存檔遷移**：`migrateRun` 對沒有 `lives` 的存檔補上 `startLivesFor(nLevel)` ＋套裝特權生命，臨時生命補特權每章份；`lastLifeLoss` 缺省即無。

**介面**：資源列「生命」分別顯示永久與臨時（`♥ 5＋臨時 2`），tooltip 為 `LIFE_RULE`；戰後結算、迎戰前、獎勵畫面顯示「本場倒下 N 隻，扣除永久 x／臨時 y，剩餘…」（`lifeLossText`）；失敗條件在「隊伍」鈕、「點燃第一盞燈」鈕與敗北橫幅的 tooltip（`FAIL_RULE`）。商店新增兩個生命商品。

**平衡備註**：每場倒下數即扣除，一般戰（2–3 隻上場）通常 0–1 生命；五章首領戰各給 +1 永久生命，所以高 N 的壓力主要來自初始生命減少與商店價格，而非單場失誤。保命來源合計上限約 +4 永久、每章 +2 臨時，不會讓 N 難度失去意義。

敗北結算：`scene = { kind: "end", result: "wiped", cause, by }`，存檔標記為結算畫面，按「收起殘燭」才清除存檔並記入戰績。

### 12.2 保命遺物與特權（各一次，用後碎裂；2d 改為「本場不扣生命」）
只在「生命將歸 0」（本場倒下數 ≥ 目前總生命）時觸發；一般戰敗不消耗。觸發後**本場不扣生命**；若本場是勝利，照常領獎勵。重戰一律把 `nonce` +1，不會原樣重播。

| 名稱 | 稀有度 | 效果 | 代價 |
|---|---|---|---|
| 替身人偶 | 普通 | 本場不扣生命，全隊 80% 體力（原 40%，倍增）；非首領回地圖，首領戰敗重回戰前 | 失去一半賽爾豆與一件隨機遺物（不含其他保命遺物；`Dice(seed,nonce)`，可重現） |
| 不滅星核 | 稀有 | 本場不扣生命，全隊回滿 100%（原 50%）；戰敗則留在原節點重戰 | 只有一次 |
| 逆時沙漏 | 傳說 | 回到戰前狀態（體力、PP、藥劑、**生命**、背包編排），可改隊重戰；只在打輸時倒轉，勝利不觸發 | 蝕度 +10；沒有快照（舊存檔）不觸發 |
| 逆命者特權 | 套裝 | 「致命時不扣生命（每局一次）」，全隊 30% 體力 | 蝕度 +6；N12 起特權失效 |

**互動順序**（`rescueSources`）：逆命者特權 → 替身人偶 → 不滅星核 → 逆時沙漏 → 敗北。同時持有時每次只消耗一個。標頭有「保命 N」鈕，觸發後顯示橫幅。

### 12.2b 遺物數值翻倍與缺圖介面（2d）

**缺圖介面**：`RelicIcon` 依序嘗試 `webp` → `/seerapi/relic/<id>.png` → 圖示字；其他代理抓圖後只要放進 `public/seerapi/relic/` 即自動顯示。

### 12.2c 章末首領「神話」（2d）
沿用既有 BOSS_ONLY 狀態「神話」（`statusRegistry`：免疫能力下降與異常、PP 無限、必中，無回合數），不重做。掛載：`startBattle` 對 `kind === "boss"` 遭遇的 `enemyRelics` 加入 `boss_myth`（遺物處理器，`relicEffectRegistry`）；處理器在己方出手前（`BEFORE_ACTION`）或對手出手時（`OPPONENT_ACTION`，由引擎通用派發 `triggerRelicEffect`，不含精靈專屬碼）首次激活，登場與回合開始不激活，已有或倒下不重複。
**時序修正**：引擎計算 PP 消耗時原本讀「出手前快照」的狀態，首領先手時激活的神話要到下一手才免 PP；改為讀最新狀態，首領先手也立即免 PP。一般遭遇與夢魘不帶神話。測試：`eclipseLivesMyth.semantic.test.ts` 第九、十段（處理器單測＋真實 headless 戰鬥，玩家先手／首領先手各一次）。

**依 N 等級**：每家商店兌換次數 `barterLimit`＝N0–5：3 次、N6–11：2 次、N12+：1 次；每條配方每店最多 2 次；賽爾豆的量每階 ±2%（拿到的 ×(1−0.02N)、要付的 ×(1+0.02N)）；N9 起藥劑換令多收 1 瓶。

**防套利規則**
1. 每件物品有一個基準價值（＝商店底價，未乘章節係數）：賽爾豆 1、星晶 70、藥劑 45、遺物 90／160／260／320、令＝`tokenBasePrice`。
2. 每條配方「得到的最高價值 ≤ 0.75 × 給出的最低價值」（`BARTER_RHO`；N 等級只會讓配方更差）。兌換數量不隨章節係數膨脹，所以不同章節的商店之間也不能低買高賣。
3. 商店係數下限 ×0.5（`SHOP_DISCOUNT_FLOOR`）低於兌換比 0.75，所以**「折扣買進再兌換」可以賺——這是刻意開放的玩法**。兌換表本身不套利（第 2 點不變）；套利只來自折扣疊加，且利潤上限為 (1 − 商店係數)×所買底價。
4. 位能函數（2026-10-25 改寫）：全價 Φ1＝賽爾豆＋Σ物品底價。任何兌換與刷新都不會讓 Φ1 上升（測試逐配方逐 N 檢查）；只有買進能讓 Φ1 上升，且增量 ≤ (1 − f_min)×底價。測試在真實商店場景隨機買、換、刷新各 2000 步（4 組章節／N），逐步斷言上述界線與總獲利僅來自折扣；另斷言下限常數為 0.5、疊到下限以下時夾在 ×0.5。把某條配方改成賺錢版本，測試會失敗。
5. 會附贈藥劑的遺物（藥劑腰帶等）是既有商店設計，不在兌換範圍；詛咒遺物不可當給出品（價值 0）。

### 12.4 水平卡片列拖曳捲動
`src/components/shared/useDragScroll.ts`：滑鼠／手寫筆按住左右拖（超過 6px 才算拖曳，之前是普通點擊）；拖曳中關掉 scroll-snap，放開有慣性（停住再放開沒有慣性），結束後吸附到最近的卡片中心；拖曳後緊接的 click 被吞掉，不會誤選卡片（下一次按下或 300ms 後解除）。觸控維持原生捲動與吸附；方向鍵左右仍切換套裝；垂直滾輪在卡片列上轉成水平捲動，到盡頭放行給頁面。目前專案內只有套裝選擇是水平卡片列（招募挑選、遺物選擇都是換行格狀，不需要）；之後有新的水平列直接 `const drag = useDragScroll({ snapSelector })`，把 `ref` 與 `{...drag.bind}` 掛上去。

### 12.5 套裝立繪顯示
素材 192–320px 寬的小圖：卡片立繪區用「原尺寸置中、只縮不放」（`max-w/max-h 94%`、`w-auto h-auto`、`object-contain`），不再 `w-full h-full` 撐滿，避免拉伸與放大模糊；沒有圖（目前只有 `morning_star`）兩個來源都失敗後改顯示徽記大字。圖檔由電腦端 `.gitignore` 管理，不進雲端 commit。


## 13. 原廠 BOSS 特性（夢魘與王座）

37 條原廠 BOSS 特性（BWIKI「赛尔号PVE概论」==BOSS特性==）以 BOSS 專用異常（`BOSS_ONLY`，名稱前綴「特性·」）加入異常資料庫；夢魘（elite）與王座（boss）開戰時抽取 1–3 條，章末首領照舊另掛神話（神話不佔特性名額）。逐條原文／實作／差異／威脅見 `docs/audits/boss_traits_review_20261025.md`，圖示對應見 `docs/data/seerapi/boss_trait_icons.md`。

### 13.1 抽取規則（`bossTraitDraw.ts`）
- 強度分 s ＝ (章 − 1) ＋ ⌊N／6⌋（0–8）。
- 數量：夢魘 1 ＋ [s≥4]；王座 1 ＋ [s≥2] ＋ [s≥5]；上限 3。王座隨行精靈（第 2 隻起）各少 1 條。一般遭遇不帶特性。
