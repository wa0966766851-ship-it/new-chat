# 自製精靈動畫製作與驗收

2026-11-04；依目前本機工具與墜星素材檢查建立。目標是角色完整、面對對手、出招有命中感，並能在真實對戰大小下順暢播放。

> 2026-11-05：播放接通不代表動作自然。目前仍有整圖晃動、拆分異樣；下一輪以 [重製規格](自製動畫重製規格_20261105.md) 的關鍵姿勢、遮擋補畫與無光效驗收為準。下文功能與修復前數值不能當成動作美術驗收通過。

## 本輪實裝狀態

2026-11-04 已接上共用場地特效、未知精靈共用演出，以及設定內的圖片手動／自動／不重試。墜星製作改為先輸出草稿，再經發佈工具檢查與備份；以下問題清單保留為修復前基準，不能當成目前仍未修改的結論。逐項結果與未驗收範圍見 `docs/audits/2026-11-04_自製出招動畫實裝與驗收.md`。

## 修復前找到的問題

1. **來源圖與動畫成品要分開判斷。** `public/elf-art/wuxu_zhuixing_body_new.png` 是 1586×1828，來源頭部完整；`docs/custom-anim/preview/char-cell.png` 也能看到完整頭部。較早的 `wuxu_zhuixing-sa-sheet.png` 不能替代目前骨骼成品的驗收。不能把不同日期、不同版本的預覽當同一份結果。
2. **拆部件可能把頭拆錯。** `scripts/lib/skeletalRig/parts.mjs` 先分配 `ringR` 再分配 `head`。在來源矩形 x=700–879、y=440–649 的可見像素中，21,075 被分給環、15,263 分給頭。這只是包含頭髮／頭部周邊的檢查區，不能將整個矩形視為人工精準頭部遮罩；但它足以證明環與頭的歸屬需要重畫確認。環移動時可能帶走部分頭部，不能只靠放大畫布修正。
3. **「零遺漏」的註解與實際結果不同。** 以 alpha>8 為可見門檻，來源有 737,765 個可見像素，`claimParts` 加 `fillUnowned` 後仍有 **1,445** 個未分配。沿相連像素擴散的方式無法補到獨立小碎片；可能損失細線、游離光點等。這不是頭部消失的單一充分證據，但應設成製作阻擋條件。
4. **特效仍主要在自己的圖塊裡。** 目前自製 manifest 有角色與本地特效座標，沒有明確的「砲口、對手受擊點、飛行路徑」欄位。換大小／換站位時，很難保證打到對手；換 P1／P2 也不能只翻整張圖了事。
5. **測試不足以驗收美術。** `tests/customPetAnimation.semantic.test.ts` 的 32 項測試通過，證明資料可讀與播放契約，沒有證明頭沒掉、臉沒扭曲或命中位置正確。
6. **檔案小不代表播放省記憶體。** 墜星目前登記的 4075×3053 圖集，解開成 RGBA 單張就約 **49,763,900 bytes（47.46 MiB）**，還沒算其他緩衝、幀資料與雙方資源。不要用 PNG 下載量推論低階電腦一定跑得動。

上述是程式與圖片檢查結果；本輪沒有完成目前骨骼成品的雙方實際對戰錄影，因此不宣稱已解決裁頭或所有落點問題。

## 建議製作順序

### 1. 固定唯一原稿與版本

保留原始透明立繪、尺寸、雜湊、來源與授權資訊；角色／皮膚／動畫來源各有固定 ID。每次預覽要標明來源雜湊與製作版本，避免新舊報告互相誤導。正式 `public/elf-anim` 只放通過驗收的輸出，草稿先放 `build/custom-animation/<id>/<version>`。

### 2. 先拆圖，再做動作

頭、軀幹、武器、披風與浮游裝置各自有可檢視的遮罩。使用人工確認的輪廓，不能把互相重疊的大多邊形直接視為正確部件。

必做三張對照圖：原圖、各部件不同顏色的歸屬圖、所有部件在零位移時拼回的圖片。重點看臉、頭髮、手、砲口與腳底；細碎光線也要記錄保留或刻意捨棄。未歸屬的可見像素一律列出，若容許刪除必須有明確遮罩與理由。

墜星先重畫頭／後環邊界，將後環應被頭遮住的區域單獨補畫或遮蔽，再測環旋轉；不要單純交換兩個多邊形優先序就宣稱完成。沒有分層原稿時，先用幅度較小、頭與身體同組的動作，確認完整後再增加拆分。

### 3. 把出招分成四部分

| 部分 | 固定在哪裡 | 需要記錄 |
|---|---|---|
| 角色動作 | 自己的站位與腳底 | 朝向、可見大小、武器／手的位置 |
| 發射與飛行 | 砲口／手到對手 | 起點、目標、路徑、時間 |
| 命中特效 | 對手當下可見身體 | 相對身體的命中點、命中時間、受擊反應 |
| 全場特效 | 場地 | 遮蓋範圍、前後層次、退場時間 |

這些是後續應加入的資料欄位，**目前尚未全部實裝**。做成共用動畫設定與播放器，不在戰鬥主檔依精靈名稱加例外。特效層可以跨越場地，角色貼圖不必為了遠射光束做成巨大空白畫布。

### 4. 對齊戰鬥節奏

使用明確的命中標記。主技能傷害、後續附加傷害各自對應既有戰鬥事件；不能等整段收招完才一起跳傷害，也不能由動畫重新計算傷害。落空、免疫、抵擋、致命一擊與多段命中應有各自對應的顯示。

1／2／5／10 倍速度同時縮放動作與特效時間，不能只加快角色；暫停、跳過、換人、死亡後要清掉舊特效。特殊額外行動優先用專屬片段，沒有時按既有規則重播屬性動作，不能重複觸發技能邏輯。

### 5. 用真實對戰畫面驗收

同一來源固定同一個網址與埠，先載入一次素材再測。使用與正式對戰相同的站位、裁切、縮放與 UI，不用獨立小畫布判定成功。

- P1／P2 分別待機、物攻、特攻、屬性、受擊；兩邊應面對對方。動畫朝向與靜態圖各自記錄，不互相覆寫。
- 對手測普通體型與大型體型各一次；看特效是否落到身上、衝刺是否穿過對手。
- 1920×1080、1366×768 與窄畫面各看一次；可見角色大小與同皮膚靜態版接近，頭腳完整。大型精靈按已接受範例保留壓迫感，不統一縮成小模型。
- 待機取循環起、中、末；攻擊取起手、命中、收招。最劇烈的一幀也不能切頭。
- 記錄「通過／失敗／未測」與圖片證據，不能用自動檢查通過代替人的觀看。

### 6. 控制資源負擔

優先共用來源、皮膚與特效，兩隻雷伊若用同皮膚便不要複製圖集。只載目前雙方及已知變身型態；換人後依容量釋放，不預載全部精靈。正式輸出優先嘗試縮圖、拆待機與出招圖集、重用特效，再比較臉與細線是否劣化。

下載大小、解壓後圖集大小、製作資料大小、首次準備時間、連續換人後記憶體都要分開記錄。不要靠增加低畫質版本就宣稱流暢；必須在目標電腦實測。遠端資源應有版本雜湊與本機快取，下載失敗回靜態圖，不能卡住戰鬥。

## 2026-11-06 修正：禁止用水波拉伸補足待機幅度

橢圓中心位移、周邊固定的變形即使沒有三角形翻折，也會把金屬、肌肉與衣料拉得像水中折射。四隻 v4 草稿已撤除這種設定。不得以「未翻折」「影格足夠」宣布自然。

獨立浮游物可整塊旋轉／位移，金屬形狀必須保持；衣襬從連接處擺動，根部不能滑動。切開會露出缺口時先補遮擋底圖，補畫限定在被遮住的範圍，不能讓生成臉或整個身體取代原畫。原有細線去背問題要另外處理，不靠動態模糊遮掩。

## 六刃物攻與特效配色（2026-11-06 接續）

玩家指定物攻是「人物衝近、持劍揮斬」，不能用站定發令、六把劍飛出去取代。發令姿勢保留給特攻。普通物攻與專用第五技能都要明確列入 `presentation.meleeSequences`，不能只讓名為 attack 的片段接近對手。六把劍總量固定：一把進入人物手中時，外部劍層只畫另外五把，還劍後再恢復六把；仍需驗收取劍／還劍過渡，不能只檢查數量。

六刃色調以原圖黑色金屬、暗綠刀紋為主，翠綠只用於短暫斬痕與命中，白綠亮芯面積要小。可參考戰鬥／邪靈標準特效、王雷伊與摩哥斯的形狀和節奏，不直接照搬金黃或紫色。參考候選必須標明來源、用途、原始與轉色檔案、時序、大小；未確認數字 ID 與屬性映射前，不冒稱已找到某屬性專屬效果。

U 端的共用技能包包含多個圖集與 clip，不能用目前只取「第一個 SwfClipAsset／第一張 Texture2D」的單精靈解析入口直接抓指定技能。先以 container 路徑定位 clip，再以 Sprite 的 m_PathID 找它對應的 Texture2D。直接使用 Texture2D.getImage() 和使用 parseBundleCore 的 atlasPixels，影像列方向不同；必須用原圖與分鏡確認，不能多翻一次。首個匯出試作已遇到取樣方向錯誤，修正後才保留候選。

本輪六刃草稿重建：先執行 `prepare_liuren_weapon_pilot.mjs`、`build_pose_animation.mjs`，再執行 `prepare_standard_impact_pilot.mjs`，最後一個腳本需要先以 `inspect_u_skill_bundle.mjs 11 19` 匯出本機研究檔。這些都是草稿流程，不能直接視為公開發佈流程。

## 咒書額外行動草稿（2026-11-06）

新增可選 extraSeal／extraSealArt 配置，只負責畫面，不建立戰鬥效果。先有書中逸出、移往對手、束縛收束的先後順序，再考慮增加特效強度。人物抬手與紙頁出現需要共同時鐘；不要只讓畫面兩側同時亮圈。原人物三張姿勢不等於完成待機與受擊。

素材維持各自角色配色；重用原廠形狀不能照搬不相容色調。小型特效圖格保持方形、限制最大顯示256px，不能鋪滿整個人物而放大模糊。亮色對手也要測，避免紫黑煙霧變成白色殘像。目前skill/19仍為候選，不以數字推定它是邪靈標準特效。咒頁的完整生成指示、原檔及縮圖均保留在wuxu_shiyan草稿目錄。

## 透明原稿與圖集負擔的判讀（帝辛試作補充）

產圖預覽可能看見透明像素內的隱藏顏色。要判斷是否真有大片霧或髒背，先按alpha合成到純深／淺背景再檢查，不能只看預覽、RGB或「沒有alpha=255的像素」就判失敗。帝辛受擊圖主體alpha多在252–253，透明區藏有金紫RGB；實際合成沒有預覽所見的大片霧。避免直接設alpha閾值而切掉髮絲與細光線。

拆原圖時，固定區與活動區不能重複疊放半透明邊緣；補底只藏在原本完全不透明的遮擋區內。休止時須驗證原像素及合成alpha，移動後再看接縫。動作端點可共用同一組休止圖層，不需要另打一張完整人物副本。圖張變少不代表記憶體變少：打包排列也會產生大量空白，必須記錄實際圖集長寬與RGBA尺寸，不能只報PNG下載大小。
