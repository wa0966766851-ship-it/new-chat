# 桌面完成版本與開發來源

桌面「03-遊戲／賽爾對戰模擬器」捷徑繼續指向 `launcher/launcher.ps1`。它讀取最後一次驗證成功的完成版本，不依賴 EXE，也不在每次開啟時自行發布未完成的來源。

## 完成開發後

在專案根目錄執行 `npm run desktop:update`。流程會依序：

1. 重新產生積木資料包，檢查型別、雷伊戰鬥、存檔修復、立繪方向、皮膚及服務身分。
2. 在 `.desktop-releases/<識別碼>/` 建立前端與後端，不覆寫執行中的 `dist`。
3. 啟動獨立本機測試服務，核對首頁、版本檔、實際服務PID與前後端版本。
4. 比較建置前後來源內容；編輯尚未停止、驗證失敗或建置不完整，一律不切換。
5. 寫入完成紀錄，最後才原子替換 `active.json`；舊完成版本保留。

當下的戰鬥與編輯不會被更新流程終止。結束戰鬥、保存編輯並關閉舊視窗，再使用原捷徑開啟。若3000埠仍有舊服務，啟動器會提示，不會擅自終止其他行程。

回復前一版本使用 `npm run desktop:rollback`，同樣在關閉目前視窗後生效。沒有先前完成版本時會拒絕回復。此命令不回復玩家存檔或設定。

## 三種入口

| 入口 | 用途 | 更新方式 |
|---|---|---|
| `npm run dev`，或環境變數 `SEER_DEV=1` 的啟動器 | 開發預覽 | 來源變更即反映；不能當完成驗收 |
| 原桌面捷徑 | 本機完成版本 | `npm run desktop:update` 成功後，下次開啟載入 |
| 網站發布／獨立EXE | 發給其他玩家 | 沿原發布流程另行驗收；不因本機完成而自動發布 |

`npm run build` 仍產生一般 `dist/` 前後端，供既有網站或封裝流程使用；不會覆蓋桌面完成版本指標。新流程沒有把所有歷史EXE自動更新成同一版。

## 資料與檔案邊界

- 正式原文：`src/data/corruptedReyDescriptions.ts`；真正執行的可編輯積木：`src/data/corruptedRey.ts`。禁止用 noop 充當「已實裝」或拼接積木摘要取代原文。
- 舊內建定義由 `savedCorruptedReyCorrection.ts` 與共用來源綁定升級。精確比對文本和行為參數，自訂修改保留；六個本機儲存入口在寫入前保留原字串。
- 桌面舊存檔還可能帶有不同版本的行為參數。`legacyCorruptedReyDesktop.json` 是實際存檔去除配裝與玩家資料後的歷史定義，用來精確辨識；它不是展示或執行來源。不得只用最新積木換成舊摘要來冒充舊存檔測試。`reySavedPresentation.integration.test.tsx` 會經過實際圖鑑資料、戰鬥詳情與完整介紹，並檢查重載後仍使用正式原文。
- 舊版倉庫及編輯器的皮膚選擇保存為 `skinId`。皮膚名錄在 `elfSkins.ts`；普通雷伊與雷龍圖均可選，原始外觀和自訂圖片不被覆寫。
- 方向只在 `seerAssets.ts` 記錄，P1朝右、P2朝左，未知圖不繼承名稱方向；詳見 `AGENTS.md`。
- 接手期46個根目錄草稿封存於 `tools/archive/20261023-rey-scratch/`，不刪除原始證據。既有戰鬥、元件與資源資料夾不作無目的的大規模搬動。

本機完成流程跑的是本次相關驗證，並不宣稱全專案所有精靈、歷史網站、EXE或使用者自訂圖紙均已驗收。

## 2026-10-23：四行魂印反覆出現的實際原因

桌面獨立瀏覽器設定檔的 `seer_default_elves_overrides[7070]` 保存了四行摘要，並優先於內建精靈。當時執行服務的版本識別與已完成版本一致，因此這次不是單純忘記重建。

該存檔除了文字較舊，魂印的麻痺／繳械與「暗影墮霆閃」首次繳械還寫死 `turns: 2`；「墮影噬雷決」增傷使用 `outgoing_attack`／`攻擊`，目前正式圖紙為 `outgoing_skill`／`技能`。舊遷移測試只替換摘要標籤，並沒有真實舊版本的這些參數，所以測試通過卻無法辨識桌面保存的定義。

目前透過已確認的歷史描述與完整積木精確比對，再更新至正式定義。測試需同時涵蓋存檔修復、GameDataProvider 覆寫來源、prepareSavedBattleRoster、新舊詳情共用元件與保存重載；任一參數被使用者修改時保留，不可用「名稱相同」或「大部分相似」強行覆蓋。配裝、當前 PP、皮膚與技能槽順序均不屬於此次定義遷移範圍。

正式執行路徑仍為 `effectMode: kit` 與可編輯 `effect_sequence`／`skill_property`；歷史快照只辨識舊版本，不會作為另一套戰鬥程式。魂印四個可執行條目可包含多個條件與 else 分支，條目數不能用來代替文案完整度或機制驗證。
