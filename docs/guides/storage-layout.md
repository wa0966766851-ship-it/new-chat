# 檔案分區與下一階段瘦身

2026-10-29 第三輪已開始按[具體計畫](../audits/2026-10-29_第三輪封存與瘦身執行.md)實行封存；下列候選數字是第二輪基準，實際現況以第三輪結果為準。本機封存統一放`.local-archives/20261029/`，其中`README.md`與`INDEX.json`提供來源和還原對照。

本指南整理現有用途與後續存放規則，不宣稱已搬移素材服務或修改所有打包流程。量測依據見[2026-10-29第二輪盤點](../audits/2026-10-29_第二輪空間研究與結構規劃.md)。

## 六個分區

| 分區 | 現行路徑 | 存放規則 |
|---|---|---|
| 原始碼與正式資料 | `src/`、`server/`、`elf_source_files/` | 進版本庫；禁止從產物反向覆蓋 |
| 正式素材 | `public/`、`pet/`、各圖標目錄 | 保持既有引用；變更需核對真實顯示 |
| 開發證據 | `docs/`、`shots/` | 報告保留相對連結，臨時截圖不混進正式素材 |
| 可丟棄的單次工作 | `build/.work/<用途>-<唯一編號>/` | 既有工作區工具建立與清理；新實驗盡量沿用，不再複製整個專案到多個固定日期目錄 |
| 正式發佈與桌面 | `dist-electron/`、`release/`、`.desktop-releases/` | 和暫存分開；目前與上一版保護，EXE與網路安裝payload不能拆開刪 |
| 遊戲下載快取與測試瀏覽器 | 執行時素材快取、隔離測試profile | 新測試使用系統臨時目錄與共用關閉工具，不再新增`.seer-cache/diag-*`完整瀏覽器副本 |

`.seer-cache/`目前混有真實素材、解包影格、截圖、預覽產物、完整測試瀏覽器資料。不能只換目錄名字就移走；讀取端、打包白名單和舊路徑相容需要一起處理。這輪先阻止新測試繼續累積完整profile。

## 優先順序

1. **停止累積**：單次測試在關閉自己的瀏覽器後清自己的profile，失敗時保留；正式玩家資料不納入清理。
2. **舊測試profile另行處理**：先辨識是否仍在用、是否保存唯一的測試存檔／證據，再決定刪除或打包歸檔。現有61個名稱符合規則的目錄約9.88 GiB，是候選目錄總量，不是可直接刪除量。
3. **舊實驗封存**：保存報告、manifest、獨有程式差異與未發布附件；確認能重建後，才刪多份Electron與node_modules。不能把未發布的輕量素材附件當成已備份。
4. **正式成品保留政策**：建議工作目錄只保留本版與上一版完整成品，其餘移交獨立歷史封存；但本輪未實行，正式舊版仍保留。移到同一顆磁碟不會釋放總空間。
5. **素材共用後續研究**：可考慮以內容雜湊共用不可變素材；目前各版本都有自己的URL與離線路徑，直接刪重複檔會破圖。不要用硬連結把可能覆寫的檔案綁在一起。

## 重現盤點

`node scripts/audit_workspace_storage.mjs` 只盤點；加 `--hash --budget-mib=64` 以64 MiB讀取預算核對部分相同大小的大檔。輸出在`.cleanup-audit/storage-analysis.json`。

這個工具不刪檔、不啟動瀏覽器、不掃到專案外、不跟隨目錄連結。重複比對只考慮至少1 MiB的檔案，且跳過Git物件與node_modules。`hashScan.complete=false`代表只完成部分核對，不能把結果當全部重複量。檔案加總是邏輯大小；硬連結、檔案系統壓縮或稀疏檔可能讓實際磁碟占用不同。

所有新維護工具預設先產出計畫，涉及刪除時仍按[整理指南](project-housekeeping.md)的版本、程序、連結及追蹤檔保護規則處理。
