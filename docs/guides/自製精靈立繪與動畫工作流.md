## 一、先分清五份東西

| 層次 | 路徑 | 用途 |
|---|---|---|
| 原畫與補畫來源 | docs/custom-anim/drafts/日期/精靈/ | 原圖、生成原檔、提示詞、失敗原因；不能拿圖集代替原稿 |
| 製作規格 | 同資料夾的 spec.json | 姿勢、腳底線、朝向、分層、分鏡及命中點 |
| 試作 | build/指定版本/精靈/ | 可反覆重建；不能被正式網站偷偷引用 |
| 正式素材與登記 | public/elf-anim/、public/elf-fx/、src/battle/petAnimationAssets.ts | 網站真正播放的版本，三者必須一致 |
| 桌面與網站產物 | .desktop-releases/、dist/、網站部署 | 是來源的快照，更新來源不等於使用者已看到更新 |

先記錄 Git 狀態與作用中的桌面版本。其他 AI 同時工作時，禁止整份回滾或 git add -A。
只改演出資料與共用播放器，不把精靈專屬戰鬥規則加進 BattleScreen 或 battleEngine。

## 二、玩家驗收標準

逐隻、逐側檢查；不以「沒報錯」「有在動」或「測試全綠」代替畫面驗收。

- 待機：原畫的臉、盔甲、衣紋清楚；頭髮、布料、浮游武器有合理的局部活動。腳不滑、鋼鐵不扭、人物不呈水波。
- 出招：先蓄勢、再發力、命中、收勢；物攻人物必須接近對手並有武器動作。第五技能身分由資料指定，不能自行當成特攻。
- 受擊：有承力、反應和回復；頭、腳和武器完整，不能突然換臉或換畫風。
- 額外行動：要看得出又做了一次事；蝕言以開書、飛頁、對手封印為主。幻化要等新外觀就緒並留辨識時間。
- 朝向：P1 朝右、P2 朝左；看頭、眼、握持與出手方向。靜態與動態分別核對，不連帶翻動另一份來源。
- 特效：落在對手身上；大爆炸可以遮場，但不能長期蓋住頭像、技能和角色。黑框、純色塊、模糊放大都不通過。
- 回位：出招後回到同一地面與大小；加速後依然命中、收尾，不跳過整段演出。

最低覆蓋：四隻 × P1/P2 × 待機/物攻/特攻/屬性/第五/額外行動/受擊，
並補 1、2、5、10 倍速、常用桌面視窗與窄螢幕。每格標「通過、失敗、未測」，不可填估計數字。

## 三、美術製作

1. 先保存完整原稿並檢查去背：在深、淺底各看一次，核對頭髮、武器、浮游物和半透明特效是否被誤刪。
2. 待機優先保留原畫像素。允許有遮擋補底的剛性分層與合理關節活動；禁止用整圖平移或連續波紋冒充身體動作。
3. 新姿勢以原圖作直接參考，明確要求同一張臉、材質、衣紋、武器與畫風。每次補一個動作節點，別一次重畫成全新設計。
4. 透明輸出可用，但必須檢查外圍灰霧。若改用純色背景，顏色必須避開角色色盤；不是所有角色都適合品紅或綠幕。
5. 共用畫布、腳底線與合理頭身尺度；不能每張各自塞滿外框。低姿勢身高降低是動作，不應重新放大填滿畫面。
6. 原檔只作一次對位取樣；保留高解析來源，別從已縮小圖集反覆裁切、放大、再壓縮。
7. review.accepted 目前只表示允許匯入試播，舊檔很多 note 仍寫待驗收；不能據此宣稱玩家品質合格。
8. 不合格圖保留為版本檔，寫明原因。不要把失敗圖直接替換原畫。

四隻的分鏡方向：
- 帝辛：金紫黑，蓄劍、踏步、近身刺斬、回位；不要讓第五退回站樁施法。
- 六刃：黑鋼暗綠，取劍、壓重心、人物衝近、揮砍、還劍；持劍加浮劍總數六把。
- 蝕言：保留幽魂與書，額外行動用飛頁與對手側束縛；不是永遠轉圈的發光物。
- 墜星：完整原稿，抬砲向上、射出、對手上方落砲、爆炸擴張、煙塵退去；保留浮游武器。

內建產圖工具可直接編輯來源圖，不需另設 API key；若透過 ChatGPT 應用程式，遵守使用者指定的對話模式。
每張保存來源、參考圖、完整提示詞、生成日期和人工檢查結果。生成成功不等於通過。

## 五、官方特效取得與清晰度

資料來源與指令見 tools/fx-extract/README.md。
官方動畫包有出招及特效，不能因為只查到立繪倉庫就說沒有。
素材包、材質包與逐格輸出存本機快取；正式專案只放真正使用的整理後特效與來源紀錄。

- 材質缺少會出純色塊；先核對 materials.bin，不用色塊圖繼續製作。
- 去除本體須檢查所有出招影格；只比較待機部位不是百分之百成功的保證。
- 本輪舊圖表單格最長只有 260 像素；不得把這張 JPEG 放大後標成 HD。
- 要變清楚須從動畫包重匯出，再以實際螢幕大小決定格尺寸。512 是本輪候選值，不是所有素材的硬性標準。
- JPEG 黑底轉透明不是完全等同官方加法混合；須在實際背景比對，不能只在黑底看。
- 特效換色不能代替分鏡設計。六刃物攻用斬痕，墜星用落砲和爆破。
- 最亮格以 peak 精確對齊命中。浮點 rate/lead 四捨五入可能差一格，不能只看平均時長。
- 同時計算下載量與解碼後記憶體；較小檔案不一定比較省記憶體。

## 七、發佈及回復

先乾跑：

    node scripts/publish_custom_animation.mjs --id <id> --source build/<候選版本>

再正式套用：

    node scripts/publish_custom_animation.mjs --id <id> --source build/<候選版本> --publish

工具會檢查圖集、同步登記，並備份舊資料夾。現在也會搬移劍、書頁、幽魂手掌等附屬素材，
把 /__animation-drafts/ 網址轉成 /elf-anim/；不能只搬 atlas 和 manifest。
發佈後重新跑正式來源完整性測試，實際開一次不帶 draft 的網址，再進行建置。
桌面須等作用版本切換、日誌 EXIT 0，並核對正式素材雜湊；只有來源改了不能說桌面已更新。
Windows 的預覽檔案監看可能暫時鎖住素材資料夾。本輪曾因此發佈 rename 失敗，工具已回復舊資料；
停止自己啟動的預覽服務後才重試成功。不要關閉玩家視窗、刪除舊檔或繞過備份來強行發佈。
不要自動關閉使用者的遊戲視窗。網站與 GitHub 是否更新分別記錄，不以推送代替網站驗證。

## 避免「高清但仍像低畫質」的驗收缺口

- 記錄角色單格有效像素、實際可見高度及畫布像素；圖集 4000px 不代表其中每個人物也是 4000px。
- 同時查看原待機、取武器、出招、收招：明暗、盔甲材質、輪廓不同時，即使檔案解析度高也不能過關。
- 補畫須以原圖作畫風主參考，上一張補畫只作姿勢參考，避免每生成一次就離原圖更遠。
- 透明輸出仍需核對半透明灰霧與發光底，不能看到 alpha 通道就當乾淨去背。
- 多武器演出須同時核對人物持有的武器及旁掛武器；隱藏的旁掛劍不能仍算作可見命中，也不能讓持劍與旁掛層重複成七把。
- 可播放、數學路線正確、正式套用、桌面包含、玩家品質通過，分開記錄。尚有明顯畫風差異的候選不因測試全綠就直接發佈。

### 截圖與六劍的驗收證據

截圖與 DOM 讀取非同一時刻，記錄前後 side／sequence／frame；第一張若是舊 UI 就不能用該張判斷格號。計算六劍應合併「人物圖內持劍＋實際浮劍繪製」，不能只數幾何函數回傳幾筆。實播證據應涵蓋雙側普通物攻、第五及回位，未取樣處明列。

驗收工具應在開始出招時自動收起；先關掉戰報等遮擋，再取樣。不要先出招才等一次關工具操作，否則短額外行動可能已播完。漏採樣只能記為未取到，須重測，不能推論播放器跳過。支援陣形除了測路線函數，還要檢查配置實際到達繪圖層；畫出六把與玩家看得清六把仍是兩個驗收項目。

補過渡圖時固定上一張已選姿勢的身體朝向、腳位、比例及披風輪廓，只改所需肢體；泛稱「畫兩姿勢中間」容易重新設計全身側面。明顯轉向或灰霧稿須標淘汰、保留來源，不能塞入正式序列。達到取樣張數上限也不等於回合結束，要另確認 UI 回到下一輪選擇。

透明圖預覽若顯示灰／金／紅底，先量該區 alpha，再放在實際背景看。alpha=0 的 RGB 不會顯示，極低 alpha 邊色與可見實心破邊分開處理。簡單紅色比例判斷可能誤殺紫衣或金甲，不可直接用來刪色。

正式技能列與工具按鈕不同：雙人預覽需要雙方都選招。isEnabled 不能證明已跑完，必須核對回合及選招提示；只有待機樣本不構成動畫失效證據。

候選整合必須繼承正式素材的 poseBlend 等演出開關，不只複製 presentation。否則正式已取消的雙身殘影會在重建候選時重新啟用。取樣時至少檢查一個姿勢切換畫面。

武器若獨立於人物飛出，出發點要從待機站位取得，不可隨突進姿勢的可見框持續平移。驗證應讓人物位置與寬度改變，檢查畫布實際繪製座標，再在正式場地看雙側出手／回位；純路線計算不足。

### 幻化後的動畫等待（2026-11-09）
