# 自製動畫技術選型與改進方案

2026-11-05。範圍：本機製作流程檢查、開源專案及官方文件研究。這不是新動畫或正式對戰畫面的驗收報告。

## 目前結論

主要缺口是姿勢、美術結構與動作因果，不是影格不足。現有播放器可以保留；不宜繼續靠增加整圖位移、部件旋轉與光效，把同一姿勢延長成出招。

建議採用「補畫關鍵姿勢＋局部骨架＋必要部位換圖＋獨立場地特效」。AI 可協助生成姿勢草稿和過渡，但應先挑選修整，再交給遊戲播放，不在戰鬥時即時生成。

## 證據與限制

- 本機既有抽樣圖與程式檢查見《自製動畫重製規格_20261105.md》。出招抽樣多為同一身體姿勢，位置、光圈與砲的變化多於肢體變化。
- 本次重新核對 `scripts/lib/skeletalRig/rigCore.mjs`：權重主要按頂點到骨段的距離分配。這是自動初稿，不能保證肩肘、臉與裝甲的合理變形。
- `scripts/lib/skeletalRig/motion.mjs` 尚有要求起步立刻可見變動的舊註解。應改以動作意義評估，蓄力停頓不應被當成缺陷。
- 墜星原圖是雙手持砲，必須保住兩手與握把的接觸，不能當浮游砲移動。
- 前一階段已製作收斂旋轉的待機草稿，但尚未替換正式動畫，不能說桌面與網站已停止旋轉。
- 已讀原廠素材的部分播放資料；雷伊物攻、星光雷納多特攻的固定尺寸逐幀視覺比較仍未完成。沒有證據宣稱已還原官方製作流程，也不能把第三方查看器當官方 U 端程式。
- 本次未安裝以下工具或模型，未量測它們在使用者電腦上的速度、顯示記憶體需求或生成品質。

## 從玩家角度看，差異在哪裡

| 目前成品的問題 | 玩家需要看到的事情 | 改進方向 |
|---|---|---|
| 整個人漂動，但沒有明顯換姿勢 | 先準備，再發力，最後收勢 | 先畫可辨識的關鍵姿勢，不先湊影格數 |
| 砲在動，手和肩沒有合理配合 | 手握住砲，身體承受重量與後座力 | 增加肩、肘、腕控制；握把與手位置互相約束 |
| 拆圖後露縫、裝甲被拉長 | 不管停在哪一格，身體結構都完整 | 補畫被遮住部分；大幅轉角另畫，不硬拉原圖 |
| 待機物件不停轉、全身同拍晃 | 安定地準備戰鬥，少量呼吸與配件延遲 | 為每個運動設定原因；機械環沒有運作需求就不旋轉 |
| 發光與角色動作是兩套時間 | 砲口先發射，之後對手中招並出現傷害 | 開火、飛行、命中、收招共用明確時間資料 |
| 特效越大，角色反而越小 | 同皮膚靜態、待機、出招的身體尺度一致 | 固定角色支點與尺度，不按每幀包含特效的外框重新縮放 |

右欄是本專案的品質目標，不是對所有官方精靈製作方法的斷言。

## 技術選項與可借用專案

### 一、分層與網格變形：適合待機及有限幅度的動作

[Live2D 官方素材處理教學](https://docs.live2d.com/en/cubism-editor-tutorials/psd/) 明確要求補上原圖被遮住的區域，否則移動後會斷開。它也提供分層素材與範例模型。

對本專案的建議：借用素材準備與變形控制方法，先處理呼吸、頭髮、披風和小幅轉動。工具本身不會自動補出抬砲後的手臂與裝甲；大幅換視角仍需另外畫稿。不要再把複製邊緣像素當成補畫。

### 二、骨架、接觸約束與換圖：推薦的主流程

[Spine IK 官方說明](https://en.esotericsoftware.com/spine-ik-constraints) 展示用手或腳的目標位置控制肢體，可避免身體移動時手腳跟著滑走。參考程式在 [spine-runtimes](https://github.com/EsotericSoftware/spine-runtimes)。整合須遵守其[專用授權](https://github.com/EsotericSoftware/spine-runtimes/blob/4.2/LICENSE)，不能當一般無條件免費套件。

[Godot cutout 官方教學](https://docs.godotengine.org/en/stable/tutorials/animation/cutout_animation.html) 提供 GBot 素材與層級、支點示範，並明確介紹骨架與逐格換圖混用，複雜手腳、表情可以換成其他畫稿。該頁目前提示尚未全面更新至 Godot 4.7，實作時需要核對所選版本操作。

對本專案的建議：借用這種混合流程，不要求整個 React 專案改成 Godot。可研究用編輯器製作後輸出既有播放器可接受的素材；具體轉換流程尚未驗證。若繼續使用目前自製骨架，則補上肢體控制、接觸約束與人工修正權重，而不是只增加骨骼數。

### 三、AI 生成兩姿勢間的過渡：先小規模試 ToonCrafter

[ToonCrafter](https://github.com/Doubiiu/ToonCrafter) 以兩張卡通圖片生成過渡，也有草圖引導範例。可研究「原待機姿勢 → 雙手抬砲朝上」這一段。

判斷與風險：它適合試作，不保證本角色的手指、砲身與裝甲逐幀一致。應先準備兩張設計一致且姿勢真正不同的圖，不把同一張圖縮放兩次當關鍵姿勢。不先一次生成六格整張圖，以免每格角色設計漂移。官方示範的解析度也不能直接當成本專案大型立繪成品品質。

### 四、以示範影片帶動角色：Wan2.2 Animate 作進階候選

[Wan2.2](https://github.com/Wan-Video/Wan2.2) 的 [Animate 前處理指南](https://github.com/Wan-Video/Wan2.2/blob/main/wan/modules/animate/preprocess/UserGuider.md) 說明從參考影片取姿勢，以及不同身體比例需要調整；官方也提示姿勢與角色一致性不保證完美。

對本專案的建議：可先拍攝或用簡單 3D 人偶做出雙手抬砲、後座、回穩的示範，再生成草稿。這是候選實驗，尚未證明能可靠處理墜星的巨大武器，也不推論能處理咤克斯等非人型。3D 人偶可只當透視和姿勢參考，不必改成 3D 遊戲。

### 五、補幀與深度視差：補助工具，不當出招主力

[RIFE](https://github.com/hzwer/ECCV2022-RIFE) 用來生成圖片或影片之間的中間影格。對本專案的判斷：應在姿勢和節奏正確後使用；它不能代替設計原本不存在的抬手動作。

單張圖的深度視差可製造前後層移動與小幅鏡頭感，但仍缺少遮擋後畫面。對本專案而言，不建議用它取代關節動作或出招姿勢。

### 六、砲擊、落雷與受擊特效：角色動作通過後再加

[Effekseer](https://github.com/effekseer/Effekseer) 可製作特效；目前 [EffekseerForWeb](https://github.com/effekseer/EffekseerForWeb) 提供 WebGL／WebGPU 瀏覽器播放範例。可研究墜星由上而下的落砲、六刃黑綠刀光與對手受擊。

它解決的是特效製作與播放，不會讓原本沒抬起來的手自動抬起。暫不替換現有特效層，先用單一效果驗證與 Pixi 的繪製順序、大小、加速及資源釋放。載入與運行成本須在實機測，不預填效能數字。

### 七、原廠素材參考：查看器有用，但不是生成工具

[seer-pet-viewer](https://github.com/Nattsu39/seer-pet-viewer) 支援查看 Unity 精靈待機／出招素材，並有預轉換成播放資料及圖集的功能。它適合輔助取得現有動作參考，不能從自製靜圖創造新出招，也不代表已取得官方創作原稿。

## 下一次墜星試作的具體流程

1. 固定原稿與角色設定：雙手持砲、白髮、裝甲、披風、砲身形狀，保存原圖與版本。不先改畫風或堆光效。
2. 先做兩張無特效姿勢：原待機與向上瞄準。兩隻手、握把、肩肘、支撐腳都合理，角色大小與支點相同。先過這一關，再做發射後座與回復。
3. 根據姿勢補畫隱藏部位；分出必要手臂和武器層。拼回原姿勢與極限姿勢都不能缺肉、重複輪廓或拉長裝甲。
4. 骨架負責有限幅度的中間動作，大幅砲身透視與手勢用替換畫稿。若測 AI，先只試上抬一段，保留失敗影格，不直接發佈生成影片。
5. 固定角色尺度、腳底與砲口位置。AI 輸出若有背景，另做逐幀一致的透明處理；不假設生成模型直接提供可用透明素材。
6. 關掉光效看完整動作。玩家應看懂「向上發射 → 受到後座力 → 砲擊由上方落到對手 → 回穩」。看不懂就回去修姿勢，不用粒子遮蓋。
7. 最後加入獨立砲口、飛行、落點、受擊。明確記錄開火與命中，不用影片自動猜傷害時點，傷害仍依現有戰鬥結算顯示。
8. 在正式對戰尺寸測 P1／P2、普通／大型對手、靜態切換與 1／2／5／10 倍速。動畫與靜態朝向分別核對，只鏡射一次。
9. 比較原廠雷伊與星光雷納多對應動作，保存固定時間點的畫面和短片，再判斷是否通過。這個逐幀參考步驟仍未完成。

## 發佈與檔案控制

製作工程、AI 模型與失敗草稿不隨遊戲發佈。正式包只包含選定成品及播放資料；模型本機或遠端生成，均不代表要讓玩家下載模型。

角色畫面與可重用場地特效分開保存；評估圖集壓縮、按需下載及快取。磁碟檔案大小和播放時解壓後的記憶體用量分開量測，不能只看 PNG 或影片很小就推論播放輕巧。

本次只新增此研究文件，沒有安裝工具、替換正式素材、修改戰鬥邏輯、重建桌面或更新網站。
