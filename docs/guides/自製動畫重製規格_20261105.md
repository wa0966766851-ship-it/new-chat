# 自製動畫重製規格與問題盤點

2026-11-05。範圍：自製動畫為何像晃動的靜圖，以及下一版怎麼做。不是新動畫已完成的驗收報告。

## 結論與證據範圍

使用者的觀察成立。過度平移只是外觀，根本是缺少足以表達出招的新姿勢，再以整圖位移、部件旋轉和光效填滿時間。拆圖後沒有補出被遮住的部分，增加幅度還會露出破綻。

本次重新產生並查看 `docs/custom-anim/preview/wuxu_zhuixing-sa-sheet.png`：六個抽樣畫面的主要身體姿勢接近，砲、光效與位置變化多於出招姿勢變化。抽樣圖不能代表中間每幀都正確，也不足以驗收細縫。

另查看六刃既有 `docs/custom-anim/preview/liuren-attack-sheet.png`，也是近似同一姿勢配光圈；這是歷史預覽，不冒充目前所有片段的重新驗收。

程式檢查範圍：`scripts/build_custom_animation.mjs`、`scripts/lib/skeletalRig/{parts,motion,rigCore}.mjs`、`src/battle/customBattleFx.ts`。實際解析本機原廠雷伊、星光雷納多素材，能讀出待機影格與材質；尚未完成兩者出招的逐幀畫面比較，不能宣稱已還原 U 端製作流程。

本次只產生預覽及修正文檔；沒有替換正式動畫、修改靜態圖方向／大小、改戰鬥機制，沒有發佈桌面或網站。現有播放器與落點能力可保留，但角色動作需要重製。測試通過不等於自然或帥氣。

## 已確認的問題

| 問題 | 依據與影響 | 修正方式 |
|---|---|---|
| 整圖運動代替表演 | 通用製作器 sprite 主要是整圖移動、縮放、旋轉；能滑動但沒有抬手、支撐、揮刀 | 先畫關鍵姿勢，再補中間動作 |
| 墜星拆分不足 | 有軀幹、頭、砲、腿和配件，沒有獨立上臂／前臂／手腕，難以表現配合抬砲的動作 | 先看原稿確認砲是肩載、手持或浮游，再建立合理連接；不要憑骨骼名稱猜結構 |
| 接縫只靠擴張邊緣 | bleed 複製鄰近原圖像素，沒有提供完整遮擋後畫稿 | 補畫被砲、頭髮或手臂遮住的身體，建立前後層；不以光暈遮裂縫 |
| 像素全保留仍可能切錯 | fillUnowned 可把像素都分出去，卻不能保證臉和裝甲歸屬正確 | 彩色部件圖、零姿勢拼回圖、極限姿勢局部圖一起檢查 |
| 多部件同拍擺動 | 墜星多條軌道在近似影格一起移動和回彈 | 區分施力、後座力、配件延遲與停止；允許有意義的停頓 |
| 砲口光不跟砲走 | 場地特效按整個可見框的固定比例定位，沒有讀武器逐幀位置 | 砲口與發射方向跟著武器變換 |
| 開火有兩份時間 | sa 的局部開火設在第46幀，場地特效由命中58幀推算成48幀出發 | 明確記錄開火與命中；不由命中倒猜開火 |
| 追求每幀都動 | 動作註解把開頭數幀不動當成缺點，排除某種緩動 | 看停頓有沒有蓄力意義；不用像素變動率判斷品質 |

46／48／58 是目前設定比較，不是錄影量得的延遲，也不是全部異樣感都由兩幀差距造成。

## 參考原廠時，先排除錯誤推論

素材解出的頂點、貼圖與命中標記是播放資料，不等於原廠美術原稿、骨架或完整創作流程。

- 一個矩形也能逐幀換姿勢圖片，不能說「待機只有一個矩形，所以只縮放」。
- 多頂點網格可以播放真實動作，也可以只搬動同一張圖；網格數和影格數不能證明自然。
- 本專案的 `petClipPool.ts`、512 MiB 預算、Worker 是本專案／第三方工具做法，沒有證據能說是官方 U 端優化。
- action_hit 之前可能有前移、揮擊與飛行，不能全部稱為蓄力。

下一步原廠參考選雷伊物攻、星光雷納多特攻，固定相機和尺寸，取起手、蓄力、發射、命中、回復。逐項記錄姿勢、腳底、武器、停頓與特效，附來源影格；沒看過的部分標未確認。這一步尚未完成，解析成功不能替代。

## 重製順序

### 第一關：只做墜星一招，先六個姿勢、不要特效

玩家不看傷害數字，也應看懂「準備向上射擊、承受後座力，再由上而下轟中對手」。

| 姿勢 | 必須看得懂 | 不能用什麼代替 |
|---|---|---|
| 準備 | 支撐身體，砲開始朝上 | 整張圖向後漂 |
| 瞄準 | 砲與連接結構一起抬起，視線合理 | 只轉砲，肩膀或手還黏在原處 |
| 蓄力 | 姿勢短暫穩住，能量集中 | 全身持續左右擺 |
| 發射 | 先發射，再沿砲軸後座，支撐處承受衝擊 | 先抽動，再從別處出光 |
| 落砲 | 對手身上有清楚的由上而下砲擊與受擊 | 打在中間，或收招後才跳傷害 |
| 回復 | 武器與身體回穩，配件稍後停止 | 全部同拍彈回，最後瞬移復位 |

先看正常對戰大小下的無光效輪廓。仍像六張相同姿勢就回去改畫稿，不進入補幀。大幅透視變化應另外畫姿勢，不能拉長貼圖代替。

### 第二關：做能動的素材，不是只把圖切碎

依結構分出頭髮、身體、武器與連接裝置、必要的前後手臂、腿腳、披風、浮游配件和光效。砲若本來浮游就不硬接手，若肩載則不能脫肩。補畫原本被遮住的區域。

交付原圖、彩色部件歸屬圖、零姿勢拼回圖，以及最劇烈姿勢的臉／肩／腰／關節放大圖。正常速度不能看見接縫，慢放與暫停也不能有缺肉、重複五官、裝甲被扯走。

### 第三關：姿勢通過才補動作

落地腳掌固定接觸位置；浮空角色另訂支撐方式。武器與連接處保持合理距離，必要時切換前後遮擋層。身體發力後，披風與配件跟隨，不是每個部件加同頻晃動。受擊依受力方向反應。

不先訂必須96幀，先決定準備、停頓、發射、回復的節奏，再決定長度。

### 第四關：動作、砲口、飛行、受擊共用明確事件

需要新增的製作資料（尚未實裝）：準備／開火／命中／回復時間、逐幀砲口及方向、目標命中點、可銜接下一動作的時點。

砲口從武器位置經角色縮放、P1／P2鏡射一次後取得，不能固定在整體框的比例。本體閃光、飛行、落砲和對手受擊使用同一時間軸。傷害仍讀既有戰鬥結果，不由動畫重算；主要攻擊與附加傷害按原結算順序顯示。速度、跳過、換人與死亡沿用既有控制。

### 第五關：完成一招後再擴展

| 精靈 | 重點 |
|---|---|
| 墜星 | 上射落砲、合理連接、支撐與後座力 |
| 蝕言 | 以額外行動為主，機械環實際展開／重組；普通技能收斂 |
| 六刃 | 黑色帶綠刀刃，獨立刀身及前後遮擋；蓄勢、斬擊、歸位可辨，不是抱臂圖滑向對手 |
| 帝辛 | 武器揮動連同手臂、重心、收勢；光線強化真正的斬擊方向 |

沒有素材支撐的動作標記缺素材並補畫，不用換名稱把整圖平移視為完成的專屬出招。

## 放行標準

1. 先1倍看完整動作，再檢查2／5／10倍；加速不能用來藏破綻。
2. 關光效仍看得懂起手、主要動作和回復。
3. 臉、頭、關節完整；武器不脫離連接處，配件不帶走身體邊緣。
4. 站定的腳不滑地；漂浮、衝刺與受擊都有原因。
5. 閃光、飛行、命中因果順序成立，落點在對手身上。
6. 正式 BattleScreen 以1920×1080及1366×768看P1／P2、普通／大型對手；不能只驗收獨立小畫布。
7. 同皮膚切靜態時大小接近，不因特效擴大外框而縮小本體。靜態方向獨立保留，不跟著動畫亂改。
8. 載入失敗回退、換人、跳過不卡戰鬥。
9. 保存同版本無光效短片、完整演出短片、接縫局部圖及通過／失敗記錄；截圖或測試全綠不能替代觀看。
