# Aegis Shell — 雙殼架構計畫（PLAN）

> 本文件是**規格**，不是進度紀錄。進度看 `PROGRESS.md`。
> 衝突時的優先級：**本文件 > KIT.md > 程式碼現況**。

## 1. 為什麼要做

現有介面是「**有遊戲皮膚的對戰配置工具**」：側欄 + 表單 + 密集數值卡。
它服務的是**編輯與除錯**，不是**玩**。

目標不是取代它，而是**長出第二層皮**：

- **Legacy Shell**：現有桌面工作台。保留、不動、繼續更新。
- **Aegis Shell**：手遊風介面。大廳 → 編成 → 戰鬥 → 圖鑑，單手可完成。
- 兩者**共用同一份狀態**（`ShellBridge`）與**同一份功能註冊表**（`SHELL_FEATURES`）。

## 2. 鐵則：舊版不得落後

這是整個專案唯一不能妥協的規則。

| 規則 | 實作 |
| --- | --- |
| 新功能必須先登記 | 任何新畫面／覆蓋層／動作，先在 `src/shell/features.ts` 加一筆 |
| 登記後兩殼同時可見 | Aegis 導航由 `aegisNavFeatures()` 生成，不是手寫清單 |
| 未重寫的畫面直接委派 | `aegis.status = "delegated"` → Aegis 內嵌 Legacy 畫面，功能 100% 相同 |
| 不得回歸 | `legacy` 一旦為 true 不得改回 false（`npm run check:parity` 會擋） |
| 重寫才移除委派 | 把畫面改寫成原生時，`status` 改為 `live`；此時該畫面才脫離 Legacy |

**推論**：只要遵守這條，Aegis 永遠不可能比 Legacy 少東西——
它最多是「比較醜」，不會是「比較少」。

## 3. 三種畫面（借鏡 world.execute(me) MV）

MV 的規則是「整支片是一場對話，用三種畫面說」：

| MV | Aegis | 用途 |
| --- | --- | --- |
| 介面 | **大廳／編成** | 玩家操作的主體，資訊密度低 |
| 版畫 | **戰鬥演出** | 全螢幕、情緒化、裝飾性 |
| 程式碼 | **除錯／測試** | 只有開發者會看，收進二級 |

規則：**版畫（戰鬥演出）必須由「玩家的一個動作」開始，由「一個事件」結束**，不能無緣無故出現。

## 4. 顏色 = 狀態

借鏡 MV 的 `config.json → palettes`：顏色不是裝飾，是狀態。

```
idle     待機（首頁、未開戰）
lobby    大廳（編隊中）
battle   戰鬥中
victory  勝利
defeat   敗北
error    錯誤 / 載入失敗
```

- 每個狀態是一整套色票（`src/design/palette.ts`）。
- **元件禁止寫死 hex**，只能引用角色：`var(--p-accent)`、`var(--p-text)`…
- 換皮 = 改 `palette.ts`，不是改 200 個檔案。

## 5. 動效 = 拍點表

借鏡 MV 的 `cues.js`（56 個拍點，每項標明「實測 / 初值」）：

- 所有時長集中在 `src/design/cues.ts`。
- 每項標記 `source: measured | spec | initial`。
- 調整手感只改這個檔；`unmeteredCues()` 列出還沒實測的項目。

## 7. 階段

| Phase | 內容 | 驗收 |

| 4 | 手遊戰鬥 HUD | 橫屏單手打完一場 6v6 |
| 5 | 手感打磨 | 轉場、音效、觸覺、reduced-motion |
| 6 | 打包 | PWA / Capacitor |

## 8. 不做的事

- **不改後端**：`server.ts`、`electron/`、`scripts/`、`tools/`（除驗收工具）一律不動。
- **不改戰鬥引擎**：`src/engine/`、`src/effects/` 不動；Aegis 只換呈現。
- **不引入 3D 引擎**：CSS 3D / 局部 three.js 即可。
- **不重寫 Legacy 畫面**：Legacy 只做「外框抽出」，內部元件零改動。
