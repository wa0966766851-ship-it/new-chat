# 技能欄與第五技能規則

給之後實裝新精靈的 AI／開發者。判定與排序的唯一來源：`src/battle/skillSlot.ts`。
回歸測試：`tests/skillRowRules.semantic.test.tsx`（`npm run test:skill-row`，已併入 `test:ui`）。

## 規則

1. **第五技能由資料旗標 `isFifthSkill: true` 決定**。格位、威力（例如 ≥160）、名稱（含「第五」）都不能用來推定。
2. **規範資料格式：`skills` 恰 5 招，4 招普通在前，第五技能放 `skills[4]` 並帶旗標。** 多的招式放 `skillPool`。
   - 沒有第五技能的精靈（目前只有 5020 皮皮）整列都不帶旗標，主列仍是 5 招。
   - 主列最多一個旗標；`skillPool` 內與主列同名的招，旗標必須一致。
3. **兩種視圖，順序不同：**
   | 視圖 | 順序 |
   |---|---|
   | 戰鬥技能列（`BattleScreen.ui.tsx`）、戰鬥資訊唯讀檔案（`ElfReadOnlyProfile`）、精靈介紹（`ElfSpotlight`） | 有第五技能時**第五在第一格**，其餘維持相對順序 |
   | 倉庫／背包詳情（`StartScreen`）、編輯器、隊伍面板 | **資料順序**（第五在最後一格），第五以「第五技能」標記區分 |
   `tests/teamWorkspace.ui.test.tsx` 鎖定倉庫順序，不要改成第五置首。
4. 第五置首的視圖一律呼叫 `orderSkillsForDisplay(skills)`（資料）或 `orderBattleSkillsForDisplay(elf.skills, visibleSkills)`（戰鬥，帶 `battleSlot`），不得自行寫「slot===4」「power>=160」之類判斷。畫面位置與資料格位分離：點選／扣 PP／換招一律用 `slot`（`battleSlot`），不是畫面位置。
5. 存檔與匯入：
   - 內建精靈的舊存檔缺旗標時，`applySavedSkillCorrections` →（`restoreBuiltinFifthFlags`）依預設資料補回；主列已有任何旗標（玩家自選）不動；`custom_` 自訂精靈不推定。
   - 文字匯入（`parseFullElfData`）只認明確「第五」標記，並以 `canonicalSkillRow` 整理成單一旗標、滿 5 招時置於 `skills[4]`。
   - 圖紙匯入保留原資料，顯示端仍由共用函式排序。
6. PP：`pp` 為非負整數；`maxPp`／`currentPp` 若有必與 `pp` 相同；`pp: 0` 只允許 `ppUnlimited: true`、`maxPp: 0`（原廠 0/0）或描述明載 PP 規則。技能石只能佔前四格，不能覆蓋第五。

## 新增精靈檢查表

- `skills` 寫滿 5 招：`[普通1, 普通2, 普通3, 普通4, 第五技能]`；第五技能加 `isFifthSkill: true`（`createRefSkill(..., { isFifthSkill: true })` 或物件欄位）。
- 同一招若也放進 `skillPool`（備選／替換庫），池內副本也要帶 `isFifthSkill: true`。
- 原廠沒有第五技能的精靈：不要標任何旗標，並把測試中的 `noFifth` 清單（只有 `5020 皮皮`）明確加上該精靈與理由——漏標會被測試擋下，這是刻意的。
- 不要為了顯示在第一格而把第五技能放到 `skills[0]`；顯示順序交給共用函式。
- 實裝後跑：`npm run test:skill-row`、`npm run test:jiuqing`、`npm run test:ui`。
