# 幻化取得魂印與下場作用域（2026-10-08）

## 處理範圍及根因

確認工作樹、TXT及正式註冊表後，修正幻化取得積木魂印的共同接點。保留既有未提交更動；沒有新增精靈專屬 BattleScreen 分支，沒有推送或打包。

觸發：幻化存續期間的回合事件、使用技能及異常附加。來源：目標資料ID決定魂印模式與程序。持有者：所有實際變動仍結算在原精靈的戰鬥身分。

先前只改取得魂印context的名稱，卻用原精靈ID查SOUL_MODE，漏掉僅用ID登記的積木魂印；使用技能及異常附加的獨立積木接點也未執行取得魂印。

現在分離來源與持有者；只跑來源魂印，不再次掃側邊timer／印記。全積木來源跳過殘留手寫handler，部分積木來源按子句索引執行。解除後不再讀取取得魂印。

## 能力快照確認

使用者確認取目標「當下能力」。自身原攻擊100，目標原200、幻化後300，取得結果400。保存當次300快照；目標先解除回200，自身解除仍扣300回100。雙方依序幻化導致不同加成不因此判為bug。原能力計算不改，只新增雙側數值斷言。

- `src/blocks/registry.ts`：取得魂印專用事件入口、技能使用與異常附加接點。
- `src/effects/battleEventRegistry.ts`：模式查目標ID，避免全積木來源跑舊handler與重複掃持續效果。
- 新增 `tests/illusionSoul.semantic.test.ts`：正式Vite註冊表及積木執行器的12個雙側情境，測來源識別、持有者、獨立接點、殘留handler、解除、不重複timer與混合模式子句。使用刻意設計的可解析魂印文本，不代表所有官方魂印組合已驗收。
- `tests/illusionPresentation.semantic.test.ts`：12擴充為20情境，增加雙艾斯菲亞／艾斯菲格幻化中主動下場與驅逐，核對能力、PP偏移、技能、圖片及下一隻隔離。下場原有邏輯不改；驅逐不新增普通登場／下場鉤子。
- `tests/hamoShiyanIntegration.semantic.test.ts`：39擴充為43正式情境，增加第五技下次無效、同類封鎖的雙側主動換人隔離。
- `tests/newElves.semantic.test.ts`：目標當下能力與解除快照斷言；全檔44個檢查通過。
- `package.json`、`docs/README.md`：納入統一測試與文件入口。
- 稽核證據及產物：只有實際重測後才核對指紋，不升級為全句驗收。
