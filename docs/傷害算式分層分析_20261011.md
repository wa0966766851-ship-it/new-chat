# 傷害算式分層分析（2026-10-11）

目的：盤點攻擊技能傷害及其他各類傷害的算式，並標出每種效果目前在哪一層發作，對照使用者提出的分層想法：

1. 先算公式（忽略雙防、雙攻等在公式裡動手腳）。
2. 公式被替換時（例如「只能造成特攻值的傷害」），不論怎麼算結果都換成這個值。
3. 增傷統一算完後一次加上。
4. 再套減傷。

行號以 2026-10-11 版本為準。BE＝`src/engine/battleEngine.ts`，DC＝`src/utils/damageCalculator.ts`，CB＝`src/battle/contextBuilders.ts`。只做分析，尚未修改。

---

## 1. 攻擊技能傷害：目前實際的層次

| 層 | 內容 | 位置 |
|---|---|---|
| **L1 公式輸入** | 攻擊值、防禦值、能力等級、威力、克制、本系 | DC:39-131 |
| **L2 公式替換** | 有替換公式時直接回傳，跳過 L3 | DC:115-116、`specialDamageFormulaRegistry.ts` |
| **L3 公式本體＋公式內乘區** | `[(Lv×0.4+2)×攻×威力÷防÷50+2]` ×本系×克制 → ×浮動 → ×暴擊 → ×套裝／稱號造成倍率、×對方套裝受到倍率、×刻印「強化」1.2 → ×寶石 → ×連擊數，每步取整 | DC:133-185 |
| **L4 增減傷池** | `base ×(1+增傷加算池)×(1−減傷合成)×乘算池 − 固定減免` | BE 3.5 段；CB 各 API |
| **L5 上限／保底／加減固定值** | 上限（limit、200 上限、受擊方單次上限）→ ＋bonusFixed → 保底 floor → 自身輸出上限 → 手下留情 | BE 3.5 段末 |
| **L6 落地** | 死亡守護 → 傷害抗性（暴擊／固定／百分比）→ **印記倍率（只有攻擊傷害在這層）** → 護盾／護罩 → 存活規則 → 抵抗致死 | BE `executeEffect('damage')` |

### 1.1 L1 公式輸入：哪些效果在公式裡動手腳

| 效果 | 鍵／來源 | 作法 |
|---|---|---|
| 雙攻合一 | `blkAtkSpatkSum` | 攻擊值＝攻擊＋特攻 |
| 臨時攻防倍率 | `calcAtkDefMult` | 自身雙攻／對方雙防乘倍率 |
| 對手攻擊變為面板比例 | `opponentAtkPanelRatio` | 覆寫攻擊值，忽略能力等級 |
| 忽略防禦％ | 特質 `ignoreDefPercent`、`ignoreSpDefPercent`（僅特殊）、`ignoreSpDefPercentUntilSwitch`、`ignoreDefPercent`、套裝 `ignoreDefSpdefPercent` | **多個來源取最大值，不相加**；防＝floor(防×(1−％)) |
| 忽略固定防禦 | 套裝 `ignoreDefSpdefFlat` | 防−N |
| 核能機甲 | 受擊方體力＜⅓ | 防×2 |
| 能力等級 | 視為下降、詩章、無視對手提升、自身下降轉移、`blkStageAsBoost` | 改等級後換算 |
| 弱點傷害 | `weakPointDefenseTurns` | 防＝min(雙防)×60％ |
| 威力倍率 | `powerMultiplierThisAction` | 威力×N |
| 克制 | `attackTypeOverride`、`targetTypeOverride`、`fixedTypeMultThisAction`、`minimumTypeMultiplierThisAction`、`noResistedThisAction` | 改屬性或倍率 |
| 本系 | `grantStabThisAction`、投石者＋寶石 | 強制 1.5 |

問題：
- **`ignoreDefPercent` 被套用兩次，其中一次不分物理特殊**（DC:64-70），所以特殊攻擊也被削了物防的比例。`ignoreDef25Turns` 走的就是這個鍵。
- 有寫入但沒有讀取者的鍵（見盤點文件）：`ignoreDefPercentTurns`（湮滅咤克斯 34％、積木非 25％的忽略雙防）。
- 戰士「始終弱點傷害」寫在沒人呼叫的 `modifyDefenseAndDamage`，通用的 `weakPointDefenseTurns` 只有斯嘉麗會寫。

### 1.2 L2 公式替換（使用者說的「只能造成特攻值傷害」）

目前只有一個：無序·蝕言在對方隊伍存活時，對方的特殊攻擊改成 `floor(最終特攻 ×(1−蝕言特防/100))`（`specialDamageFormulaRegistry.ts:7-16`）。
- **跳過**：本系、克制、浮動、暴擊、套裝／稱號／刻印、寶石倍率，`isCrit` 恆為 false；連擊數照乘。
- **之後照樣進 L4–L6**：增傷、減傷、上限、抗性、護盾都會套用，**符合**你說的「先換成這個值，再算增減傷」。
- 這是唯一的替換點。之後若有其他「傷害固定為 X」類效果，應該都登記在這裡，不要寫成 multiplier 或 limit。

### 1.3 L3 公式內乘區：還沒到「增傷」層就先乘了

| 倍率 | 位置 | 說明 |
|---|---|---|
| 暴擊 2×(1−致命抗性) | DC:174-185 | **致命抗性在 L6 又乘一次**（確認的 bug） |
| 套裝造成傷害倍率 | DC:165 | 與 L4 增傷分開，相乘 |
| 稱號造成傷害倍率 | DC:166 | 同上 |
| 對方套裝受到傷害倍率 | DC:167 | 減傷提早在公式裡乘，不經過 L4 的減傷規則（真傷免疫、減傷覆寫都管不到它） |
| 刻印「強化」×1.2 | DC:169-172 | 同上 |
| 寶石 `skillStoneDamageMultiplier`（×2） | DC:185 | 同上 |

套裝的「造成／受到倍率」和刻印「強化」，在原作是公式內乘區還是增傷，需要你確認。

### 1.4 L4 增減傷池：**目前沒有統一**

`damageComp` 有三個欄位可寫，各精靈、套裝、積木寫法不一：

| 欄位 | 運算 | 誰在用（舉例） |
|---|---|---|
| `increasePercent` | **加算池**：所有來源相加後乘 (1+總和) | 奧丁、斯嘉麗、異世界雷伊、滄嵐、布林克克、哈莫、多數套裝、藏品、通用特性（屬性強化 +14％、強化 +20％）、積木 `dmg_mod`、閘門計時器 |
| `multiplier` | **乘算池**：每個來源各自相乘；**減傷也可能寫在這裡**（`multiplyDamageReduction`、異常 `damageTakenMultiplier<1`） | 六刃（魂印、亂舞）、次元龍（詩章）、聖光邁勒斯、譜尼、競技場各精靈、帝皇之盾、魯斯王、馬爾修斯、特性重傷 ×2、`dmgDoubleTurns`、受擊方 `DamageBoostTurns` |
| `decreasePercent` | **減傷合成**：1−(1−a)(1−b)，各來源作用於剩餘傷害 | `addDamageReduction`（魔王咒怨、堅硬、積木減傷） |

**結論：增傷沒有「統一算完再一次加」。** 同樣寫「提升100%」，寫進加算池或乘算池結果不同。以 base 342、兩個「提升100%」為例：
- 都進加算池：342×(1+1+1)＝**1026**
- 都進乘算池：342×2×2＝**1368**
- 一個加算、一個乘算：342×2×2＝1368

所以兩隻精靈的增傷疊在一起時，結果取決於當初是誰寫的程式。六刃少的 +100％也屬於這類：它寫進乘算池卻少加了 1。

另外，「減傷」同時存在於三個地方：`decreasePercent`、`multiplier`（<1 的倍率）、L6 的傷害抗性。前兩者都經過 `effectiveReduction`（真傷免疫、減傷覆寫、千秋一淚衰減），L6 抗性不經過。

### 1.5 L5 上限／保底

順序：`stage1×multiplier − 固定減免` → 上限 → ＋`bonusFixed` → 保底 → 自身輸出上限 → 手下留情。
- `bonusFixed`（強攻＋80 等）加在上限**之後**，可以超過上限。
- 印記倍率在 L6 才乘（只有攻擊傷害如此），所以**可能突破 L5 的上限與手下留情**；效果 API 則在上限之前乘。

### 1.6 L6 落地

死亡守護 → 傷害抗性（暴擊、固定、百分比，各乘一次）→ 印記（攻擊傷害才在這裡）→ 護盾（技能類）／護罩（固定、百分比）→ 存活規則 → 抵抗致死。

## 3. 對照你的想法：建議的統一分層

```
A 公式輸入   忽略雙防、雙攻合一、弱點、能力等級、威力、克制、本系
B 公式替換   「傷害固定為 X」類：一旦命中，直接取代 C 的結果
C 公式本體   [(Lv×0.4+2)×攻×威力÷防÷50+2]×本系×克制×浮動×暴擊×連擊
D 增傷       所有「提升X%」加總後一次乘：×(1+ΣX)
             「翻倍」「變為N倍」另列獨立乘區：×ΠN
E 減傷       所有「減少X%」：×Π(1−X)（或加總，待定）
F 上限／保底 上限、保底、手下留情、固定加減值
G 落地       抗性、護盾、存活規則、抵抗致死
```

要套用這個分層，需要做的事：
1. `damageComp` 拆成明確欄位：增傷加算池、增傷獨立乘區、減傷。禁止把減傷寫進 multiplier。所有精靈、套裝、積木改用對應的 API，例如 `addDamageIncrease(comp, 1.2)`、`addDamageMultiplier(comp, 2)`、`addDamageReduction(comp, 0.3)`，由一個函式統一結算。
2. 套裝、稱號、刻印、寶石的倍率，依你的決定歸到 C（公式內）或 D（增傷）。
3. 印記倍率一律在 D／E，不再在落地段才乘。
4. 致命抗性只在一個地方乘。
5. X系、額外行動、固定、百分比都走同一條 D→E→F，只差 A–C。

## 4. 需要你決定的規則

1. **同類增傷疊加**：多個「提升X%」是加總（目前多數套裝、積木、特性的做法），還是各自相乘（目前六刃、次元龍、競技場的做法）？
2. **「翻倍／變為N倍」**：是不是獨立乘區（與「提升X%」分開相乘）？
3. **減傷疊加**：維持目前「各自作用於剩餘傷害」1−(1−a)(1−b)，還是加總？
4. **套裝／稱號／刻印「強化」／寶石倍率**：屬於公式內乘區（C），還是增傷（D）？
5. **固定加值**（強攻＋80、bonusFixed）：在上限之前還是之後？
6. **真實傷害**：要不要受「傷害上限」與「保底」影響？
7. **公式替換後**：是否仍吃暴擊、連擊（目前不吃暴擊、照乘連擊）？

## 5. 使用者決定與實作（2026-10-11）

| 規則 | 決定 | 實作 |
|---|---|---|
| 多個「提升X%」 | 各自相乘 | `battle/damagePipeline.ts` 的 `createDamageComp`：舊寫法 `increasePercent += x` 每次寫入都算獨立來源，彼此相乘 |
| 描述寫「加法結算」 | 同組先加總 | `addDamageIncrease(comp, rate, group)`；銀翼騎士基礎 30%＋先出手 30%＝60% |
| 翻倍／變為N倍 | 獨立乘區 | `multiplier` |
| 減傷 | 各自相乘；需加總的同組最高 100%（不溢出、不歸零） | `addDamageReduction` 相乘，`addGroupedReduction(comp, rate, group)` 同組加總後夾在 100% |
| 套裝／稱號／刻印／寶石 | 依描述 | 依描述皆屬「造成的攻擊傷害提升／受到的攻擊傷害減少X%」，從公式內移到增傷／減傷層（`equipmentDamageFactors`）；寶石「傷害翻倍」移到獨立乘區；「威力翻倍」仍在公式 |
| 固定加值（強攻＋80） | 公式內 | `bonusFixed` 先加進公式結果，再吃增減傷與上限 |
| 真實傷害 | 不受上限與保底影響 | `applyTrueDamage` 移除 limit／floor（自身輸出上限仍適用） |
| 公式替換 | 不吃暴擊，也不乘連擊 | `calculateDamage` 替換後直接回傳總傷 |

同時修正：
- 致命抗性被套用兩次：只在公式的暴擊倍率套用。
- 六刃魂印：改為 ×(1＋120%×(1＋層數))，低於½時效果值翻倍。
- 晨曦之星：「造成攻擊傷害提升」原本也套到自己受到的非攻擊傷害上。
- 烈焰機甲「火屬性傷害提升25%」原本未實作，現在已補上。
- `ignoreDefPercentTurns`／`Value`（忽略雙防X%）原本寫入後無人讀取，現在引擎會讀；湮滅咤克斯補上 34% 的數值。
- 取整加入浮點容差（100×2.55 不再變成 254）。

先前「特殊攻擊也被削防」的判斷有誤：`ignoreDefPercent` 的語意是「忽略雙防」（例如積木「忽略雙防25%」），物理、特殊都套用是正確的。物理專屬的迪恩之刃已在藏品函式內篩選。

測試：`tests/damagePipeline.semantic.test.ts`（7 項）。另依新規則更新 `damageScopes`（雷伊兩個增傷 1.5×1.7＝255）、`skillStones`（寶石翻倍改由 equipmentMultiplier 回報）。完整測試 97 項通過；4 次完整執行中有 1 次出現 1 項偶發失敗，之後 3 次都通過，失敗的是哪一項尚未查出。

### 六刃「體力無法恢復／增加超過原始體力上限」出了什麼狀況

1. 獲得臨時體力上限時，同時把**目前體力**加上同樣的量，體力直接超過原始上限。
2. 恢復公式是 `min(上限, 目前+恢復量)`，而恢復上限＝原始上限；體力已經超過原始上限時，任何一次恢復（每次行動後的回血）都會把體力**往下拉回**原始上限，看起來像「恢復反而扣血」。
3. 「體力調整」（adjust_hp）完全不看這個上限。
4. 出場時給上一隻精靈的恢復直接改寫體力，跳過恢復規則，連陣亡的精靈都能被「補」回來。

修正：臨時上限只提高上限、不加目前體力；恢復永遠不會讓體力下降；增加體力也受原始上限限制（但不扣血）；上一隻精靈的恢復改走恢復流程，陣亡或滿血不處理。
