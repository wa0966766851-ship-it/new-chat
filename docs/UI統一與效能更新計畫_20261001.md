# UI 統一與效能更新：實際修正、驗收與下一階段

日期：2026-10-01。狀態：第一階段已實作，整體 UI 改版及效能驗收尚未完成。

## 範圍與原則

- 以首頁 iOS 科技風格統一卡片、側欄、分頁及資訊層級；不改精靈立繪、朝向或技能機制。
- 使用者確認「複製」是圖片本身，不是網址；桌面右鍵提供圖片複製選單。
- 優先處理效果資料庫與較後面的頁面；不能以「能開啟」或單元測試通過宣稱不卡頓。
- 命運之輪、星際探索的玩法、特殊精靈移入首頁及卡池暫不改。一般頁面的參考評級獨立處理。
- 語意參照 `elf_source_files/elf_files/*.txt` 與最終合併後的精靈資料；有衝突時列為待確認，不憑種子資料或先前聊天判定。
- 工作樹已有多批修改，保留全部既有變更。本階段沒有提交、推送或雲端上傳。

## 下一階段更新計畫

### P0：先完成卡頓的可重現測量

1. 正式版逐頁記錄首次／再次開啟、搜尋、分類、首末頁、連續 20 次開關的耗時與長任務，不只用開發模式體感。
2. 對比分頁前後卡片數與記憶體，確認關閉彈窗後沒有殘留監聽、計時器或解析工作。
3. 克制矩陣約 28×28：分離固定資料與 hover 高亮，避免每次滑鼠移動重繪全表；先測量再改。
4. 解耦測試中的伺服器／Vite 相依，消除測試 HMR 埠碰撞。
5. 載入畫面有模擬的 Kernel／安全／記憶體訊息，不是效能監測；改成真實載入狀態或明確標示展示動畫。
6. 開發服務日誌確認修改本計畫 MD 也觸發整頁重載，會讓正在驗收的頁面退回首頁。開發監看應排除文件及驗收產物；這與正式版卡頓分開追蹤。

### P1：自訂與編輯頁真正重排

1. 分為「基本資料、特性、技能、訓練、抗性」；高階選項收合，保留全部既有編輯能力。
2. 桌面固定輕量預覽，手機改頁籤而非兩個長欄並排；避免外層與內層同時捲動。
3. AI 輸入與手動輸入共用分類與保存流程，不把預覽臨時體力保存成正式數據。
4. 增加匯入、保存、取消、重新開啟回歸測試，驗證表單重排不遺失欄位。

### P2：介紹與背包一致化

1. 主頁詳情保留合法的戰前訓練／編輯操作；戰鬥與百科唯讀資料共用分類，但不暴露調整入口。
2. P1／P2、在場／場下、隱匿／魘味、負體力及動態 PP 各實測一次。
3. 背包選擇卡片統一屬性、體力、特性摘要與點擊熱區；手機按鍵不可過小。
4. 圖片複製補手機可發現的操作入口；目前桌面右鍵不能當作完整手機支援。

### P3：資料庫的內容與顯示去重

1. 異常狀態用唯一 ID 建立主索引，分類作標籤；多分類出現同名條目不再讓人誤以為有兩個不同異常。
2. 分清「描述模板、已解析積木、手寫執行、語意測試通過」，不讓參考詞庫暗示所有效果已實裝。已實際看到「【修復】」「常駐效果：」「【咒術師】」等標題與背景介紹被錯列為可引用效果，且部分條目時點落入預設「技能使用時」；需保留原段落階層再確認生成方式。
3. 逐條比對 TXT、最終資料與執行程式；不直接修改魂印文本遷就引擎 bug。
4. 靜態機制文案（護盾、護罩、額外行動、非攻擊傷害等）與目前測試規則重新核對，有疑義先列出。
5. 悲歌的種子描述曾省略時點，但最終覆寫後的「陰世遊靈」已有「使用技能後」；不能把種子差異當作正在執行的 bug。
6. 現有 S／A 仍只是參考名單，不等於完整戰力評估。特殊模式的精靈移入首頁與卡池重分級另開計畫，等使用者解除暫不修改限制。

### P4：剩餘大型區塊與技術基礎

1. 目前安裝的 Blockly 13.3.0 核心為單體壓縮模組，已按需載入；不使用未公開內部路徑硬拆核心。
2. 優先只在打開積木編輯器時初始化工作區；關閉時釋放；純資料解析可在量測後評估 Worker，DOM 工作區不能直接搬入 Worker。
3. 是否替換或升級 Blockly 要另測相容性，不能只為消警告冒險改核心。
4. 補齊 React 型別宣告並處理暴露出的問題。目前型別檢查通過不代表所有 JSX 屬性已受到完整型別檢查。
