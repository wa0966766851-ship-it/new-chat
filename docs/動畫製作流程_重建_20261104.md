# 動畫製作流程重建

> 建立：2026-11-04
> 起因：骨骼動畫實驗產出 41.9 MB manifest，完全不可用
> 關鍵發現：官方素材與 Lively 壁紙都是「分層 + 單份網格」，不是「逐幀網格」

---

## 一、失敗原因（已驗證）

### 舊方案的產出

```
public/elf-anim/wuxu_zhuixing/
  atlas.png        6.42 MB
  manifest.json   41.90 MB   ← 問題在這
```

### 為什麼 41.9 MB

```js
const [cols, rows] = spec.grid || [48, 62];   // 48×62 網格
// → 47 × 61 = 2,867 個四邊形
// → 每幀存 2,867 個 quad（每個含 8 位置 + 8 UV）
// → 182 幀（standby 40 + sa 60 + hited 10 + ultimate 72）
// → 834 萬個數字 → 41.9 MB
```

**根本錯誤：把「Spine 骨骼即時變換」做成了「逐幀預烘焙頂點」。**

### 效能影響

| 項目 | 數值 |
|---|---|
| 每幀繪製 | 2,867 個 quad |
| 24 FPS 下 | 68,808 次/秒 |
| 正常動畫 | 20–50 quad/幀 |
| **倍數** | **82 倍** |
| 單隻記憶體 | 約 126 MB（JSON 解析膨脹 3 倍） |
| 6v6 隊伍 | 約 1.5 GB |

## 二、正確做法（你的 Lively 壁紙驗證過）

### rosmontis-airy-dream 的結構

```
character.png              9.7 MB   ← 角色本體，1 張
layers/fx_..._03.png       3.6 MB   ← 光效層，1 張
layers/fx_..._05.png       2.4 MB   ← 光效層，1 張
layers/fx_..._06_2.png     1.4 MB   ← 光效層，1 張
index.html                 2.7 MB   ← 網格頂點 + 渲染邏輯
spine-webgl.js             473 KB   ← Spine 執行時
```

**總計 20.3 MB，但這是桌布規格（4K 全螢幕）。**

### 核心渲染邏輯

```js
for(const l of backgroundLayers) {
  batch.draw(l.glTexture, l.packed, l.indices);
}
renderer.draw(batch, skeleton);
```

**關鍵三點：**
1. **網格頂點只存一份**（靜態定義，不是每幀）
2. **`batch.draw(紋理, 頂點, 索引)` 一次 draw call 畫整層**
3. **變形靠 `skeleton.updateWorldTransform()` 即時算**

## 三、與官方素材的對照

| 方案 | atlas | manifest | 總計 | 說明 |
|---|---|---|---|---|
| **官方序列帧** | 738 KB | 19 KB | **0.76 MB** | 每幀一張切圖 |
| **Lively 壁紙** | 17.1 MB | 2.7 MB | 20.3 MB | 4K 桌布規格 |
| **舊骨骼方案** | 6.42 MB | 41.9 MB | **49.5 MB** | ❌ 不可用 |

**官方素材 = 序列帧（每幀一張）**
**你的壁紙 = 分層 + Spine（一份網格 + 骨骼變形）**

**兩者都是「一份素材服務多幀」，只有舊方案是「每幀一份素材」。**

## 四、「中間素材」的定義與清除

### 必須保留（成品）

| 素材 | 用途 |
|---|---|
| `character.png` / `atlas.png` | 角色本體 |
| `layers/fx_*.png` | 光效層 |
| 網格頂點資料 | 定義如何變形 |
| 骨骼資料 | 定義如何運動 |

### 可清除（中間產物）

| 素材 | 為什麼可清 |
|---|---|
| **原始序列帧**（如 `迷迭香旅行_01~16.png`） | 只用來生成 atlas，成品不需要 |
| **AI 生成提示詞記錄** | 生成過程紀錄 |
| **逐幀預烘焙頂點** | 正是失敗方案的問題 |
| **臨時裁切圖** | 拼進 atlas 後無用 |

### 判定原則

**問一句：「成品執行時需要讀這個檔案嗎？」**

- 需要 → 保留
- 不需要（只是生成過程用過） → 可清除

## 五、重建後的製作流程

### 階段 1：取得素材

```
輸入：官方序列帧 或 AI 生成圖
輸出：原始幀圖（暫存）
```

### 階段 2：分層

```
把每幀拆成：
  - 角色本體（固定不變的部分）
  - 光效層（會變化、會發光的部分）
  - 背景層（如果有的話）

輸出：每層一張圖（不是每幀一張）
```

**關鍵：找「在多幀之間不變」的部分，合併成一張。**

### 階段 3：建立網格

```
對每層建立網格：
  - 網格密度：依變形需求決定（8×8 ~ 24×24 足夠）
  - 只存一份靜態網格
  - 不要逐幀存

輸出：頂點 + 索引 + UV（一次性）
```

### 階段 4：定義骨骼與動畫

```
骨骼：
  - 軀幹、頭、四肢、武器（10~20 根）
  - 每根骨骼綁定網格權重

動畫：
  - 關鍵幀（rotation / translation / scale）
  - 由執行時插值

輸出：骨骼 + 關鍵幀資料（KB 級）
```

### 階段 5：打包

```
輸出：
  - atlas.png（合併所有層）
  - manifest.json（網格 + 骨骼 + 關鍵幀）
```

### 階段 6：清除中間素材

```
刪除：
  - 原始序列帧
  - 臨時裁切圖
  - 生成腳本的中間輸出
```
