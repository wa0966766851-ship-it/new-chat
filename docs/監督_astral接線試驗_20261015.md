# 監督報告：astral 接線試驗（free-deepseek-switch, epoch 2）

## 監督目標

在 Codex 退場、無人監督的情況下，接管並驗證「5032–5034 astral 系」是否真能上線，
並確保其他模型（GLM／DeepSeek 切換工）的產出**經正式路徑驗證**，而非只在測試中自證。

## 執行過程與結果

### 已執行：接線試驗（經使用者明確授權）

於 17:39 依預先定位的接線點，將 astral 三份 Kit 接入正式定義：
- `src/data/migratedSequenceSkillKits.ts`：import 三組（`MIGRATED_ASTRAL_AESFIA_KITS`／`_SKILLS_2`／`_FLASH`）＋陣列展開
- `src/data/reviewedSoulKits.ts`：import `MIGRATED_ASTRAL_AESFIA_SOUL_KIT` ＋陣列插入

接線後 `npm run lint` EXIT 0，且經 `applyReviewedSkillKits` 實測，5032 五技**全部成功套用為 `effectMode=kit`**、魂印「核」9 條命中——
證明接線機制本身正確、`elfId + name + description` 三者吻合。

### 但接線暴露了 6 條真實缺陷（**這正是接線的價值**）

接上後 `npm run test:data` 立即 EXIT 1，`kitValidation.ts` 擋下以下不合法條目：

| Kit | 位置 | 錯誤 |
|---|---|---|
| 星核幻舞 | kit[2] | 持續連鎖：恢復後連鎖需明確目標、正比例及自身使用事件 |
| 星核幻舞 | kit[5] | 集合／額外行動：`action.perNonFullPp` 不接受程式或巢狀行為 |
| 星核脈衝 | kit[5] | 集合／額外行動：`action.perNonFullPp` 不接受程式或巢狀行為 |
| 殞星衝擊 | kit[5] | 條件尚無等價查詢 |
| 魂印「核」 | kit[1] | 連鎖觸發尚無等價事件或與節點不符 |
| 魂印「核」 | kit[2] | 連鎖觸發尚無等價事件或與節點不符 |

**關鍵意義**：GLM 的 `migrate_5032_*` 四份測試全部 EXIT 0（共 11 checks），是因為那些測試**自行把 Kit 掛到 `skill.kit` 上**，繞過了 `pack_reviewed_kits` 的正式驗證。
一旦進入正式定義路徑，6 條不合法立刻現形。

> 這不代表 GLM 造假——它的測試確實驗證了行為語意。但**「測試通過」與「可上線」是兩件事**，
> 未經正式驗證的 Kit 不得視為完成。此點與 `docs/協作分工_20261015.md` 的「入口存在不等於驗收」一致。

## 另行發現：5034 既有失敗（與接線無關）

`npm run test:new-elves` 在**回滾後仍 EXIT 1**，故確認**非本次接線造成**，屬既有問題。

- 失敗點：`tests/newElvesIntegration.semantic.test.ts:142`
  `assert.ok(state[`${side}Timers`].some(t => t.payload?.immuneStatus))`
- 根因：5034 `背隳誓盟` 已是 `route=kit`（`src/data/migratedReactionSkillKits.ts:48`），
  其 Kit 用 `immune_status_turns` 表達免疫；測試仍斷言舊 handler 的 `payload.immuneStatus` timer。
- 性質：**過期斷言**，與 5002 `盾碎同歸`（已由本 session 修正）同型。
